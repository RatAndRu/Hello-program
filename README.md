# 🩺 NET DOCTOR — почему телефон не видит мой Python-сервер

Репозиторий содержит один инструмент: [`netdiagn/net_doctor.py`](netdiagn/net_doctor.py) —
пошаговую диагностику ситуации «на ноутбуке сервер открывается, а с телефона в той же
Wi-Fi — нет». Один файл, только стандартная библиотека Python 3, русский интерфейс.

[![NET DOCTOR — самотесты](https://github.com/RatAndRu/Hello-program/actions/workflows/netdoctor-tests.yml/badge.svg)](https://github.com/RatAndRu/Hello-program/actions/workflows/netdoctor-tests.yml)

---

## Ситуация, для которой он сделан

На ноутбуке (Windows) работает свой Python-сервер, например `http://192.168.0.60:5000/`.
На самом ноутбуке всё открывается — и по `127.0.0.1`, и по `192.168.0.60`.
А с телефона в той же Wi-Fi сети — **нет**. Раньше работало, сломалось «само»
(например, после отпуска с чужим Wi-Fi и экспериментов с VPN/1.1.1.1 WARP).

Инструмент не гадает: он идёт по цепочке

```
[Python-сервер] → [ноутбук: адрес + брандмауэр] → [Wi-Fi/роутер] → [телефон]
```

и показывает, **на каком именно этапе обрыв**, а затем помогает причину устранить.

## Что инструмент умеет

* **Живой журнал** обращений к тестовому серверу: видно, достучался ли телефон, и с какого адреса;
* распознаёт попытки по `https://` (TLS-приветствие) — по ним сразу понятно, что сеть работает,
  а дело в адресе;
* **контрольный тест закрытого порта** — отличает «пакеты доходят и их режет ноутбук»
  от «пакеты вообще не доходят»;
* выбирает **правильный адрес для телефона** (и QR-код) из нескольких адресов ноутбука,
  служебные (хот-спот `192.168.137.1`, VMware, Bluetooth, APIPA) помечает как бесполезные;
* проверяет **правила брандмауэра**: покрывают ли они вашу подсеть и **тот самый файл
  `python.exe`, который слушает порт** (важно, когда установлено несколько версий Python);
* смотрит **сканирование и журнал блокировок**, профиль сети, WARP/VPN (отделяя фоновую службу
  от активного туннеля), антивирусы со своим сетевым экраном (ESET и др.), прокси, hosts;
* по ключу `--fix` готовит `netdoctor_fix.ps1` (правило брандмауэра **только для своей
  локальной сети** + профиль сети Private + правило для слушающего интерпретатора)
  и `netdoctor_undo.ps1` для полного отката.

В конце — таблица «ЦЕПОЧКА: ГДЕ ПРОВАЛ» и вердикт с причинами, отсортированными по вероятности.


Самотесты гоняются в GitHub Actions при каждом `git push`.

## Частые вопросы

**GitHub компилирует Python сам?**
Нет. GitHub — это хранилище + браузер кода: он красиво показывает `.py`, PDF и
картинки, но не запускает Python. Чтобы код проверялся сам, есть **GitHub Actions** —
workflow прогоняет `python net_doctor.py --selftest` при каждом `git push`.
Зелёная галочка ✔ означает, что тесты прошли.

**Нужно ли что-то устанавливать?**
Нет. Только Python 3.8+ на Windows-ноутбуке. Инструмент не требует `pip install`:
QR-код печатается символами, если библиотеки `qrcode` нет.
