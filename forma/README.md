# ФОРМА 3D 0.79 — 3D-редактор, которым управляют словами

Параметрический редактор твёрдых тел для Windows. Модель описывается текстовым
сценарием: одна команда на строку. Приложение строит замкнутую геометрию,
показывает её в 3D, проверяет фактические размеры и связи и возвращает отчёт,
который можно отдать человеку или нейросети для следующей правки.

```forma
корпус = lathe points=[[0,0],[42,0],[42,95],[0,95]] segments=144 thickness=4 open=top
ручка = sweep path=[[40,0,28],[58,0,28],[67,0,42],[67,0,62],[58,0,76],[40,0,76]] width=9 height=13 smooth=10
кружка = union [корпус,ручка]
color кружка material=ceramic

check кружка watertight
check кружка height 90..100
check кружка wall 3..5
check кружка symmetric y
```

Текущий реестр: **242 команды, из них 123 примитива**. Полное описание каждой
команды, всех параметров, псевдонимов, ориентации и пример формируются из того
же реестра, которым пользуется геометрическое ядро.

**Готовый анатомический проект:** пример `human_skeleton` содержит скелет
взрослого человека из **206 отдельных костей** (80 осевых + 126 аппендикулярных),
400 168 треугольников и 412 встроенных проверок. Отдельный GLB совместим с
Blender. Состав, источники, лицензии, воспроизводимость и восемь проверенных
видов: [docs/human_skeleton.md](docs/human_skeleton.md).

Ещё в реестре: **типы объявлены у 1526 параметров из 2505** (224 команды), и
каждый пример реестра собирается — отчёт `docs/revision.md`, документ
[docs/types_079.md](docs/types_079.md).

## Что нового в 0.79

**Типы параметров — у большинства команд.** Раньше типизированные контролы
(число, ползунок, вектор, флажок) были только у двенадцати «избранных» команд:
всё остальное панель показывала свободным вводом. Теперь тип объявляется один
раз для повторяющегося имени — `radius`, `wall`, `at`, `segments`, `angle` — в
таблице `forma/param_types.py`, и достаётся каждой операции, где это имя
встретилось. Явное объявление команды по-прежнему важнее общего.

| | 0.78 | 0.79 |
|---|---|---|
| параметров с типом | 133 | **1526** из 2505 |
| команд хотя бы с одним типом | 12 | **224** из 242 |

**Формула в сценарии остаётся формулой.** Если значение задано выражением
(`round=R/2`, `at=[R, 0, 10]`), контрол показывает его как есть и работает
только на чтение: правка числом молча разорвала бы связь с параметром `R`.

**Ревизия команд — машинная и повторяемая.** `tools/audit_commands.py` строит
пример каждой команды, считает время и треугольники, проверяет тела на
manifold и делит падения по причинам. Все 242 команды проверены: **241 пример
собирается**, один (`openscad`) ждёт установленной внешней программы, без
примеров — ноль. Шесть примеров, которые раньше не собирались, исправлены и
закреплены тестами: `hinge_move`, `slider`, `kerf_cut`, `scatter`,
`fold_pattern`, `import`. Отчёт — `docs/revision.md`, шаг ревизии добавлен в CI.

## Что нового в 0.78

**Шаг в стек объекта.** В панели объекта под списком его строк появился блок
«Добавить шаг»: объединить с деталью, вычесть деталь, оставить общее, сварить,
сдвинуть, повернуть, масштабировать, разрезать, покрасить. Шаг — это **одна
строка** `.forma`, которую сервер складывает из проверенных значений
(`forma/steps.py`): `a = union [a, b]`, `translate [a] offset=[0, 0, 10]`,
`color a #ff0000 material=plastic`. Полей ровно столько, сколько у операции
параметров; имена деталей берутся из сцены, а не вводятся руками.

Строка встаёт на своё место в стеке: **после** деталей, которые использует, но
**до первого их использования** — группы, проверки или булевой операции,
поэтому они видят уже новую форму. Второй шаг идёт под первым, а не над ним.

Сборка проверяется до правки: если сценарий с шагом не собирается (например,
вычитание совпадающих деталей оставляет пустоту), текст в редакторе остаётся
прежним, шаг не появляется, причина показывается в панели. Откат не «чинит»
сценарий задним числом — он просто не применяет шаг.

## Что нового в 0.77

**Все примитивы — плитками.** В режиме плиток больше нет «избранных» 23 фигур:
плитка есть у **каждого** конструктора реестра — 123 примитива плюс тела
вращения и метабол (точение, выдавливание, протяжка, лофт, труба, метабол),
итого 128 картинок 128×128. Рядом с картинками `tools/render_thumbs.py` пишет
`web/thumbs/tiles.json`: слово операции, заводская строка параметров и
подпись. Клик вставляет **одну строку** — `arch = arch` или
`воронка = воронка` — и ничего больше; панель объекта открывает эти параметры
как обычные. Над сеткой появился поиск: сто двадцать восемь плиток иначе не
найти.

![0.77: все примитивы плитками — 128 миниатюр](docs/v077_tiles.png)

**Кэш операций.** Одна и та же деталь больше не строится дважды. Ключ —
слово операции, её параметры, точность сцены и значения параметров сценария
(`forma/cache.py`), кэшируется геометрия, а не объект: имя, цвет и материал
остаются принадлежностью конкретной строки. Команды, которые берут готовый
объект (`difference`, `hull` по именам), не кэшируются, а составные операции
(разъём, крепёж) — тем более: повтор только главной детали потерял бы
подсборку. Кэш живёт на процесс, счётчики — на сборку: при правке одной строки
интерфейс заново строит сценарий, но детали приходят из кэша. Проверено на
всех `examples/*.forma` и на полном прогоне тестов в порядке CI: набор
объектов, объёмы и треугольники совпадают с построением без кэша. Вагон
(1212 операций): первый прогон ≈3.0 с, повторный и после правки параметра —
≈2.0 с. В ключ входят не только параметры команды, но и параметры сцены,
переменные, настройки точности и имена готовых тел и контуров; детали со
сведениями о сборке (`meta`), покраской, мазками или ролями граней не
кэшируются вовсе. Потолок — 1500 деталей и 1.5 млн треугольников, тяжёлая
геометрия в памяти не оседает. Отключается `FORMA_CACHE=0`, статистика
попаданий едет в payload сборки (`cache`) и в подсказку строки состояния.

## 1. Что нового в 0.75

**Источник истины — текст `.forma`.** Панель объекта больше не подменяет
значения «на лету»: она меняет **одну строку** сценария и пересобирает модель.
Правка приходит из разбора, а не из регулярных выражений, поэтому вектор
`at=[0,0,5]`, комментарий в конце строки и перенос через `\` остаются целыми,
а связанное значение вида `round=R/2` не перезаписывается молча — сначала
спрашивается подтверждение «разорвать связь».

| Правка | Что делает |
|---|---|
| `set_param` | заменяет значение ровно в найденном диапазоне строки |
| `unset_param` | убирает параметр — так включается «авто» |
| `set_params` | несколько параметров одной строки за один проход |
| `add_command` / `delete_line` / `move_line` | порядок шагов объекта |
| `set_enabled` | временно выключает шаг: строка становится комментарием |

**Типы параметров объявлены, а не угадываются.** Для примитивов появилась
спецификация (`forma/param_spec.py`): диапазон, шаг, единица, набор вариантов
и режим «авто» (`omitted`, `sentinel`, `enum`). Интерфейс строит по ней
слайдер со стрелками и полем, вектор — покомпонентно, флаг — чекбоксом,
список — стрелками. Свободный ввод остался только у `type: "str"`.

```forma
корпус = cylinder radius=40 height=90 wall=3 cavity=верх
винт  = shaft length=60 diameter=12 chamfer=0.8
```
У `cylinder.segments` и `shaft.segments` есть режим `авто`: параметра в строке
нет — число сегментов выбирает операция по детализации.

**Пресеты формы из сценария.** `пресет_формы "плита" box size=[200,100,12]` —
объявление в `.forma`; панель показывает его рядом с заводскими, а применение
остаётся одной правкой строки. Пресеты сцены (`preset`) не затрагиваются.

**Плитки.** В инструментах есть режим плотной сетки: 128-пиксельные
изометрические миниатюры без пола, сетки и тени (`tools/render_thumbs.py`,
идемпотентно). Клик — операция с заводскими параметрами.

**Скорость.** `/api/edit` собирает модель без анализа (`analyze_model=False`)
и возвращает `timings`: правка `alien.forma` — 0.8 с, разбор — 1.1 мс.

**Где это видно.** Вкладка «Параметры» → блок «Объект» (он больше не прячется:
пока деталь не выбрана, там подсказка). Быстрый переход — кнопка
«параметры объекта →» в карточке выбранной детали. У объекта видны все его
строки: порядок (`▲`/`▼`),
выключение (`◼`), удаление (`✕`) и параметры каждой строки. У `union` и
`difference` сверху появляются блоки **фигур-источников** из провенанса —
у каждой свои параметры. Невалидная перестановка откатывается: текст
возвращается к прежнему виду, модель остаётся рабочей.

## 2. Что нового в 0.74

**Полигонаж стал управляемым.** Раньше это был один режим с сюрпризами: сетка
исчезала в художественном стиле, а «просвечивали ли грани» зависело от
дальности и удачи z-fighting. Теперь у полигонажа два явных параметра:

| Параметр | Значения | Смысл |
|---|---|---|
| `poly_fill` | `непрозрачный` / `сквозной` | оставить грани или сделать деталь полупрозрачной (рентген: видны все рёбра, включая задние) |
| `poly_edges` | `сетка` / `структурные` | все рёбра треугольников или только настоящие изломы, посчитанные по геометрии |
| `poly_angle` | 5…89° | порог излома для структурных рёбер |

В непрозрачном режиме грани отодвигаются по глубине (`polygonOffset`), поэтому
линия всегда выигрывает у своей же поверхности — одинаково и на детали 5 мм, и
на вагоне 1300 мм. Мировой сдвиг глубины, который врал на разных расстояниях,
убран.

**Структурные рёбра не пропадают.** Новый режим считает рёбра из самой сетки:
вершины сшиваются по координатам, каждому ребру находятся две соседние грани,
и в рисунок попадают только те, где двугранный угол больше порога. Куб даёт
ровно 12 рёбер и ни одной диагонали треугольников, гранёный цилиндр при пороге
30° — только два обода. Такие линии рисуются экранными полосами: толщина
стабильна, лесенок нет, при повороте ребро не исчезает.

Подробности — [`docs/RENDERING.md`](docs/RENDERING.md).

**Пол больше не обрезается хордами.** Круг пола строился из 96 отрезков: при
радиусе 2 м хорда — 134 мм, и на видах «спереди/справа» пол заканчивался
заметной прямой. Теперь число сегментов считается от стрелки прогиба 0.3 мм.

**Тень на полу — настоящая, а не «запечённая».** В маску падающей тени попадала
сама модель: её затенённые грани рисовались туда `ShadowMaterial`, и рядом с
тенью появлялся серый двойник. Модель из маски убрана; эвристика по яркости
осталась только запасным источником и больше не подмешивается к точной маске.

**Стили больше не смешиваются.** Смена режима начинается с его пресета: после
«скетча» в «аниме» не остаётся штриховки, после «линии» в «манге» — выключенного
затенения. Правило одно для окна и для сценария (`scene anime mode=…`), оно
лежит в `web/js/style_presets.js` и повторено в Python.

**Оси и сетка.** Оси пересчитываются от габарита новой модели (раньше оставались
длиной прошлой сцены), стрелки снова участвуют в глубине и не протыкают деталь,
а сетка и оси в художественном стиле подчиняются своим переключателям, а не
прячутся сами.

![0.74: контур 0.1 px и 2.0 px](docs/v074_lines.png)

**Волосяные контуры.** Нижний предел толщины контура снижен: в шейдере 0.28
плотного пикселя вместо 0.6, в окне — 0.1 px с шагом 0.05. Там, где контуры
идут плотно, больше нет чёрных заливок; в Python-рендере линия тоньше 0.2 px
ослабляется, а не пропадает.

### Что было в 0.73

**Габарит — это изделие, а не ядро.** `face_box` в выпуклом режиме наращивал
выступы наружу: деталь «куб 80» с `relief=7` получалась 94 мм, и в отчёте
сборки это не всплывало — вызов формально успешен. Теперь ядро сжимается на
relief с той стороны, где стоит выступ, и габарит готовой детали в точности
равен `size`. Углубления проверяются тем же фильтром, что и экспорт: если
тело распадается на части или внутри появляются закрытые полости, операция
останавливается и называет безопасную глубину («relief не больше 10 мм»).

**Новые параметры.**

| Команда | Параметр | Что даёт |
|---|---|---|
| `face_box` | `offset=[u,v]` | рельеф не по центру грани |
| `cube_hole` | `offset=[u,v]` | отверстия от центра: крепёж по углам фланца |
| `cube_hole` | `depth=` | глухое отверстие от стороны +оси |
| `box` | `wall=`, `cavity=`, `cavity_depth=` | полость со стенкой в любом блоке, включая наклонный |

**Полость в `box`** повторяет форму основания: контур берётся из двух срезов
блока, сжатых внутрь на `wall`, поэтому стенка нигде не тоньше заданной, а
дно остаётся не пробитым. Раньше «наклонная коробка с полостью» была
недоступна: `box_body` не умеет наклон, а `box` не умел полость.

![0.73: габарит, смещение рельефа, глухое гнездо, полость в наклонном блоке](docs/v073_sheet.png)

**Единый стандарт имён.** Появились [`docs/NAMING.md`](docs/NAMING.md)
(правила, словарь канонических имён, местные синонимы, чек-лист нового
параметра) и [`docs/ATLAS.md`](docs/ATLAS.md) (атлас понятий: поверхность →
элемент → структура корпуса, у каждого — определение, параметры, чем строится
и чего в языке пока нет). В интерфейсе: «направление» вместо «рельеф»,
«форма рельефа» вместо «профиль», «угол между сторонами», «разница половин»,
«глубина нахлёста», «радиус углов в плане», «припуск на сборку».

**Интерфейс догнал язык.** `cube_hole` получил независимые оси
(`hole_x/hole_y/hole_z` со своими формами), `hole_all`, `oval_aspect`,
`offset`, `depth`; `face_box` — `segments` и `offset`; `box_body` —
`припуск` и `сегменты`; `box` — полость. Правило проверяется тестом: каждый
параметр этих команд обязан быть в карточке.

## 2. Что нового в 0.72

**Наружность и внутренность отдельных граней.** Новый режим «грани» позволяет
самому выбрать треугольники на модели и назначить требование: **синие** —
целиком снаружи других видимых тел, **красные** — целиком и строго внутри
другого замкнутого тела, **серые** — без требования. ЛКМ выбирает грань,
Shift добавляет, Ctrl/Cmd снимает; соседние тела можно сделать прозрачными,
чтобы выбрать полностью скрытый корень. Это отдельный диагностический режим,
а не художественная кисть и не проверка направления normals.

Проверяется вся грань, а не только её центр: пересечение или касание оболочки
не проходит strict inside. Поэтому у красного корня зуба наружу не должен
торчать ни один треугольник. Разметка записывается в Forma-сценарий командой
`полигоны`, переживает rebuild и автоматически перепроверяется; явный контроль
добавляется строкой `check корень наружность`. Подробности, DSL и ограничения:
[docs/face_visibility.md](docs/face_visibility.md).

## История: 0.71

**Playback и Studio.** Автосборка подсвечивает именно текущую строку,
прокручивает редактор и gutter к ней и выделяет создаваемый или изменяемый
объект. В кадры попадают форма, положение и видимость, включая пустой кадр
`hide`; проверки, цвет и служебные команды не создают лишних остановок.
Повторный ▶ — единственная команда остановки: клики по сцене, выбор объектов,
переход по кадрам и закрытие окон не останавливают показ. Камера показывает
XYZ, азимут, наклон и крен. Свет, фон, NPR, тени, сетка, пол, оси, полигонаж,
заслонки, автоповорот, орбита и «к предмету» сохраняются через rebuild и
перезагрузку; Studio перестроена секциями и проверена на ширинах 340–1440 px.

**Качество сетки.** Новый `forma/mesh_quality.py` различает плоские иглы и
иглы на кривизне, находит колпаки, полюса/стяжки, перегрузы плотности, швы,
bowtie, границы, non-manifold рёбра, дубли и вырожденные грани. Добавлены
`check тело сетка`, автоматические замечания и `metrics["mesh_quality"]`,
а также `forma mesh модель.forma --json --sliver 0.3`. `simplify` пишет
изменение показателей до/после. Это диагностика и измерение эффекта, не
автоматический remesh: детектор не обещает исправить шов или геометрию.
Пороги и ограничения описаны в [docs/mesh_quality.md](docs/mesh_quality.md).

Защищённая лампа Arte Lamp Banker A2492LT-1AB и material-aware NPR проходят
свои регрессии; файлы постороннего кронштейна в этот проект не добавлялись.

## 2. Что нового в 0.46

### Поры с заданной формой и размером

`porous` строит сферические ямы, цилиндрические отверстия с плоским дном и
внутренние пузыри. `size` — радиус раскрытия, `width` — диаметр и имеет
приоритет; `depth` измеряется от исходной поверхности. `count` и `seed`
повторяемы. Раскрытия разводятся без перекрытий; невозможный `count` явно
отклоняется. `smooth`, `uneven` и `rough` меняют саму геометрию стенок и кромки.

```forma
камень = box size=[100,80,30] round=4
камень = porous [камень] mode=поры size=5 depth=2.5 count=24 smooth=.35 uneven=.12 rough=.08 seed=3

плита = box size=[100,80,30]
плита = porous [плита] mode=отверстия width=10 depth=6 count=18 smooth=.2 seed=8
```

### Плоский срез и канавка по его периметру

`shave` снимает материал плоскостью под произвольным углом. По контуру нового
среза можно пройти прямоугольной, овальной или треугольной канавкой. Это не
второй срез и не текстура: профиль имеет собственные ширину, глубину и отступ.

```forma
деталь = box size=[90,70,40] round=3
деталь = shave [деталь] depth=6 groove=овальная groove_width=5 groove_depth=2.5 groove_offset=4
```

`point` сохраняет положение вершины острия, возвращает одно корректное тело и
проверяет ошибку ядра после сборки.

### Трещины и древесные ложбинки

Новый `crack` вдавливает линии в существующую поверхность. `удар` создаёт
ветвящиеся лучи, `разлом` — длинную трещину с ответвлениями, `дерево` — ровные
продольные ложбинки. Лучи проецируются на настоящую сетку, поэтому инструмент
работает не только на плоскости.

```forma
плита = box size=[120,90,16]
плита = crack [плита] mode=удар at=[0,0,16] dir=[0,0,1] count=8 radius=43 width=2 depth=1.2 seed=4

доска = box size=[140,70,16]
доска = crack [доска] mode=дерево count=13 width=1.7 depth=.8 angle=0 seed=2
```

### Складки без диагональных артефактов

`wrinkle` автоматически разбивает сетку по длине волны. Режимы `радиус`,
`высота`, `шум`, `клетка`, `трещины` деформируют объёмное тело, а не добавляют
декорации. У рукава `surface=наружная` сохраняет внутреннюю стенку;
`surface=вся` деформирует обе. Угловые режимы плавно затухают у торцов и не
образуют звезду на торцевом веере.

```forma
наружная = cylinder radius=40 height=90 segments=64
внутренняя = cylinder radius=28 height=90 segments=64
рукав = difference [наружная,внутренняя]
delete наружная
delete внутренняя
рукав = wrinkle [рукав] mode=радиус amp=2.5 freq=12 axis=z surface=наружная
```

### Сгибы исходной поверхности

* `fold` и `fold_sheet` делят оставшуюся после дуг длину на равные плоские
  полотнища; каждая вторая складка больше не шире остальных.
* `сгиб` непрерывно отображает собственную сетку листа на прямые участки и
  дуги. Поддерживаются диагональ, линия через угол и `parts=3…12` для гармошки.
* `складка` в режимах `гребень` и `канавка` перемещает вершины исходной
  поверхности. Не добавляет полукольцо и не подставляет вторую плоскость.

```forma
лист = sheet width=105 length=240 thickness=1
гармошка = fold [лист] parts=5 angle=150 gap=.8 sharp=.15 axis=x

квадрат = sheet width=120 length=120 thickness=1
угол = сгиб [квадрат] at=[0,0,1] dir=45 angle=120 gap=.5

основа = sheet width=120 length=100 thickness=1
гребень = складка [основа] from=[-50,0,1] to=[50,0,1] r=6 depth=5 mode=гребень taper=.3
```

### Рифление, вафля, кора и рельеф

`corrugate mode=рифление` зависит только от одной координаты и даёт прямые
параллельные рёбра. `mode=вафля` зависит от двух координат и даёт двумерную
клетку. Плотность сетки — не меньше двенадцати рёбер на шаг.

`bark` строит нерегулярные извилистые борозды разной ширины и глубины,
вторичные трещины и мелкие пластины. Узор бесшовный по окружности и повторяется
по `seed`.

`relief` без `image` использует встроенную `docs/pattern.png`. Карта доступна
из любой рабочей папки и включается в однофайловую Windows-сборку.

```forma
рельеф = box size=[120,100,12]
рельеф = relief [рельеф] depth=2 mode=плоскость
```

### Наращивание на выбранном объекте

`hair` требует существующий объект. Иголки, волоски, локоны и мех начинаются
внутри поверхности и свариваются с ней в одно тело; автономной основы не
создаётся. `surface` выбирает каноническую сторону или всю поверхность,
`at+radius` может ограничить пятно.

```forma
основа = cylinder radius=43 height=28 segments=56
иголки = hair [основа] style=иголки surface=верх count=65 length=22 thick=1.6 spread=.18 seed=4
```

### Покраска узором

`pattern` остаётся покраской, а не рельефом. Перед назначением цветов сетка
автоматически разбивается под размер фигуры с ограничением бюджета, поэтому
круги и ромбы не превращаются в несколько крупных цветных заплаток. Форма,
габарит и объём не меняются.

```forma
куб = box size=[70,70,70]
color куб #f0e6cf
pattern куб #b44b3e shape=круги size=10 step=20
```

Для утверждений прямо в сценарии добавлены:

```forma
check нож collision tolerance=0.01 allow="нож:втулка"
check лезвие ход axis=z до=90 step=5

```

`blocked_mm3` — списки всех её пар (первую дублирует `blocked_pair`). Свободный
ход означает отсутствие
столкновений **в проверенных положениях**, а не непрерывное доказательство между

## 2. Что нового в 0.48

### Полости-лодочки и вогнутый люверс

У `полуовал` и `pie` появились `wall` и `cavity_depth`. Внутренний контур
получается настоящим смещением исходного силуэта на `wall`, а не масштабной
копией или рисунком. Полость открыта с лицевой стороны, снизу остаётся дно;
`cavity_depth ≤ thickness-wall`. Независимые `edge` и `hole` сохранены.

У люверса `transition=прямой|вогнутая` выбирает наружный переход от трубки к
бортику. Вогнутый вариант — четверть эллипса высотой `transition_h`, с
вертикальной касательной у трубки и горизонтальной у бортика. Это не `fill`:
заполнение верхнего отверстия по-прежнему задаётся отдельно.

```forma
лодочка = полуовал width=160 height=90 thickness=24 wall=3 cavity_depth=19 plane=плашмя
сектор = pie diameter=140 angle=180 thickness=24 wall=3 cavity_depth=18 at=[180,0,0]
люверс = grommet diameter=12 height=10 wall=1.6 flange=4 transition=вогнутая transition_h=5 at=[260,0,0]
```

### Глазное яблоко и капсульная паутина

`eyeball` (`глазное_яблоко`) не заменяет лицевой `глаз`. Новый примитив создаёт
четыре отдельных объёма: склеру, сферические диски радужки и зрачка и выпуклую
роговицу с `transmission=1`. Внутренние слои немного перекрываются, оптические
поверхности разнесены: нет щелей и совпадающих мерцающих граней. Оптическая
ось смотрит в `−Y`; размеры `diameter`, `iris`, `pupil`, `cornea`, выпуклость
`bulge` и толщина кромки `cornea_t` задаются числами.

`web` (`паутина`) строит настоящие капсульные нити круглого сечения. Доступны
`shape=круг|сектор|угол|треугольник|крыло|плавник`, число `radials/rings`,
диаметры `wire/ring_wire`, провисание `sag`, изгиб `bend` и наружный `frame`.
По умолчанию ячейки сквозные. `membrane=да` добавляет тонкую перепонку;

```forma

паутина = web shape=круг radius=70 radials=12 rings=5 wire=.8 sag=.14 at=[100,0,0]
крыло = web shape=крыло radius=90 angle=145 radials=7 scallop=.38 membrane=да at=[220,0,0]
плавник = web shape=плавник radius=70 angle=105 radials=8 scallop=.3 at=[360,0,0]
```

### Настоящий Shrinkwrap

`shrinkwrap [цель, объект]` деформирует вершины именно второго объекта по
сетке первого. `direction=ближняя|нормаль|вверх|вниз|±X|±Y` задаёт лучи,
`detail` — шаг дробления исходной сетки. `gap>0` приподнимает над целью,
`gap<0` погружает; это не команда посадки `на_границе`.

Замкнутая пластина не схлопывается: толщина измеряется двусторонними пробами
вдоль проекционного луча, включая боковые рёбра. `amount` управляет силой,
`transition` плавно оставляет удалённые вершины в исходной форме.
`join=нет|слить|сгладить` выбирает раздельный результат, булево объединение
или объединение со скруглением вогнутого стыка радиусом `weld`.

```forma
цель = sphere radius=20
плёнка = box size=[20,20,2] at=[0,0,20]
color цель #6686a0
color плёнка #d7765f
плёнка = shrinkwrap [цель,плёнка] gap=.6 direction=вниз detail=2
```

### Поворот ступеней и новая плоская чешуя

У `stairs` параметр `turn` вращает каждую ступень вокруг её собственного
центра в плане. Исходный марш сначала разрезается на ступени с сохранением
выбранных скруглений, затем они соединяются; слишком большой угол на узком
марше явно отклоняется, если разрывает соседние проступи.

Старая чешуя из выпуклых капель удалена. Новый `scales` использует плоские
наклонные пластинки: `kind=рыба` — округлый веер, `kind=дракон` — острый лист.
Корень погружён в тело, свободный конец приподнят на угол `tilt`. Верхний
конечный сектор перекрывает корень следующей нижней чешуйки; шаг рядов строго
`length·(1-overlap)`. `thick` задаёт толщину пластины, а не раздувание сферой.

```forma
марш = stairs steps=7 rise=18 run=28 width=120 turn=30
рыба = sphere radius=30 at=[0,0,150]
scales рыба kind=рыба rows=8 per_row=12 length=6 tilt=18 overlap=.45
дракон = sphere radius=30 at=[0,0,150]
scales дракон kind=дракон rows=8 per_row=12 length=6 tilt=28 overlap=.45
```

## 3. Что нового в 0.47

![Формы и полости 0.47](docs/whatsnew/whatsnew_047.png)

### Профили, стенки и скрытые каналы

У `cone` есть три разных радиальных профиля: `form=прямой`, `парабола` и
`холмик`. `wall>0` делает полый конус с открытым низом и закрытой вершиной,
`smooth` сглаживает его без подмены выбранного профиля. `cylinder wall>0`
строит несквозную полость с `cavity=верх` или `низ`, у `pyramid wall>0` полость
открыта только снизу. `ring cavity>0` создаёт закрытый канал внутри материала
обода, а не увеличивает центральное отверстие.

```forma
конус = cone radius=45 height=90 form=парабола wall=4 smooth=1
цилиндр = cylinder radius=40 height=90 wall=5 cavity=верх
пирамида = pyramid sides=4 radius=55 height=90 wall=5
кольцо = ring diameter=30 width=12 thickness=6 cavity=2 round=0
```

### Полосы, решётки и отверстия

`strip path=подкова` строит непрерывную подкову; независимые `path` и `path_z`
сохраняют два контура, а у прямой полосы доступно ровное центральное отверстие.
`grating pattern=круги|треугольники` добавляет настоящие сквозные ячейки этих
форм. У `cavity_frame` квадратная и овальная полости не зависят от внешнего
контура. Отверстия удалены из `box`: для центральных сквозных каналов служит
`cube_hole`.

```forma
подкова = strip length=200 width=14 thickness=5 path=подкова curve=40
решётка = grating width=150 height=110 pattern=треугольники cols=5 rows=4
блок = cube_hole size=[90,70,60] hole=24 axis=z
```

### Кромки и скругление без деформации граней

`disc` и `oval` имеют независимые `edge/edge_band`. У `pie`, `полуовал` и
`arch` истончается только круглая часть, радиальные плоскости и прямые торцы
сохраняют толщину. Пирамида и колонна используют радиусное скругление рёбер,
а не Loop-стягивание широких граней. У сектора шара убраны угловые выступы.

### Отдельные овалы и капсулы, объёмный инь-ян

У `tee` и `yoke` режимы `shape=овалы` и `shape=капсулы` различаются геометрией:
первый строит цельные эллиптические ветви, второй — прямые стороны с
полукруглыми торцами. Оба сохраняют точные габариты и остаются одним телом.
У капсульной Т ножка не проходит сквозь перекладину. `yin_yang` по умолчанию
имеет `form=объёмная`; ровная пластина остаётся доступна через `form=плоская`.

```forma
тавр = tee arm=90 bar=20 stem=22 leg=60 shape=капсулы round=2
рогатка = yoke height=110 spread=64 arm=16 shape=овалы
инь = yin_yang diameter=120 thick=16 form=объёмная side=левый
```

### Механика и мелкие детали

* `spring hole>0` — полость по всей винтовой длине проволоки; у `worm_shaft`
  есть профили и окончания витка, осевой `bore` и `channel` внутри червяка.
* `lever knob=линза|вогнутая` — выпуклая линза либо чаша только снаружи;
  стык остаётся выпуклым, палка не выступает. `grommet fill=ровно|выпуклая|
  вогнутая` заполняет верхнее отверстие одним телом с втулкой.
* У `column` отрицательный `taper` расширяет верх, `base_size=0` убирает
  площадку, `base_h` сохраняет нижнюю зону стержня, `rim_h` работает и при
  `rim=0`. Текстового переключателя площадки нет.
* `gusset` имеет независимые прямые/вогнутые/выпуклые контуры и варианты
  `*_с_пазом`; `blade kind` меняет не только название, но и силуэт, сечение и
  ложбины. `nail` — гладкий гвоздь без резьбы.
* `spikes` — инструмент над существующим объектом, а не автономная площадка.
  Исправлены сопряжение крюка, плоскость и seed облака, силуэт и кромка
  кленового листа. У `swirl` непрерывный виток сужается в остриё; `root_d`
  уменьшает начало, `base=да` скрывает его в плоском основании.

### Турбинная лопасть

`turbine_blade` строит несимметричный аэродинамический профиль с независимыми
хордой корня/конца, толщиной, кэмбером, установочным углом, круткой,
стреловидностью, осевым изгибом, корневой зоной и окончанием. Это объёмная
лопасть, а не согнутая прямоугольная пластина.

```forma
лопасть = turbine_blade length=180 chord=70 root_chord=20 tip_chord=42 thick=7 tip_thick=2.5 camber=.09 stagger=25 twist=55 sweep=28 root_h=12
```

### Дополнение: плотные вмятины, новые полости и швейная пуговица

![Дополнение форм 0.47](docs/whatsnew/whatsnew_047b.png)

* `face_box detail=0…5` управляет радиальной тесселяцией линз и вмятин. Мелкая
  сетка сглаживает саму кривую поверхность и не создаёт диагональные заплатки;
  габарит куба сохраняется.
* `prism wall>0` вырезает слепую полость с `cavity=верх|низ` и независимой
  `cavity_depth`. Внутренний контур следует сужению, сдвигу и повороту верха.
  `pipe hole=нет` убирает внутренний канал и оставляет сплошной прямой или
  изогнутый стержень; `wall` тогда не используется.
* `fold_sheet`, `fold` и `сгиб` принимают `joint=круг|широкая|сплайн|фаска`.
  Помимо обычной дуги есть три острых, но более плавных профиля: широкий
  радиус, кривизна с мягкими концами и две дуги с промежуточной фаской.
* `disc` и `oval` с `outline=вогнутая4` получают четыре вогнутые стороны между
  кончиками на осях. `indent=0…0.8` меняет глубину дуг; плоский верх, купол,
  чаша и независимая `edge` работают по фактическому контуру.
* `strip path=J` строит одну ленту с длинной ногой, полукруглым крюком и
  коротким подъёмом. `length` — длина центральной линии, `curve` — радиус.
* Новый отдельный `sewing_button` (`пуговица`) не заменяет прежнюю кнопку из
  двух объектов. `kind=отверстия` даёт 0…8 настоящих сквозных отверстий;
  `kind=ушко|трапеция` — заднее крепление со сквозным каналом без лицевых
  дырок. `rim_side=верх|низ|нет` ставит бортик только с одной стороны,
  `top=плоская|выпуклая|вогнутая` и `sag` управляют лицевой поверхностью.

```forma
вмятина = face_box size=[60,50,40] mode=вогнутый profile=линза relief=8 margin=5 faces=верх detail=5
призма = prism sides=6 radius=35 height=60 wall=3 cavity=верх cavity_depth=40
стержень = pipe diameter=20 wall=2 hole=нет length=100 angle=75 radius=45
сгиб = fold_sheet width=90 length=180 thickness=1.2 parts=3 angle=115 joint=сплайн
звезда = disc diameter=100 thickness=5 outline=вогнутая4 indent=.35 top=выпуклая sag=5
крючок = strip length=180 width=10 thickness=4 path=J curve=24
пуговица = sewing_button diameter=30 thickness=4 holes=4 hole_d=3 pitch=8 rim_side=верх top=вогнутая
с_ушком = sewing_button diameter=30 kind=ушко top=выпуклая sag=4 eye_d=6 shank_h=11
```

## 5. Канонические стороны и посадка

Для каждого предмета однозначно заданы исходные стороны:

| сторона | направление |
|---|---|
| верх | `+Z` |
| низ | `−Z` |
| право | `+X` |
| лево | `−X` |
| перёд | `−Y` |
| зад | `+Y` |

При выделении показываются личные оси предмета. Повороты и масштабирование
обновляют их вместе с геометрией. Команда `ориентация` возвращает стороны,
центр габарита, центр массы и сведения о пустотах. Несимметричные формы и
открытые полости дополнительно описаны в карточке команды.

```forma
корпус = box size=[140,40,40]
корпус = rotate [корпус] angle=90 axis=y
крышка = cylinder radius=18 height=6
крышка = place [крышка] on=корпус side=top осями=хозяина

деталь = box size=[20,20,10]
деталь = place [деталь] on=корпус side=front face=top gap=2
```

`place` измеряет зазор от фактической границы, а не от центра. Можно посадить
свою выбранную сторону на сторону хозяина, выставить оси параллельно или
перпендикулярно и использовать размеры соседа:

```forma
ящик = box size=[80,50,30]
шайба = cylinder radius=6 height=6
шайба = translate [шайба] offset=[0.5*width(ящик),0,height(ящик)]
шайба = размер [шайба] width=0.25*width(ящик)
```

## 6. Основные группы команд

### Тела и заготовки

Стандартные тела, тела вращения, лофт, sweep, листы и готовые детали находятся
в упорядоченных группах «Инструментов». В карточке есть живое превью, описание
формы и настоящие параметры команды. Ползунки и выборы подставляются в текст
сценария и сохраняются вместе с проектом.

Специальные формы продолжают работать: кнопка из двух объектов, настраиваемые
лестница, рычаг и призма, объёмный слиток, бусина со сквозным каналом,
сектор тора, полости и рельефные грани.

### Булевы операции и слитные модели

```forma
итог = union [а,б]
итог = difference [а,б]
итог = intersect [а,б]
итог = fuse [а,б] radius=3 edges=все
```

`fuse` соединяет и сглаживает выбранные стыки. Для печати проверяйте не только
`NoError`, но и число частей, герметичность, толщину и саму форму.

### Массивы и градация

```forma
ряд = ряд [деталь] count=5 step=[40,0,0] grow=1.15 turn=12
круг = array [деталь] count=12 mode=radial radius=100 spin=да
```

У `ряд` можно ступенями менять размер, поворот и силу применяемого инструмента.
Размещение и зазоры можно выражать через `width()`, `height()`, `length()` и
центр массы другого объекта.

### Цепь и соединения

Оригами остаётся отдельной нишей листовых сгибов. Цепь и соединение готовых
объектов остаются самостоятельными возможностями:

```forma
ц = цепь links=8 size=26 wire=3.4 at=[0,0,80] dir=[1,0,0]
ц = соединить [первый,второй] size=16 wire=2.4 sag=.15
```

Сопряжения задают отношение деталей. После следующего преобразования
`check имя связь` пересчитывает остаток и показывает, осталась ли деталь на
месте.

### Скульпт и поверхность

Кисти вмятины, выдувания, щипка, разравнивания и разглаживания работают по
сетке. Для повторяемого текстового моделирования предпочтительны команды
`wrinkle`, `crack`, `porous`, `shave`, `point`, `corrugate`, `сгиб`, `складка`,
`hair`, `bark` и `relief`: их параметры записаны прямо в проекте.

Доступны обычный рендер, скульптинг/органика и аниме/манга. Зеркальность,

## 8. Проверки и отчёт

```forma
check деталь watertight
check деталь parts 1
check деталь size 79..81 59..61 39..41
check деталь wall 2..4
check деталь volume 1000..5000
check деталь связь
```

`watertight` проверяет замкнутость оболочки, `parts` — число тел,
`wall` — толщину лучами, `volume` — объём, `связь` — остаток сопряжения.
Отчёт включает предупреждения, фактические габариты, ориентацию, материалы,
треугольники и результаты проверок.

Успешное построение само по себе не доказывает правильность формы. Для новых
инструментов используются количественные проверки и визуальная приёмка:
профиль, дно отверстия, пустоты, соединения, тесселяция и отсутствие
диагональных артефактов.

## 9. Экспорт и Blender

```forma
/экспорт glb
/экспорт stl
/экспорт obj
/экспорт ply
/экспорт step
/экспорт 3mf
/снимки front,iso,right,top
```

* **GLB** — цвета, материалы, отдельные объекты и анимация; основной обмен с
  Blender.
* **STL / 3MF** — печать геометрии без сценового освещения.
* **OBJ / PLY** — сетки для других редакторов.
* **STEP** — обмен с CAD, если доступен соответствующий конвертер.
* **DXF** — развёртки и плоские контуры поддерживаемых листовых деталей.

Импорт GLB/OBJ/STL доступен через меню. После импорта используйте `repair`,
проверку герметичности и личные оси; не заменяйте скругление рёбер общим
Loop-сглаживанием широких граней.

## 10. Инструкция для нейросети

Кнопки **«Инструкция ИИ»** и **«Все команды»** копируют справочник в отдельное
поле, не затирая запрос. Полный каталог содержит каждую команду, русские
псевдонимы, параметры, ограничения, ориентацию и рабочий пример.

Рекомендуемый цикл:

1. скопировать инструкцию и все команды отдельно от запроса;
2. сформулировать предмет, размеры, стороны и допустимые пустоты;
3. построить текстовый сценарий;
4. прочитать отчёт и исправить форму, а не только сообщение об ошибке;
5. проверить сцену в обычном или нужном специальном рендере;
6. экспортировать GLB для Blender либо STL/3MF для печати.

## 11. Запуск

### Windows

Готовые ZIP и EXE публикуются на странице
[Releases](https://github.com/RatAndRu/Hello-program/releases). EXE собирается
только через GitHub Actions CI: локальный Windows-бинарник не подменяет
релизный. Встроенные карты, примеры, интерфейс и справка упаковываются в сборку.

### Из исходников

Требуются Python 3.11+, NumPy, `manifold3d` и PyYAML.

```bash
cd forma
python -m pip install -r requirements.txt
python -m forma.app --browser
```

Самопроверки:

```bash
python -m forma.app --selftest
python -m forma.app --uistest
python -m unittest discover -s tests -v
python -m forma.eval --out foundation-eval.json --compare docs/foundation_baseline.json
python -m forma.fuzz --cases 24 --seed 20261102 --timeout 30 --output fuzz-report.json
node --check web/js/app.js
```

Профиль отдельных команд: `python -m forma build model.forma --profile`.
Устройство benchmark, формат ответов нейросети и fuzz-repro описаны в
[docs/foundation_eval.md](docs/foundation_eval.md).

Дополнительные рецепты находятся в [docs/RECIPES.md](docs/RECIPES.md).
Развитие и ограничения — в [docs/PLAN_NEXT.md](docs/PLAN_NEXT.md) и
[docs/SELF_ANALYSIS.md](docs/SELF_ANALYSIS.md).
