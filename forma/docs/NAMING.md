# Стандарт имён параметров Формы 3D

Один смысл — одно слово. Параметр с одинаковым именем в любой команде означает
одно и то же, а разные вещи называются по-разному. Стандарт действует не только
для четырёх примитивов (`box`, `face_box`, `cube_hole`, `box_body`), а для всего
реестра команд: если новому параметру не находится место в этой таблице, значит
либо он назван неточно, либо в языке не хватает понятия.

## 1. Три правила

1. **Габарит — это изделие, а не ядро.** `size` описывает готовую деталь вместе
   со всеми выступами. Если операция добавляет материал наружу, она обязана
   сдвинуть построение внутрь, чтобы габарит остался равен `size`. Проверяется
   тестом: у детали с рельефом габаритный ящик равен `size`.
2. **Величина и направление — разные параметры.** `relief` — сколько, `mode` —
   куда (наружу или внутрь). Никогда наоборот, никогда одним словом.
3. **Единицы.** Линейные — миллиметры. Углы — градусы. Доли (сглаживание,
   сужение, доля среза) — безразмерные 0…1. Это записывается в описании
   параметра, а не угадывается.

## 2. Канонические имена

| Имя в языке | По-русски в интерфейсе | Что означает | Единица |
|---|---|---|---|
| `size` | габарит | габаритные размеры готовой детали `[x,y,z]` | мм |
| `wall` | стенка | толщина стенки оболочки (и дна, если не задано отдельно) | мм |
| `bottom` | дно | толщина днища полости | мм |
| `cavity` | полость | открытая сторона полости: `верх`, `низ`, `нет` | — |
| `cavity_depth` | глубина полости | глубина от открытой стороны, не пробивает дно | мм |
| `relief` | величина рельефа / припуск | размер выступа, углубления или зазора на сборку — смысл уточняется операцией | мм |
| `mode` | направление | направление рельефа: `ровный`, `выпуклый`, `вогнутый` | — |
| `profile` | форма рельефа | форма рельефа: `линза`, `трапеция`, `квадрат` | — |
| `margin` | поле до края | расстояние от края грани до рельефа | мм |
| `offset` | смещение | сдвиг центра элемента от центра грани или детали | мм |
| `round` | радиус рёбер | радиус скругления рёбер (у `box_body` — углов в плане) | мм |
| `chamfer` | фаска | снятая фаска по ребру | мм |
| `taper` | сужение | доля сужения вершины трапеции | 0…1 |
| `depth` | глубина | глубина отверстия, паза, канала | мм |
| `diameter` | диаметр | диаметр отверстия или тела вращения | мм |
| `count` | количество | число повторяющихся элементов | шт |
| `pitch` | шаг | расстояние между повторяющимися элементами | мм |
| `axis` | ось | ось, вдоль которой работает элемент: `x`, `y`, `z` | — |
| `segments` | сегментов | число сегментов по окружности | шт |
| `detail` | детализация | уровень детализации 0…5 | уровень |
| `center` | центрировать | ставить центр в точку `at`, а не низ | да/нет |
| `at` | положение | положение детали в пространстве `[x,y,z]` | мм |

Имена `frame`, `cavity_size`, `hole_*`, `expand_*`, `groove_*` — составные:
первая часть называет элемент, вторая уточняет его свойство. Правило составных
имён: **элемент, потом свойство** (`hole_shape`, а не `shape_hole`;
`cavity_depth`, а не `depth_cavity`).

## 3. Слова, которые нельзя использовать как синонимы

| Нельзя | Почему | Правильно |
|---|---|---|
| `size` = ядро | обещает габарит, которого нет | `size` = габарит, ядро считается внутри |
| `profile` = форма рельефа в интерфейсе | `profile` в других операциях — профиль сечения тела | в UI «форма рельефа», в языке `profile` |
| `mode` в интерфейсе подписан «рельеф» | это направление, а не величина | «направление» |
| `relief` у `face_box` и `box_body` с одним смыслом | там высота рельефа, тут припуск на сборку | в описаниях уточнять: «величина рельефа» / «припуск на сборку» |
| `round` = «скругление» везде | у `box_body` это углы в плане, у `box` — все рёбра | «радиус рёбер» / «радиус углов в плане» |
| `expand` = «расширение половины» | непонятно, половины чего и куда | «разница половин» |
| `expand_seat` = «заход пояса» | жаргон | «глубина нахлёста» |
| `base_angle` = «угол основ.» | неясно, угол чего с чем | «угол между сторонами» (скос осей X и Y) |
| `oval_aspect` = «вытянутость» | неясно, чего | «вытянутость овала» |

## 4. Местные синонимы

Слово, которое в разных операциях значит разное, допускается только как
**местный** синоним операции (`param_aliases` в описании команды). Он
переводится в каноническое имя до общей проверки параметров.

| Операция | Синоним | Каноническое имя |
|---|---|---|
| `face_box` | `направление` | `mode` |
| `face_box` | `форма_рельефа` | `profile` |
| `face_box` | `выступ`, `глубина`, `величина`, `глубина_рельефа` | `relief` |
| `face_box` | `поле`, `поле_до_края` | `margin` |
| `face_box` | `срез_угла` / `углы` / `угол` | `corner_cut` / `corners` / `corner` |
| `cube_hole` | `глубина` | `depth` |
| `cube_hole` | `форма_отверстия`, `ось_отверстия`, `отверстия` | `hole_shape`, `axis`, `hole` |
| `cube_hole` | `вытянутость` | `oval_aspect` |
| `cube_hole` | `смещение_отверстий` | `offset` |
| `box` | `стенка`, `полость`, `открыть`, `глубина_полости` | `wall`, `cavity`, `cavity`, `cavity_depth` |
| `box` | `угол_между_сторонами`, `скос_осей` | `base_angle` |
| `box` | `разница_половин`, `большая_половина`, `тип_стыка`, `глубина_нахлёста`, `сглаживание_перехода` | `expand`, `expand_side`, `expand_joint`, `expand_seat`, `expand_smooth` |
| `box_body` | `припуск`, `припуск_на_сборку` | `relief` |
| `box_body` | `скругление_в_плане`, `углы` | `round` |
| `box_body` | `дно`, `толщина_дна`, `толщина_стенки` | `bottom`, `bottom`, `wall` |

Общие слова живут в `forma/dsl.py` (`PARAM_ALIASES`) и действуют во всех
командах: `габарит` → `size`, `стенка` → `wall`, `полость` → `cavity`,
`смещение` → `offset`, `глубина` → `depth`.

## 5. Что изменилось в интерфейсе

| Было | Стало |
|---|---|
| `face_box`: «рельеф» (режим) | «направление» |
| `face_box`: «профиль» | «форма рельефа» |
| `face_box`: «поле грани» | «поле до края» |
| `face_box`: «высота/глубина» | «величина рельефа» + подсказка «габарит остаётся равен size» |
| `cube_hole`: «размер» | «габарит» |
| `cube_hole`: «скругл.» | «радиус рёбер» |
| `box`: «угол основ.» | «угол между сторонами» |
| `box`: «расширение половины» | «разница половин» |
| `box`: «соединение» | «тип стыка» |
| `box`: «заход пояса» | «глубина нахлёста» |
| `box`: «плавный переход» | «сглаживание перехода» (0…1) |
| `box_body`: «скругл.» | «радиус углов в плане» |
| `box_body`: припуск отсутствовал в карточке | «припуск на сборку» с пояснением |

## 6. Чек-лист нового параметра

1. Найти смысл в таблице §2. Нет смысла — сначала завести понятие в
   [`ATLAS.md`](ATLAS.md), потом параметр.
2. Имя — каноническое; в интерфейсе — русская подпись из §2.
3. Если слово в этой операции значит другое — добавить местный синоним
   (`param_aliases`), а не менять каноническое имя.
4. Единица измерения в описании параметра обязательна.
5. Вывести параметр в карточку интерфейса (`forma/web/js/app.js`) — правило
   «в языке есть, в интерфейсе есть» проверяется тестом.
6. Описать в `summary` команды, что изменилось в геометрии.
7. Тест: хотя бы одна сборка с новым параметром и одна ошибка с понятным
   текстом.
