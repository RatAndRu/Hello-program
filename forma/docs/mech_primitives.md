## 4. Как перенести в другую ветку

1. Скопировать `forma/forma/ops_mechparts.py` — модуль ни от чего не зависит,
   кроме `errors`, `ops`, `ops_hardware._thread_bore`.
2. В `forma/forma/run.py` после последнего `from . import ops_*` добавить:

   ```python
   from . import ops_mechparts  # noqa: F401,E402

   from .orient_notes import PRIMITIVE_ORIENTATIONS as _PRIMITIVE_ORIENTATIONS  # noqa: E402
   _PRIMITIVE_ORIENTATIONS.update(ops_mechparts.ORIENTATION_NOTES)
   ```

   Памятки ориентации приходят вместе с геометрией, править `orient_notes.py`
   не нужно.
3. Если в целевой ветке есть `tests/test_v041.py` и `tests/test_v043.py` —
   там зашито число примитивов (было 122, стало 135) и список когда-то
   удалённых команд. `bearing` и `rack` возвращаются новыми конструкторами —
   так же, как в 0.53 вернулись `rail` и `hinge`; из списков `REMOVED` они
   убираются.
4. Тесты: `forma/tests/test_mechparts.py`.
5. Карточки для панели инструментов: 13 блоков `op: '…'` в
   `forma/web/js/app.js`, группа «Готовые детали».
6. Готовый патч текстовых правок: `forma/docs/mech_primitives.patch`
   (`git apply` из корня репозитория; картинки копируются отдельно, они в
   `forma/docs/reference/mech/`).

## 5. Границы автоматики — честно

* **Коническая шестерня** — усечённое прямозубое колесо: зубья сбегают к
  малому торцу пропорционально, высота зуба при этом уменьшается. Настоящее
  коническое зацепление с постоянной высотой зуба и образующей по конусу
  программа не строит; для кинематики такой модели достаточно, для расчёта
  пятна контакта — нет.
* **Сепаратор** — корончатый: сплошной обод снизу и рёбра между телами
  качения. Штампованный сепаратор с карманами-окнами не строится: вычитание
  карманов из кольца распадалось на отдельные дуги.
* **Упорный подшипник** — два плоских кольца и шары; отверстия под смазку и
  конусные подкладные шайбы не делаются.
* **Шлицы** — геометрия для вида и посадки биты, а не для прочностного
  расчёта: допусков, поднутрений и скруглений входа нет.
* **Резьба** — винтовая поверхность с шагом из параметра, но без допуска и
  без сбега; гайка Nyloc получает нейлоновое кольцо только как канавку, без
  отдельного материала.
* **Фастекс** — две половины лежат рядом; щелчок, упругий ход усиков и
  сопряжение «в защёлкнутом виде» не моделируются. Толщина усиков задана
  долей от толщины корпуса.
* **Ящик** — доски параллельны, сучков, фасок и гвоздей нет; крышка — плоский
  щит с двумя обвязками.
* **Проверки диапазонов** срабатывают до построения: `bearing d=30 D=20`,
  `crate length=200 post=90`, `buckle width=40 length=45` дают ошибку с
  подсказкой, а не молча кривую деталь.

## 6. Примеры

```forma
шариковый = bearing d=15 D=35 B=11
игольчатый = bearing d=20 D=26 B=16 type=игольчатый
упорный = bearing d=30 D=47 B=11 type=упорный

рейка = din_rail length=500
ящик = crate length=880 width=600 height=790
проушина = lug inner=32 outer=64 length=90 thickness=4 bend=30
кронштейн = corner_bracket size=[80,80] width=60 thickness=5 gusset=5
застёжка = buckle width=25 length=60

зубчатая = rack length=300 module=2 width=20 height=18 holes=3
венец = gear_internal teeth=40 module=2 thickness=10 rim=6
косозубая = gear_helical teeth=24 module=2 thickness=12 angle=20 bore=10
коническая = gear_bevel teeth=20 module=2 thickness=12 taper=0.6 bore=10

головка = screw_head d=6 head=цилиндр drive=шестигранник
потай = screw_head d=4 head=потай drive=крест
барашек = wing_nut d=8
nyloc = special_nut d=10 type=nyloc
```

Имя слева от знака равенства — имя объекта в сцене, команда — справа.
