# Топология в ФОРМА 3D: что уже есть, чего не хватает и что автоматизировать

> Часть серии: [индекс всех документов и инструментов](topology_index.md).

Проверено по коду и на реальных файлах 2026-10-30. Речь только о топологии сетки —
не о форме, не о материалах.

---

## 0. Короткий вывод

1. **Ядро (Manifold) уже гарантирует половину того, о чём предупреждает гайд.**
   Дырки, non-manifold, перевёрнутые нормали, дубли граней, T-стыки и n-гоны в
   собственной геометрии приложения **физически невозможны** — их не создаёт ни
   одна команда. Проверять их в сценарии бессмысленно, `check watertight` для
   своей геометрии — тавтология (всегда «пройдено»).
2. **Остаются четыре реальных риска:** качество треугольников (иглы и вытянутые
   грани, до 77 % граней у кружки), неравномерная плотность (разброс длин рёбер
   до ×600 243 у часов), совпадающие вершины из SDF/marching cubes (у `alien`
   после сварки появляются 3 non-manifold ребра) и импорт чужих файлов.
3. **Инструменты лечения есть, автоматики нет.** `clean`, `repair`, `simplify`,
   `refine`, `smooth` — это команды, которые надо *вспомнить и написать*. Ни одна
   из них не вызывается сама, ни на импорте, ни на экспорте, ни после булевых.
4. **Аналитика сильная, но не про топологию.** 25 правил `check` — из них
   топологических 5, и все они меряют сцену, а не файл, который уезжает в Blender.
   Настоящий аудит (`tools/topology_audit.py`, 15 кодов) живёт отдельным CLI и в
   приложении не вызывается вообще.
5. **Инструкция для нейросети о топологии — одна строка** (`weld / repair /
   simplify — сварка, починка, упрощение сетки`). Гайд на 877 строк лежит в
   `docs/`, но в промпт не попадает, поэтому ИИ каждый раз решает задачу заново.
6. **67 % работы можно снять с нейросети** тремя вещами: автоаудит на экспорте с
   гейтом, авто-лечение после SDF/импорта/булевых, и «контракт» в инструкции —
   «топология гарантирована, думай о форме».
7. **Остаётся 20 % решений, где нужен ИИ** (какая стратегия лечения, значим ли
   дефект в этом контексте, менять ли форму) и **13 %, где нужен человек**
   (эстетика, техпроцесс печати, пригодность под риг, приёмка изменений формы).

## 1. Как устроен конвейер и что гарантировано

```
сценарий .forma
   → DSL (dsl.py) → операции (ops_*.py)
   → mf.Manifold  ← единственное представление геометрии
   → metrics.analyze (отчёт, предупреждения) + checks.evaluate_checks
   → export_glb / export_stl / export_obj / export_3mf (trimesh)
   → файл у пользователя
```

`Manifold` — не «меш, который мы надеемся, что замкнут», а математически
корректное тело с границей-многообразием. Каждая операция возвращает либо валидное
тело, либо ошибку.

### 1.1 Что невозможно по построению

| Дефект из гайда | Почему невозможен |
|---|---|
| дырка, незамкнутая оболочка | `Manifold` не бывает с границей |
| ребро с 3+ гранями, «лист ребром» | то же |
| перевёрнутые/несогласованные нормали | ориентация задаётся объёмом |
| дубли граней, z-fighting внутри тела | булевы операции схлопывают совпадения |
| T-стык | нет общего «хирургического» редактирования вершин |
| n-гон, «неплоский квад» | в ядре только треугольники |
| плавающие вершины, мусор | вершины принадлежат граням |

### 1.2 Что реально случается (проверено на экспортах)

| Риск | Откуда | Пример |
|---|---|---|
| Иглы, вытянутые треугольники | `smooth_out`, `refine`, лофт/вращение, резка булевыми | кружка: 76.97 % игл, 78 % вытянутых (19.4 % площади) |
| Неравномерная плотность | почти совпадающие кольца профиля, текст-глифы | часы `мостик_колёс`: ×600 243 (0.000153 … 91.6 мм) |
| Совпадающие вершины из SDF | marching cubes, метаболы, `blob`, `from_sdf` | `alien`: 3 совпавшие вершины → 3 non-manifold ребра **после сварки при аудите** |
| Схлопнувшиеся грани | полюса UV-сферы, стыки булевых | гостиная `lamp_bulb`: 96 граней; часы: 6 граней в 2 объектах |
| Много оболочек | текст, метки, составные детали | часы: 75 оболочек у 60 узлов |
| Швы нормалей | экспорт режет вершины по углу 38° | кружка: 103 120 «совпадающих» вершин — это норма glTF, не дефект |
| Импорт чужого файла | вне контроля ядра | `import repair=нет` падает, `да` — чинит с предупреждением об объёме |

**Важно:** почти все эти дефекты *не видны в приложении* и обнаруживаются только
постфактум, в файле.

## 2. Что уже есть

### 2.1 Инструменты лечения (команды DSL)

| Команда | Что делает | Ограничение |
|---|---|---|
| `clean [a] tolerance=0.01` | сварка вершин, вырожденные и дублирующиеся грани (через trimesh) | только по запросу; на валидном Manifold чаще всего no-op |
| `repair [a] smooth=1 simplify=0.5 drop=0.05 deviation=0.2` | зашивает дыры веером, сглаживает, выбрасывает мусор, упрощает | сделана для сканов; веер даёт плохие треугольники на больших дырах |
| `simplify [a] deviation=0.2` | упрощение ядром с допуском отклонения | не следит за появлением игл |
| `refine [a] length=1.5` / `levels=1…4` | равномерное дробление под целевую длину ребра | растит полигонаж, не адаптируется к кривизне |
| `smooth`, `polish` | G1-сглаживание, снятие «лесенок» | может создать тонкие треугольники |
| `offset`, `shell`, `fillet`, `bevel`, `chamfer` | геометрия, но определяет плотность у кромок | — |
| `union / difference / weld / trim / intersect` | булевы, `weld` сшивает шов без внутренней геометрии | стык двух поверхностей «в ноль» даёт совпадающие вершины |
| `import … repair=да` | сварка + заливка дыр + fix_normals + voxel-фолбэк + предупреждение об изменении объёма >2 % | только импорт |
| `blob`, `from_sdf`, `human`, `door_handle` | SDF/marching cubes: ровная плотность, но артефакты полей | нет пост-обработки топологии |
| `primitive_topology.py` | **квад-логика**: `cube_sphere`, `dual_sphere`, `pentagon_sphere`, `honeycomb_sphere`, `linear_subdivide`, `loop_smooth` | только сферы; в ядро всё равно уходит треугольная сетка |

### 2.2 Аналитика

| Инструмент | Что даёт | Где |
|---|---|---|
| `check` — 25 правил | `watertight, genus, parts, size/height/width/depth, volume, mass, wall, wall_min, flat_bottom, overhang, symmetric, gap, clearance, inside, tris, sharp_edge, tri_quality, deviation, связь, position, center, grid` | `checks.py`, вкладка «Проверки» |
| `metrics.analyze` | габариты, объём, масса, площадь, части, род, стенка (лучи), дно, нависания, симметрия, паспорт детали, сравнение с прошлой сборкой, **12 автоматических предупреждений**, текст отчёта для человека и ИИ | `metrics.py` |
| `passport`, `section`, `probe` | паспорт детали, 2D-сечение с DXF/SVG, «есть ли материал в точке» | `ops_inspect.py` |
| `interference` | пакетный отчёт пересечений объектов (AABB + объём) | `ops_inspect.py` |
| `ориентация` | куда смотрят верх/низ/бока, центр массы | `ops_inspect.py` |
| `tools/topology_audit.py` | 15 кодов: non_manifold, boundary, winding, degenerate_area, degenerate_index, duplicate_faces, inverted, normals_inverted, normals_flat, slivers, stretched, density, loose, doubles, shells; раскладка по объектам, род оболочек, JSON, код возврата | **отдельный CLI** |
| тесты | 10 тестов аудита (проходят), регрессы сцен с проверкой стыков/пересечений (`test_living_room_052.py` и др.) | `tests/` |

### 2.3 Инструкции

| Источник | Объём | Кому |
|---|---|---|
| `docs/topology_guide.md` | 877 строк: 11 разделов, 30 дефектов, 4 чек-листа, аннотированные источники | человеку, лежит вне приложения |
| `README.md` §8 и раздел «Топология перед экспортом» | правила `check`, как запускать аудит | человеку |
| `forma/instruction.py` (кнопка «Инструкция ИИ») | **одна строка** про `weld / repair / simplify` + одна про нулевые треугольники в GLB | нейросети |
| `forma/agent.py` | в примерах есть `check имя watertight` | нейросети |
| `topology-course/` | интерактивный курс со схемами «плохо → лечение» | человеку, для обучения |

### 2.4 Интерфейс

Вкладки «Отчёт», «Проверки» (вердикты ✓/✗), «Объекты», «Связи», «Ассистент»
(сборка запроса к нейросети). Топологического блока нет: ни валентности, ни
качества треугольников, ни числа оболочек.

### 2.5 Замеры на своих примерах

Аудит `topology_audit.py` по свежим экспортам GLB:

| Пример | Трис | Ошибки | Предупр. | NM | Граница | Иглы, % | Игл на изгибе, % площади | Разброс длин рёбер |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| `mug` | 41 248 | 0 | 1 | 0 | 0 | **76.97** | 0.01 | ×31 457 |
| `vase` | 8 568 | 0 | 0 | 0 | 0 | 0.00 | 0.00 | — |
| `apple` | 20 456 | 0 | 0 | 0 | 0 | 1.57 | — | — |
| `clock` | 50 062 | **2** | 9 | 0 | 0 | 19.62 | 86.2 (`стойка_1`) | **×600 243** |
| `alien` | 19 056 | **1** | 0 | **3** | 0 | 0.14 | 0.03 | — |
| `living_room` | 94 512 | **1** | 7 | 0 | 0 | 25.00 | 10.17 | ×30 687 |

Три вывода из таблицы:

* **Кружка и часы доказывают, что `check tri_quality 2` в нынешнем виде
  непригоден:** 77 % «игл» у кружки — плоские, они безвредны, но правило их
  считает и валит проверку. Нужен разрез «иглы на плоскости / на изгибе» — он уже
  реализован в аудите, но не в `check`.
* **`alien` — штатный пример приложения — уезжает в Blender с 3 non-manifold
  рёбрами.** Приложение об этом не сообщает: `Manifold` валиден, дефект возникает
  при экспортной сварке совпавших вершин из marching cubes.
* **`living_room` и `clock` дают ошибку `degenerate_index`** (96 и 6 схлопнувшихся
  граней) — то есть у собственных примеров есть дефекты уровня «ошибка», а
  панель «Проверки» показывает зелёное.

Стоимость: анализ сцены гостиной 253 объекта / 140 тыс. треугольников — 13.0 с с
анализом против 10.6 с без (накладные +2.4 с); аудит готового GLB на 94 тыс.
треугольников — 1.6 с. То есть аудит дёшев для экспорта и слишком дорог для
пересчёта на каждое нажатие клавиши.

## 3. Чего не хватает

| Компонент | Сейчас | Следствие |
|---|---|---|
| Топологические метрики в отчёте | нет ни валентности, ни игл, ни оболочек | ИИ и человек не видят главного риска |
| Аудит в приложении | только внешний CLI | дефект находят после экспорта, вручную |
| Гейт на экспорте | экспорт пишет файл без проверок | `alien`/`clock`/`living_room` уезжают с ошибками |
| Авто-лечение | `clean`/`repair` — только по команде | нейросеть должна помнить о них в каждом сценарии |
| Правила `check` по топологии | 5 из 25, без плоских/изогнутых игл, без оболочек и полюсов | нельзя поставить требование «0 игл на изгибе» |
| Цель модели | пороги стенок захардкожены под печать | для рендера и анимации предупреждения нерелевантны |
| Локализация | аудит даёт объект, но не место | нельзя починить точечно |
| LOD / бюджет полигонов | только `check tris` | нет уровней детализации |
| Инструкция для ИИ | одна строка | нейросеть думает о топологии каждый раз |
| CI | аудит не запускается в workflow | регресс топологии не отлавливается |
| Квады/SubD на выходе | логические квады только у сфер | для скиннинга в Blender нужна ретопология руками |

## 4. Что можно автоматизировать полностью (без ИИ)

Порядок — по соотношению «польза / объём работы».

### P0.1 Единый модуль топологии `forma/topology.py`

Перенести логику `tools/topology_audit.py` из stdlib-читалки файлов в работу с
`mf.Manifold`, оставив CLI тонкой обёрткой (тесты `test_topology_audit.py` не
ломаются, аудит становится общим источником правды для приложения, CLI и CI).

```python
# forma/topology.py
def topology_report(solid, *, min_angle=3.0, max_aspect=10.0) -> dict:
    """Тот же набор кодов, что у CLI, но по живому Manifold."""

def scene_topology(scene) -> dict:
    """Сводка по сцене + список объектов с ошибками."""
```

### P0.2 Блок `topology` в `metrics.analyze`

Считать по объектам с кэшем (как `MetricsCache`: ключ `имя + tris`): число игл и
вытянутых, доля игл на изгибе, разброс длин рёбер, оболочки, полюса, схлопнувшиеся
грани. В отчёт — 3 строки и предупреждения с кодами. Стоимость +1.5–2 с на сцену
140 тыс. треугольников; полный вариант — только для экспорта и вкладки «Отчёт».

### P0.3 Гейт на экспорте + JSON-отчёт

В `webui.export()` и `cli.cmd_export` перед записью файла:

* прогнать `topology_report` по тем же массивам, что уходят в GLB;
* положить рядом `<имя>.topology.json`;
* при ошибках — **не писать файл** и вернуть понятный список с подсказкой
  `heal …` (флаг `force=да` для осознанного обхода).

Это одна точка, закрывающая `alien`, `clock` и `living_room`.

### P0.4 `heal` — авто-лечение

```forma
деталь = heal [деталь] purpose=печать        # по умолчанию
деталь = heal [деталь] purpose=рендер force=да
```

Цепочка: сварка совпавших вершин → растворение вырожденных граней → удаление
крошечных оболочек → ориентация → (для сканов) заливка дыр → упрощение до допуска.
После каждого шага — контроль: объём ±2 %, габарит ±0.1 мм, иначе откат шага и
отчёт. Для `blob`/`from_sdf` включать автоматически.

### P0.5 Бюджеты в генераторах

* `lathe`/`loft`/`sweep`: если соседние точки профиля ближе 0.05 мм — схлопывать
  и предупреждать (причина ×600 243 у часов и ×30 687 у `plant_pot`).
* `refine`/`smooth`: после операции — локальный `simplify` плоских зон, чтобы не
  плодить иглы (кружка: 77 %).
* `blob`/`from_sdf`: мин. шаг сетки и пост-сварка совпавших вершин.

### P1.1 Новые правила `check`

`manifold`, `shells 1`, `slivers 2`, `slivers_bend 0.2`, `poles 8`, `edge_spread 50`,
`normals`, `self_intersect`, `topology` (композит: все коды аудита разом).
Разрез «плоско/изгиб» обязателен — иначе кружка с 77 % плоских игл никогда не
пройдёт проверку.

### P1.2 Локализация

К каждому коду — не только объект, но и центр масс проблемного кластера и
габарит. Тогда ИИ (или авто-лечение) правит точку, а не всю деталь.

### P1.3 `purpose` на объект и сцену

`purpose=печать|рендер|деформация|cad` — от него зависят и пороги `check`, и
набор предупреждений, и требования гейта. Сейчас порог «стенка ≥ 1.2 мм» вшит в
`metrics.py` независимо от задачи.

### P1.4 `lod`

Три уровня детализации с допусками и отчётом «что осталось от топологии».
Полезно для game-ready и рендера; на печати не нужно.

### P1.5 Аудит в интерфейсе и в CI

Вкладка «Проверки» + сворачиваемый блок «Топология» (светофор по худшему коду,
таблица объектов, кнопка «Починить» = `heal`). В workflow — прогон аудита по
`forma/exports/**/*.glb` (инфраструктура уже есть).

### P2 Квады и SubD

Генерация quad-dominant сетки для сфер/цилиндров/лофтов и экспорт «под SubD».
Сейчас квады существуют только как логические панели в `primitive_topology.py`, в
ядро уходят треугольники. Это месяцы работы и нужно только тем, кто уходит в
Blender на скиннинг.

## 5. Где автоматика не справится сама, но справится ИИ с проверками

Это режим «полуавтомат»: приложение считает факты и предлагает инструменты, ИИ
принимает решение и вызывает команду, приложение проверяет результат.

| Решение | Почему не автоматизируется | Что делает ИИ | Чем проверяется |
|---|---|---|---|
| Значим ли дефект | игла на плоскости безвредна, на изгибе — полосы; у тонкой детали неизбежна | смотрит долю «на изгибе» и контекст детали | `slivers_bend`, рендер под углом |
| Стратегия лечения | веер, Grid Fill-подобная заливка, пересборка узла, `refine`+`simplify`, `heal` | выбирает по геометрии и по цене | аудит до/после, объём/габарит |
| Менять ли форму ради топологии | иногда проще перестроить узел, чем чистить | решает, предлагает пользователю | `check deviation`, `interference` |
| Назначение модели | печать / рендер / анимация — разные требования | спрашивает или выводит из задачи | `purpose` |
| Направление потока и плотность | где ставить плотнее — вопрос смысла | задаёт `refine length=…` локально | `edge_spread`, `tris` |
| Когда `simplify` допустим | риск потерять мелкую деталь | сравнивает метрики до/после | `deviation`, паспорт |
| Ремонт неизвестного импорта | нельзя знать, что «правильно» | выбирает repair/пересборку/отказ | объём ±2 %, скан-отчёт |
| Бюджет полигонов между деталями | компромисс рендера и печати | распределяет по важности | `check tris` по объектам |
| Достаточно ли хорошо | «зелёный» гейт ничего не говорит о замысле | судит по смыслу задачи | отчёт + снимки |

Ключевой приём: **ИИ не считает — он выбирает.** Все числа даёт приложение, ИИ
выбирает стратегию из закрытого списка и перепроверяет результат тем же отчётом.

## 6. Что без человека не проверить и не исправить

1. **Эстетика и силуэт после лечения.** Сварка/упрощение могут «зализать» угол или
   убрать фаску. Числа это пропустят, глаз — нет.
2. **Пригодность под конкретный риг и мимику.** Приложение не знает, где будет
   локоть, и не хранит петель: судить о пригодности для скиннинга может только
   человек (или ретополог в Blender).
3. **Техпроцесс печати:** материал, ориентация, поддержки, допуски станка и
   усадка. Приложение оценивает стенку и нависания, но не знает ваш принтер.
4. **Допуски сборки и посадок** в реальном изделии (зазор 0.2 мм — норма для
   дерева и провал для прецизионной механики).
5. **Намеренные технологические вхождения.** В гостиной 64 разрешённых контакта и
   17 стыков каркаса — это проектное решение, а не дефект. Автоматика не отличит
   замысел от ошибки без разметки.
6. **Происхождение и лицензия импортированной модели** — юридический вопрос.
7. **Приёмка изменений формы после `repair`** (объём изменился на 2 %: это
   допустимо или уже брак?).
8. **Конфликт «форма против топологии»**, когда выбор меняет замысел.

(+2.4 с приемлемо, +10 с — нет); число «сюрпризов после импорта в Blender» (цель 0).

## 8. Приложение

### 8.1 Что можно сделать уже сегодня (без доработок)

```forma
деталь = clean [деталь] tolerance=0.01
check деталь watertight
check деталь parts 1
check деталь tri_quality 2
check деталь tris 2000..80000
check деталь sharp_edge 120
```

и отдельно, после экспорта:

```bash
python3 forma/tools/topology_audit.py готовая.glb --json отчёт.json
```

### 8.2 Предлагаемый текст для инструкции ИИ

> **ТОПОЛОГИЯ (контракт).** Ядро возвращает только корректные тела: дырки,
> non-manifold, перевёрнутые нормали и n-гоны невозможны — не трать на них
> проверки и рассуждения. Ты отвечаешь за форму, положение и поворот. Плотность
> задавай через `refine length=…` только там, где нужна мелкая работа. Если в
> отчёте `topology.status = warn`, выполни `heal [объект]` и пересобери отчёт.
> Если `heal` не помог — сообщи человеку код дефекта и объект, не перестраивай
> форму сам.

### 8.3 Коды дефектов — единый словарь

`non_manifold, boundary, winding, degenerate_area, degenerate_index, duplicate_faces,
inverted, normals_inverted, normals_flat, slivers, stretched, density, loose, doubles,
shells` — те же 15, что в `tools/topology_audit.py`. Любая новая проверка обязана
использовать один из них, чтобы отчёт, UI и гайд говорили на одном языке.
