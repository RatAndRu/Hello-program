# Этап 0: benchmark, профилирование и воспроизводимые проверки

Этот контур измеряет существующее ядро и ответы внешней нейросети. Он не
вызывает сеть, не добавляет ограничения токенов/команд и не создаёт новых
проектов в меню.

## 1. Профиль каждой команды

`Build.command_timings` и одноимённое поле JSON содержат для каждой исполненной
DSL-команды:

- порядковый номер и строку исходника;
- каноническое и исходное имя команды;
- объект результата;
- `ok/error`;
- время в миллисекундах.

В профиль попадают параметры, проверки и команда, на которой сборка упала.
Кадры сборки (`steps`) по-прежнему служат другой цели и не используются как
профиль.

```bash
python -m forma build model.forma --profile
python -m forma build model.forma --json > build.json
```

`--profile` печатает самые медленные команды и этапы parse/build/analysis.
JSON остаётся машинным без дополнительного текста. Время зависит от машины и не
является golden-критерием.

## 2. Golden и eval

Набор: `benchmarks/foundation.json` — 20 задач по примитивам, профилям,
булевым, механике, оригами, SDF, тексту, полостям и размещению по меркам.

У каждой задачи есть:

- пользовательский `prompt`;
- эталонный `script`;
- обязательные/запрещённые команды;
- независимые `checks`.

Проверки добавляются раннером после сценария кандидата. Поэтому удаление
`check` из ответа не повышает результат. Эталон допускает разные решения:
важны заданное имя результата, геометрия и проверки, а не побуквенное совпадение
сценария.

```bash
# Проверить эталон и записать новый измеренный отчёт.
python -m forma.eval --out candidate-reference.json

# Сравнить успешность с зафиксированным baseline.
python -m forma.eval --out foundation-eval.json \
  --compare docs/foundation_baseline.json
```

Отчёт содержит версии Forma/Python/manifold3d/numpy, hash benchmark и каждого
сценария, успех, первую попытку, число итераций, ошибки, независимые проверки,
габариты, объём, части, род, треугольники и профиль команд.

`docs/foundation_baseline.json` — эталонный прогон: **20/20 задач и 80/80
независимых проверок**, 28 152 треугольника в успешных сценах. Это baseline
геометрического контура, а не заявленный процент качества какой-либо LLM.

### Ответы нейросети

Каталог кандидатов поддерживает два формата:

```text
primitive_box.forma              # одна попытка
primitive_box.attempt01.forma   # первая попытка
primitive_box.attempt02.forma   # исправление после ошибки компилятора/проверок
```

Если есть `<id>.forma`, он имеет приоритет над серией attempt. Раннер идёт по
попыткам до первого успеха и считает отдельно:

- успех первой попытки;
- финальный успех;
- число итераций;
- число задач, исправленных после первой попытки.

```bash
python -m forma.eval --candidates /path/to/attempts \
  --out model-eval.json --compare docs/foundation_baseline.json
```

Для исследовательского прогона, где неуспешные задачи тоже нужны в отчёте,
есть `--allow-failures`. Сравнение не использует машинно-зависимое время как
признак регрессии.

## 3. Детерминированный fuzz

```bash
python -m forma.fuzz --cases 24 --seed 20261102 \
  --timeout 30 --output fuzz-report.json
```

Генератор покрывает примитивы, extrude, отверстия, fold_sheet, канавки, gear,
pipe, текст, blob и spring. Одинаковые `seed/cases` дают одинаковые сценарии.

Каждый случай выполняется в отдельном spawn-процессе. Проверяются:

- отсутствие ошибки построения;
- видимые непустые тела и `NoError`;
- положительный конечный объём и конечный bbox;
- GLB: сигнатура, версия и согласованная длина.

При падении или timeout рядом с отчётом создаётся папка
`<имя>-repros/<case>.forma` и JSON с ошибкой. Случаи короткие и сами служат
minimal repro. Локальный baseline seed `20261102`: **24/24**.

Оба контура включены в Windows CI; JSON-отчёты прикладываются к CI artifacts.

## 4. Регрессии оригами

Добавлены компактные проверки трёх фактических рисков:

1. При угле `сгиб` ≤ 22° `simplify` больше не может удалить всю дугу ради
   допуска, превышающего её стрелку. Плоские полотнища по-прежнему упрощаются.
2. Повторный `fold` не возвращает ложный успех при грубой потере объёма:
   предусмотрен жёсткий предел 5% даже при последовательных операциях.
3. `fold_sheet parts=4 angle=179` проверяется на одно тело и сохранение объёма
   в пределах 2%.

Это защита от молчаливых дефектов, а не объявление общего многослойного
оригами решённым. История складок и обратная деформация уже сложенной сетки в
этот этап не входят.
