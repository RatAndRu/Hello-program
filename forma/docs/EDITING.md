# Правка сценария из панели параметров

Источник истины Формы — текст `.forma`. Панель не хранит значений: она просит
сервер изменить **одну строку** и пересобирает модель обычным путём. Никакого
второго состояния (кэша значений, «черновика» параметров) нет.

## 1. Смещения вместо регулярных выражений

`forma/dsl.py` при разборе считает карту смещений: для каждого символа
логической строки — его позицию в файле. В `Command.spans` попадают диапазоны

```text
line   [начало, конец]           — вся команда без комментария
verb   [начало, конец]           — слово операции
args   [[начало, конец], …]      — позиционные аргументы
kwargs {ключ: {key, value, whole}} — имя, значение и весь токен
target — у присваивания, диапазон всей строки
```

Склейка переносов (`\` и незакрытые скобки) смещения не теряет: пробел,
вставленный между физическими строками, получает позицию последнего символа
предыдущей строки, а токены остаются на своих настоящих местах. Поэтому
`at=[0,0,9]` на второй строке команды правится по абсолютному смещению в файле.

Проверка — `tests/test_v075.py::SpansTest`.

## 2. Правки

`forma/edit.py::edit_source(script, edit)` возвращает новый текст и описание
того, что произошло. Ошибка не портит файл: при отказе текст возвращается
без изменений.

| `action` | Аргументы | Поведение |
|---|---|---|
| `set_param` | `line`, `param`, `value` | заменяет значение; если параметра нет — дописывает в конец команды |
| `set_at` | `line`, `value` | то же для `at` |
| `unset_param` | `line`, `param` | убирает параметр вместе с пробелом перед ним |
| `set_params` | `line`, `values` | несколько параметров за один проход |
| `add_command` | `after_line`, `text` | вставляет одну строку |
| `delete_line` | `line` | удаляет физическую строку (или весь блок переноса) |
| `move_line` | `line`, `to` | переносит блок после строки `to` |
| `set_enabled` | `line`, `enabled` | выключает шаг, ставя `# ` в начало строки |

Правила:

* **Связанные значения не перезаписываются молча.** Если в строке стоит
  `round=R/2`, правка возвращает `reason: "linked"` и требует
  `break_link: true`. Интерфейс спрашивает подтверждение.
* **Строки внутри `module`/`def` не правятся.** Панель помечает их
  `editable: false`: это текст автора сценария, а не параметры модели.
* **Имя параметра ищется с учётом синонимов.** Если в строке написано
  `радиус=10`, правка параметра `radius` изменит именно это слово.
* **Перенос строки не ломается.** Недостающий параметр дописывается в конец
  команды (в последнюю физическую строку), а не перед `\`.

## 3. Типы параметров

`forma/param_spec.py` объявляет для операции тип каждого параметра:

| Тип | Элемент управления |
|---|---|
| `num` | ползунок + стрелки шага + поле, единица рядом |
| `int` | то же с шагом 1 |
| `vec` | отдельное поле на компоненту (`x`, `y`, `z`) |
| `flag` | чекбокс |
| `enum` | список со стрелками, ввод запрещён |
| `str` | свободный ввод — единственный допустимый случай |

Режимы «авто»:

* `omitted` — параметра нет в строке (значение выбирает операция);
* `sentinel` — особое число, например `0` = «по детализации»;
* `enum` — «авто» отдельным пунктом списка.

Кнопок сброса две: `↺` возвращает заводское значение, чекбокс «авто» убирает
параметр из строки. Это разные действия, и они по-разному выглядят в тексте.

Итого 133 параметра из 2502 у 241 операции (5.3 %). Остальные пока приходят в

интерфейсе и в отчёте, но не закрывает требование «ни одного обязательного
ручного ввода» для остальных операций: их спецификации нужно объявлять
по семействам (резьба и крепёж, механизмы, архитектура, текст и кривые).

## 4. Скорость

`POST /api/edit` собирает модель с `analyze_model=False` и возвращает
`timings` (мс): `parse`, `build`, `total`. Замер на `examples/alien.forma`
(15 команд, 231 000 треугольников): разбор — 1.1 мс, сборка — 803 мс, полный
запрос — 815 мс. Анализ модели запускается отдельно, кнопкой проверок.

## 5. Стек инструментов объекта

Для выбранного объекта панель показывает все его строки в порядке выполнения:

* `▲` / `▼` — перестановка (`move_line`); если после перестановки модель не
  собралась, текст возвращается к прежнему виду;
* `◼` / `◻` — временное выключение и включение (`set_enabled`);
* `✕` — удаление строки (`delete_line`);
* параметры каждой строки — типизированные контролы.

У `union`, `difference` и вычитания сверху идут блоки **фигур-источников** из
провенанса: параметры принадлежат источникам, а не результату.
