Семь простых фигур-знаков сделаны в 0.24. Здесь — разбор сложных направлений:
что именно мешает сегодня, какая команда нужна, как её честно реализовать в
текущем ядре (manifold3d + сетка + SDF + текстуры), сколько это стоит по
времени и треугольникам и в каком порядке брать.

Общий принцип: **сначала материал поверхности, потом предмет**. Все девять
направлений про «поверхность не гладкая»: складки, пряди, чешуйки, поры,
кладка, зазубрины. Если сделать один инструмент деформации и один инструмент
тиражирования деталей по поверхности, из них собираются почти все пункты.

## 0. Что уже есть (на это опираемся)

| инструмент | что даёт | чего не хватает |
|---|---|---|
| `sweep` + `scale_curve` + `round_caps` | труба переменного сечения по пути | ступенчатое сужение только по длине, нет плоского профиля-линзы |
| `lathe` + `thickness` | тело вращения со стенкой | нет углового рельефа (складки по кругу) |
| `blob` / `from_sdf` | плавные органические слияния | дорого на мелочи, сетка по всему объёму |
| `fuse` | сварка и скругление стыков | не создаёт складок, только сглаживает швы |
| `scatter` | разброс копий по площади | разбрасывает по плоскости, а не по поверхности детали |
| `holes`, `knurl`, `groove` | отверстия, накатка, канавки | только тела вращения и плоские сетки |
| `texture`, `emboss` | картинка на поверхности, надпись | текстура **не меняет геометрию** |
| `import`, `clean`, `simplify`, `smooth` | чужие модели, чистка сетки | нет заделки дыр и воксельного пересчёта |

Ключевой недостающий кирпич — **один универсальный** инструмент:

## 1. `wrinkle` — волна по поверхности (фундамент для половины списка)

```
складки = wrinkle [юбка] amp=3 freq=18 axis=z mode=радиус seed=1
```

Что делает: берёт вершины готового тела, считает для каждой локальные
координаты (цилиндрические `r, φ, z` или декартовы `x, y, z`), гонит
периодическую функцию и смещает вершину по нормали. Тело пересобирается через
`manifold_from_arrays` (этот путь уже используется в `fuse`, `holes`, `knurl`).

Режимы, которые закрывают разные пункты списка:

| `mode` | формула смещения | для чего |
|---|---|---|
| `радиус` | `amp·cos(freq·φ)` | плиссе юбки, рёбра вазы, гофра стакана |
| `высота` | `amp·cos(freq·z)` | кольцевые складки ткани, рёбра сильфона |
| `шум` | `amp·fbm(x,y,z)` | кора дерева, пемза, мятая ткань, камень |
| `клетка` | `amp·cos(fx·x)·cos(fy·y)` | стёганая ткань, пупырчатый шоколад |
| `трещины` | `-amp·|cos|^k` | кора, кирпич, потрескавшаяся краска |

Стоимость: 0.05–0.2 с на 20–60 тыс. треугольников, память — одна копия сетки.
Требует, чтобы тело было достаточно плотным: перед деформацией автоматически
`refine_to_length(amp/3)`.

**Порядок: сделать первым.** На нём сразу едут: ткань (складки), кора,
пористый камень, мятая бумага, гофра, чешуя-рябь, волны на воде.

## 2. `garment` — ткань: юбка, пиджак, смокинг

Две разные задачи, не надо смешивать:

**(а) Юбка — тело вращения со складками.** Это `lathe` по замкнутому профилю,
где радиус зависит ещё и от угла: `r(φ, z) = r0(z)·(1 + k·cos(n·φ)·w(z))`,
`w(z)` растёт книзу (у пояса складок нет). Готовая команда:

```
юбка = skirt waist=60 hem=190 length=240 pleats=12 depth=8 thick=3
```

Внутри: `массив профилей` → `loft` по кольцу с `closed_path` (он уже умеет
замыкать) или прямое построение вершин, потом `shell` на толщину. Одно тело,
2–6 тыс. треугольников, 0.1 с. Плиссе, годе, клёш — это `depth` и `pleats`.

**(б) Пиджак/смокинг — оболочка по сечениям туловища.** Это `loft` из 10–14
сечений (шея → плечи → грудь → талия → бёдра), где каждое сечение — не
окружность, а сглаженный прямоугольник с вырезами под проймы. Лацканы — две
`свернуть`-полосы (плоский профиль по пути от шеи к груди, `banana` уже даёт
нужную дугу). Рукава — `sweep` по дуге с `scale_curve`, манжеты — `ring`.

```
смокинг = jacket height=760 chest=104 waist=92 shoulders=46 lapels=да sleeves=да
```

Это уже не один примитив, а **набор**: `jacket` собирает 6–8 деталей и в конце
`fuse radius=6 edges=все` — чтобы силуэт был слитным, а не «торс + две трубы».
Стоимость 0.5–2 с. Складки на локтях и подоле — `wrinkle mode=высота`.

## 3. `hair` — волосы и мех: аниме-причёска, кот

Волосы — это не тысячи волосков, а **пряди-клин**: плоский линзовидный профиль,
проведённый по дуге, с сужением к концу и лёгкой закруткой. Из 20–40 таких
клиньев получается читаемая аниме-причёска, и это одно тело после `fuse`.

```
причёска = hair head=да style=аниме length=180 spikes=9 clumps=24 sweep=да
```

Внутри: скальповая зона на сфере/эллипсоиде → для каждой пряди строится путь
(от макушки вниз-в сторону, с изгибом), профиль — линза `w×0.25w`, `sweep` с
`scale_curve=[1, 1.15, 0.6, 0.05]` и `round_caps`. В конце `batch_boolean(Add)`
и один `fuse radius=2`, чтобы пряди слиплись у корней.

| стиль | как строится | пример |
|---|---|---|
| `аниме` | 20–30 широких клиньев, острые кончики, чёлка отдельным веером | персонаж |
| `хвост` | 1 толстый жгут назад + резинка `ring` | хвост, косичка |
| `короткий` | 12 клиньев по черепу, длина до шеи | кот, мальчик |
| `мех` | те же клинья, но густо и коротко, по всей поверхности тела | кот, шерсть |

**Мех** отдельной командой: `fur [кот] length=6 density=25` — короткие
конусы по нормалям, только в силуэтных зонах (там, где нормаль смотрит от
камеры вбок). Честное предупреждение: полноценный мех — это текстура и
шейдер, а не геометрия. Геометрией делаем **силуэт** (20–60 клоков), остальное
— карта шерсти в материале.

## 4. `scales` — чешуя, дракон, рыба

Чешуя — тиражирование плиток по поверхности. У нас есть `ray_cast`, значит
можно честно найти поверхность:

```
чешуя = scales [рыба] length=14 width=11 rows=9 overlap=0.45 lift=0.6
```

Алгоритм: для сетки параметров (u вдоль оси, v по кругу) пускаем лучи изнутри
наружу вдоль нормали, получаем точки и нормали, ставим в каждой «черепицу»:
плоскую каплю (`drop` сплюснутый или линзу) с наклоном по нормали и поворотом
по касательной, соседние ряды перекрываются на `overlap`. Всё в один
`batch_boolean(Add)`, затем `fuse radius=1`, чтобы чешуйки срослись с телом.

Стоимость: 200–600 чешуек × 60 трис ≈ 30 тыс. трис, 0.3–1 с. Больше 1000 —
уже тяжело, тогда `lift` мельче и `simplify`.

Дракон и рыба собираются из этого + существующего: тело — `sweep` по
S-образному пути с `scale_curve` (толстое в груди, тонкое к хвосту), плавники
— `banana flat=0.25`, крылья — две тонкие мембраны (лофт из 3 сечений) на
лучах-пальцах, голова — `blob` из 4 сфер, рога — `horn`, гребень — `scales
row=1`. Это рецепт в `examples/dragon.forma`, а не новая команда.

## 5. `foliage` — листья, трава, куст, клумба

`leaf` уже есть. Не хватает трёх вещей:

* `grass patch=120 width=400 depth=300 blades=300 height=90 bend=25` — пучок
  травинок: 300 тонких `sweep` по дуге с разбросом; 0.3 с. Для газона — не
  геометрия, а текстура + 20 силуэтных пучков по краю.
* `bush size=200 leaves=180` — `blob`-основа + `scatter` листьев по её
  поверхности (тот же `ray_cast`, что у чешуи).
* `bloom petals=7 radius=40` — цветок: `petals` лепестков-линз по кругу +
  сердцевина; клумба = `scatter` из 10–30 цветков по площади с `seed`.
  Плюс существующий `scatter` уже даёт разброс — нужно только повернуть
  копии по нормали склона (это уже сделано в `pile`).

## 6. `display` — экран: смартфон, будильник

Сегодня экран собирается вручную из 4 деталей (корпус, ниша, экран, стекло),
как в `clock_led.forma`. Нужна одна команда:

```
экран = display width=64 height=132 thick=9 style=смартфон
телефон = display width=64 height=132 thick=9 style=смартфон content=семь_сегментов
```

Внутри: скруглённый корпус (`box round`), внутренняя ниша (`shell`), панель
`material=screen`, стекло `transmission=0.7`, фаска на кромке, четыре кнопки.
`content=led` дополнительно ставит `seven_seg` на панель, `content=ui` —
несколько эмиссивных прямоугольников/полосок (полоски статуса, часы, иконки).
Это шаблон из 5–7 строк, завёрнутый в команду, чтобы нейросеть не собирала
его каждый раз заново.

Будильник отличается корпусом-«мыльницей» (`fuse radius=9 edges=все`, как уже
сделано в 0.23) и верхней кнопкой — параметр `style=будильник`.

## 7. `mirror` — зеркало

Геометрия тривиальна (рама + пластина `material=mirror`), а вот **отражение**:

* PNG-отчёты: уже есть отражение «студии» (пол/небо/софтбокс). Достаточно
  добавить в `_shade` второй проход для плоскостей с `metal>0.9, rough<0.05` —
  отражать не только окружение, но и другие объекты сцены (трассировка луча
  от пикселя в плоскость и по отражённому направлению в zbuffer). 0.1–0.3 с на
  кадр — реально, потому что у нас уже есть `ray casting` по zbuffer.
* Окно: три.js `Reflector` даёт настоящее планарное отражение; ставим только
  для объектов с `material=mirror` (одна плоскость на сцену).
* В GLB: зеркало = `metal=1, rough=0.02` + окружение; Blender покажет
  отражение сам.

Отдельная команда: `зеркало = mirror width=600 height=900 frame=40`.

## 8. `porous` — пемза, губка, шоколад, сыр

Дырки бывают трёх разных типов, и это три разных инструмента:

| предмет | тип | как |
|---|---|---|
| пемза | много мелких пор у поверхности | `wrinkle mode=шум` + 40–80 вычтенных сфер малого радиуса, только в тонком слое у поверхности |
| губка | крупные сообщающиеся каверны | ячеистая структура: 3D-сетка Вороного/кубическая решётка, вычитание 30–60 эллипсоидов, потом `shell` не нужен — дырки сквозные |
| воздушный шоколад | пузыри внутри, поверхность гладкая | вычитание сфер **внутри** тела, снаружи ни одной: `random inside bbox, keep if distance to surface > r` |
| сыр (эмменталь) | редкие крупные круглые глазки | `holes` уже почти умеет: нужен `mode=глазки` — сетка с сильным `seed`-разбросом и сферы разного радиуса |

Одна команда с режимом:

```
пемза = porous [камень] mode=поры size=4 density=60 seed=3
губка = porous [блок] mode=ячеи size=18 density=25
шоколад = porous [плитка] mode=пузыри size=6 density=35
```

Стоимость — главный риск: 200 вычитаний на 50 тыс. трис = 2–6 с. Поэтому:
сначала `simplify` до 8–12 тыс., вычитание `batch_boolean`, потом `refine`.
И честная проверка `check` (герметичность) после.

## 9. `lattice` — сетка: клетка, забор, ситец, ткань

Сетка — это решётка из брусьев, **обрезанная по детали**:

```
клетка = lattice [купол] mode=ромб cell=40 wire=4 depth=30
```

Алгоритм: строим два (или три) семейства брусьев-полос, пересекаем их между
собой, получаем плоскую/объёмную решётку, затем `intersect` с оболочкой
детали (`shell [купол] thickness=depth`). Результат — решётка, повторяющая
форму. Забор — `lattice mode=прямоуг` на плоскости + столбы; ситец/ткань —
это уже текстура, а не геометрия (печать рисунка `texture` + складки
`wrinkle`).

Стоимость: 40×40 брусьев ≈ 6 тыс. трис, 0.2–0.5 с.

## 10. `bark`, `bricks` — рельефные вещи

* **Кора**: `bark` = `lathe` ствол + `wrinkle mode=трещины amp=4 freq=9` +
  несколько глубоких вертикальных борозд (`groove` с большим шагом) +
  поперечные трещины. 1 тело, 0.3 с. Ключ — не шум, а **вертикальные
  борозды с рваным краем**: `amp(r) = base + шум·0.4`, чтобы борозды были
  неровными.
* **Кладка**: `bricks width=250 height=180 brick=[60,25] joint=8 rows=6` —
  ряд кирпичей со сдвигом вполкирпича, шов вдавлен (`joint`), сколы углов
  (`chamfer`), разные размеры ±2 %. Одно тело после `union` + `fuse radius=1`.
  Кладка — редкий случай, когда `union` уместнее `fuse`: швы должны быть
  видны.

## 11. `blade` — лезвия: ятоган, катана, стилет, серп

Клинок — это **лофт сечений вдоль изогнутой оси**, где сечение — линза с
одним или двумя остриями:

```
катана = blade length=700 width=32 thick=7 curve=18 kind=катана edge=одна
стилет = blade length=280 width=14 thick=4 kind=стилет edge=две
серп = blade length=300 width=40 curve=140 kind=серп edge=одна
```

Сечение задаётся как многоугольник из 6–8 точек: спинка (толстая, скруглённая),
дол (необязательная канавка), кромка (сходится в 0.05–0.1 мм — острее не
имеет смысла, ядро требует замкнутый объём). По длине: у основания полная
толщина, к кончику `kissaki` — скос. `curve` — стрела прогиба (у катаны
18–25 мм на 700 мм), `kind` подставляет пропорции и профиль:

| kind | сечение | изгиб | кончик |
|---|---|---|---|
| `катана` | несимметричная линза, спинка 0.35 толщины | 18–25 мм | kissaki, скос 25° |
| `танто` | толще, спинка прямая | 0–5 мм | широкий скос |
| `стилет` | ромб, две кромки | 0 | игла |
| `двуручник` | линза, две кромки, дол | 0–8 мм | скос |
| `серп` | сильный изгиб, кромка внутри | 120–160° | остриё внутрь |
| `ятоган` | как катана, но шире | 15 мм | — |

Стоимость: 2–6 тыс. трис, 0.1 с. Плюс рукоять (существующий `sweep`) и
гарда (`box`/`ring`) — в рецепте `examples/katana.forma`.

## 12. `relief` — карта высот: узор на вазе, логотип, принт

Два разных сценария, и первый важнее:

**(а) Настоящий рельеф геометрией.** Картинка читается в градациях серого,
значение 0…1 = смещение по нормали. Для вазы развёртка цилиндрическая
(`u = φ/2π`, `v = z/h`), поэтому узор **оборачивается без шва**:

```
ваза = lathe points=[...] segments=256
ваза = relief [ваза] image=docs/pattern.png depth=2 mode=обёртка
логотип = emboss [плита] text="ФОРМА" depth=1.2     # уже есть
принт = relief [плита] image=logo.png depth=0.6 mode=плоскость
```

Реализация: `PIL` уже в зависимостях, читаем картинку в градациях серого,
билинейно сэмплируем, смещаем вершины по нормалям, пересобираем манфолд.
Требование — плотная сетка: `refine_to_length(depth/2)` перед деформацией,
иначе узор «поплывёт». 512×512 картинка на 100 тыс. трис — 0.4 с.

**(б) Карта высот в материале (без геометрии).** Для мелкого: генерируем из
той же картинки normal map и кладём в `texture` — в окне и в Blender это
неровность, которая ничего не стоит по треугольникам. В PNG-отчёте добавим
«bump» в `_shade`: сдвиг нормали по градиенту карты — 20 строк в рендере.

## 13. `pattern` — рисовать примитивами (ваш «куб с кружками»)

Это уже работает через `вычесть`/`пересечь`, не хватает удобства: одной
командой размножить резак по поверхности.

```
плита = box size=[120,90,20]
плита = pattern [плита] shape=sphere radius=9 grid=[4,3] depth=6
```

Внутри — `array` по двум направлениям + `ray_cast` до поверхности + вычитание
с запасом `depth` внутрь. Тем же способом делаются: отверстия по сетке,
тиснение логотипом, «пузыри» на панели, зубчатый край. Родственник `holes`,
но с любой фигурой-резцом.

## 14. `repair` — довести скан до рабочего тела

`import` + `clean` уже есть, но сканы приходят дырявыми, и ядро требует
замкнутый объём. Нужна последовательность:

```
скан = import "scan.stl"
скан = repair [скан] mode=заделать holes=все smooth=1 simplify=0.35
```

Что внутри:

1. **Заделка дыр**: находим граничные рёбра (ребро, у которого один
   треугольник), собираем их в замкнутые петли, каждую петлю зашиваем
   веером от центра (для невыпуклых — триангуляция в плоскости петли через
   `triangulate_2d`, которая уже есть).
2. **Мелкий мусор**: `decompose`, выкинуть компоненты меньше 0.1 % объёма.
3. **Сглаживание**: лапласиан 2–3 прохода (тот же код, что в `fuse`).
4. **Упрощение**: `simplify` до целевого числа треугольников.
5. **Проверка**: `check` — герметичность, род, объём.

Без этого скан нельзя ни резать, ни печатать. Стоимость: 1–3 с на 100 тыс.
трис.

## Что осознанно НЕ делаем геометрией

* **Мех и трава целиком** — это текстура и шейдер; геометрией делаем только
  силуэт (20–60 клоков по краю).
* **Ткань с настоящей физикой складок** (симуляция) — вне ядра: ядро
  параметрическое. Складки задаём функцией (`wrinkle`), а не считаем.
* **Тканый рисунок (ситец)** — `texture` + карта высот, не решётка из нитей.
* **Настоящее преломление в стекле для PNG** — только смешивание; преломление
  остаётся в окне (three.js) и в Blender.
