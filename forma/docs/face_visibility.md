# Наружность / внутренность отдельных граней

Режим «грани» хранит **геометрические требования к выбранным треугольникам**.
Он не меняет материал, не является художественной кистью, не проверяет
направление normals и не означает видимость из текущей камеры.

## Значение цветов

| Цвет | Требование к каждому отмеченному треугольнику |
|---|---|
| **Синий** (`outside`) | Целиком находиться снаружи всех других видимых тел и не пересекать/касаться их оболочек. |
| **Красный** (`inside`) | Целиком и строго находиться внутри хотя бы одного другого видимого замкнутого тела. Контакт с его оболочкой не допускается. |
| **Серый** | Требования нет; грань не участвует в этой проверке. |

«Снаружи» здесь — геометрическое положение относительно других тел, а не
утверждение, что грань видна из произвольного ракурса. Скрытые объекты и их
соседи не используются как доказательство видимой сцены: размеченные грани
скрытого объекта пропускаются с предупреждением, а явный `check` не проходит.

## Работа в интерфейсе

1. Постройте модель и нажмите **«грани»** над viewer.
2. Выберите объект в панели. Оставьте «соседние тела прозрачные» включённым,
   если нужный корень полностью скрыт внутри головы или другого тела.
3. ЛКМ выбирает треугольник, **Shift** добавляет, **Ctrl/Cmd** снимает его из
   выделения. Белый контур показывает текущий выбор.
4. Нажмите **«снаружи»**, **«строго внутри»** или **«обычные»**. Delete на
   выделенных гранях также возвращает серый статус; Escape выходит из режима.
5. После автоматической пересборки читайте счётчик и список нарушений. Кнопка
   нарушения выбирает конкретную грань на модели; «проверить» повторяет build.

Цвета диагностические и не проходят через PBR/NPR, поэтому синий, красный и
серый не искажаются стилем. Playback продолжается при выборе и разметке.
На узком экране панель остаётся в пределах viewport и прокручивается отдельно.

## Сохранение в Forma

UI записывает компактную команду полной замены разметки объекта:

```forma
голова = box size=[80,80,80]
корень = box size=[20,20,20] at=[0,0,30]
корень = полигоны inside=[0,1,2,3]
check корень наружность
```

Это только иллюстрация синтаксиса: для настоящего корня выберите **все** его
грани, которые обязаны быть скрыты, а не копируйте индексы из примера. Если у
всего корня красный статус, любой торчащий, пересекающий или касающийся
оболочки треугольник даст нарушение. Полностью скрытый корень даёт ноль.

Допустимы positional/assignment-формы и псевдонимы:

```forma
полигоны "корень" outside=[0,4] inside=[8,9]
корень = полигоны снаружи=[0,4] внутри=[8,9] серые=[10]
```

`outside`, `inside` и `neutral` не должны пересекаться. Команда заменяет
прежнюю разметку объекта; неуказанные индексы серые. UI не выписывает серые
индексы. Пустая команда `корень = полигоны` снимает все требования. Номер вне
текущей сетки — ошибка, а не молчаливый перенос на другую грань.

Индексы относятся к **экспортному порядку треугольников**, который также
использует picking в three.js. После изменения топологии (remesh, boolean,
simplify и т. п.) выберите грани заново: смысл старых номеров у новой сетки
может измениться. Обычный rebuild той же геометрии сохраняет разметку и
выполняет проверку снова. GLB остаётся обычной геометрией; диагностические
цвета не заменяют экспортируемый материал.

## Что именно проверяет ядро

Для каждой отмеченной грани ядро сначала ищет контакт **всего треугольника**
с оболочкой другого тела, включая неcoplanar- и coplanar-пересечения. Только
если контакта нет, parity-ray по внутренней точке классифицирует всю грань.
Поэтому частично торчащий треугольник не получает ложный «inside» из-за
центра, оказавшегося в материале контейнера. Незамкнутая оболочка не может
доказать strict inside и даёт понятное нарушение, а не фиктивный успех.

Расчёт запускается только при наличии разметки. Итог доступен в интерфейсе,
в `analysis.face_visibility` (подробности и `violation_list`) и в
`analysis.metrics.face_visibility` (короткие счётчики). Автоматические
замечания появляются и без явной проверки. Строка:

```forma
check корень наружность
```

добавляет обычную контрольную проверку объекта. Она не проходит при нарушениях,
при скрытом объекте и при полном отсутствии разметки. Это отдельное правило;
`check … normals`, `check … сетка` и художественная раскраска не заменяют его.
