# База примитивов ФОРМА 3D: инвентаризация, пробелы, приоритеты

Проверка «все ли формы собраны» по факту реестра: **227 команд, из них 122 —
примитивы**. Ниже — что покрыто, чего нет, что не нужно делать примитивом, и
что добавить в первую очередь.

Разбор вопросов к этому отчёту (эскиз и кривые, виды пружин, семейства,
«зачем математика», шпонка, орнамент) и список исправлений —
[`sketch_and_families.md`](sketch_and_families.md). Схемы:
[`img/sketch_curve_why.svg`](img/sketch_curve_why.svg),
[`img/families_vs_count.svg`](img/families_vs_count.svg).

---

## 0. Короткий ответ

1. База **не «неполная» — она несимметричная**: сильно развиты механические
   детали и декор, почти пусто в природе, лаборатории, игрушках, тканях, одежде,
   электрике и строительных конструкциях.
2. **Фундаментальный пробел один**: нет эскиза с дугами и сплайнами. Профиль для
   `extrude`/`sweep` задаётся только списком точек; полигона, дуги, безье и
   ограничений нет. Это влияет на все области сразу.
3. **Второй фундаментальный**: мир «стандартных» элементов отсутствует —
   подшипники, шпонки, ремни, рейки, звёздочки, фитинги, сортамент
   (двутавр/швеллер/уголок). Их нельзя собрать «из кубиков»: размеры берутся из
   таблицы стандарта, а не из формы.
4. Восемь существующих примитивов **мелкие по вариантам**: шестерня только
   прямозубая, пружина только сжатия, `bolt` только с шестигранной головкой,
   `profile2020` только один профиль.
5. Тридцать форм **не надо** делать примитивами: они собираются за 2–6 операций
   (ведро, кружка, чайник, стул, тумба). Для них нужны рецепты и проверки, а не
   новые команды.
6. Добавлять 250 новых команд нельзя: это убьёт выбор ИИ. Нужны **семейства**:
   один примитив с параметром `variant` вместо пяти.
7. Приоритеты: P0 — эскиз, подшипник, сортамент, фитинги, ремень/рейка/звёздочка;
   P1 — крепёж-мелочь, рельеф/природа, ткани, тара, электрика; P2 — остальное.
8. Мерило: набор из 100 типовых объектов по 12 областям; задача считается
   покрытой, если решается ≤ 3 командами без ручной подгонки.
9. Сейчас примеров 21, и они почти все из четырёх областей (быт, механика,
   транспорт, человек). Природа, стройка, одежда, лаборатория — ноль.
10. Главный риск расширения — не количество, а **дубли и перекрытия**
    (`скоба`/`sheet`/`strip` уже наполовину швеллер и уголок).

## 1. Методика

Что сделано:

1. Выгружен реестр `forma.ops.OPS` — 227 записей с категориями, алиасами и
   описаниями.
2. Все 122 примитива разложены по 10 доменам по назначению (одна команда может
   относиться к двум — классификация по основной роли).
3. Составлен список кандидатов из ~330 стандартных форм по 20 областям и
   сверен с реестром **по точным именам и алиасам** (ложные совпадения
   отброшены вручную: `key` → `keyframe`, `brow` → `banana`, `sand` → `polish`,
   `polygon` → `refine`).
4. Проверена **глубина** 10 существующих примитивов (варианты внутри команды).
5. Сверены внешние стандарты: сортамент (ГОСТ 8239-89, 8240, 8509-93, 8510-86),
   крепёж и подшипники (ISO 4762, ISO 4032, ISO 15).

Оговорки: классификация по домену условная; «нет» означает «нет отдельной
команды», а не «нельзя собрать».

## 2. Как устроена база: четыре слоя

| Слой | Что это | Чем покрыт | Граница слоя |
|---|---|---|---|
| 1. Параметрические примитивы | 122 команды | box…knot | одна команда = одно тело с числами |
| 2. Профиль + операция | контур, который ведут | `extrude`, `lathe`, `sweep`, `loft`, `pipe` | профиль задаётся **только точками** |
| 3. Скалярные поля | SDF и метаболы | `blob`, `from_sdf`, `human`, `skeleton_original` | дорого, но бесконечная форма |
| 4. Композиция | булевы, посадки, массивы | `union`, `difference`, `fuse`, `weld`, `place`, `array`, `scatter` | требует, чтобы детали уже были |

**Вывод:** «все формы» недостижимы, и это нормально. Слой 2 и 4 закрывают
бесконечное семейство. Примитив нужен там, где композиция дорога или где форма
определяется стандартом. Отсюда критерий (§5).

## 4. Чего делать примитивом НЕ надо (и почему это важно)

Каждая новая команда — это ещё один вариант для выбора ИИ. Прежде чем добавлять,
проверяем: собирается ли за ≤ 6 операций.

| Форма | Сборка сейчас | Операций | Решение |
|---|---|---|---|
| ведро | `lathe` + `handle`/`sweep` | 2–3 | рецепт |
| кружка | `lathe` ×2 + `difference` + `sweep` + `union` | 5 | рецепт (есть пример) |
| чайник | `lathe` + `sweep` ×2 + `bore` | 5 | рецепт |
| стул | `box`/`sheet` ×2 + `sweep` ×4 + `fillet` | 7 | рецепт или P2 |
| тумба | `box` ×5 + `fillet` + `hinge` | 8 | рецепт |
| песочница-купол | `hemisphere` + `shell` | 2 | есть |
| ваза | `lathe` | 1 | есть |
| кузов | `loft` | 1–2 | есть |
| кабель | `sweep` по пути | 1 | **не нужен** (`rope` уже есть) |
| полигон | `prism sides=n` | 1 | **не нужен** |
| клин | `tri_prism` / `sector` | 1 | **не нужен** |
| тарелка/миска | `plate` / `hemisphere` | 1 | есть |

Правило: сюда попадают все формы с **нестандартными** пропорциями. Как только
пропорции становятся стандартными (стул по ГОСТ, ящик по модулю 400/500/600),
форма переезжает в примитивы.

## 5. Критерий «делать примитивом» и правило семейств

Примитив оправдан, если выполнены **минимум два** условия:

1. **Стандарт.** Размеры берутся из таблицы (подшипник 6204: 20×47×14), а не
   придумываются. Пользователь не должен помнить числа.
2. **Дорогая сборка.** Типичная композиция > 6 операций.
3. **Частота.** Встречается в задачах чаще ~5 %.
4. **Проверяемость.** Есть что проверять числом (посадка, зазор, число зубьев,
   межосевое расстояние).

Правило семейств: **один примитив с `variant`, а не пять команд**.

```
gear variant=прямозубая|косозубая|шевронная|внутренняя|коническая
spring variant=сжатия|кручения|тарельчатая|волновая|листовая
bolt variant=шестигранник|внутр.шестигранник|потайной|фланцевый
```

Это даёт глубину без взрыва выбора. Пример уже есть: `скоба` с
`shape=прямоугольная|овал` и `open=вверх|вниз`.

Цена в промпте (замер по `instruction.py`): описание команды в реестре ≈ 107
токенов, строка в полном каталоге ≈ 367 токенов, одно значение `variant` ≈ 20.
Полный каталог сейчас ≈ 83 тыс. токенов, инструкция целиком ≈ 88.6 тыс. —
поэтому +26 команд (+9.5 тыс.) дешевле, чем +60 узких команд, и дороже, чем
+60 вариантов (+1.2 тыс.). Подробнее — `sketch_and_families.md` §3–4.

## 6. Пробелы по областям — крупный список

Формат: **чего нет** → зачем → минимальный набор параметров → чем заменить
сейчас. P0/P1/P2 — приоритет.

### 6.1 Эскиз, кривые, 2D — фундамент (P0)

Нет ни одного 2D-примитива: профиль везде задаётся списком точек. Кривая сама
толщины не имеет — толщину даёт операция (`extrude`/`lathe`/`sweep`/`loft`),
которая этот контур замыкает и вытягивает; кривая заменяет сотни чисел, которыми
сейчас описывают ту же форму (разбор: `sketch_and_families.md` §1).

| Чего нет | Зачем | Параметры | Сейчас |
|---|---|---|---|
| `sketch` с линиями, дугами, окружностями, сплайнами | любой «нестандартный» контур: кронштейн, лопатка, логотип-контур | `points`, `segments=[{line|arc|spline}]`, `closed` | список точек + `fillet` |
| ограничения эскиза (совпадение, касание, равенство, параллельность) | редактируемость: меняешь один размер — перестраивается всё | `constraints=[...]` | вручную пересчитывать точки |
| `offset2d`, `fillet2d`, `chamfer2d` | контур под сварку, канавка под уплотнение | `delta`, `radius` | `offset` — деформация поверхности 3D, не контура |
| булевы в 2D (пересечение профилей) | вырезы, окна, профили из пересечения | `intersect`, `union2d` | `extrude` + `difference` |
| проекция 3D → 2D | развёртки, шаблоны для лазера | `project` (вид сверху/спереди в контур) | `section` есть (DXF/SVG по плоскости), `project` нет |

Почему P0: без этого `extrude`/`sweep`/`loft` работают только с «уже
посчитанными» точками, то есть каждая новая форма требует ручной арифметики
(именно так собирался кронштейн в `photo_to_model.md`).

### 6.2 Крепёж (P1, но часть P0)

Есть: `bolt`, `nut`, `washer`, `screw` (саморез), `nail`, `thread`, `bore`.

| Чего нет | Зачем | Параметры | Сейчас |
|---|---|---|---|
| машинный винт с цилиндрической головкой (ISO 4762) | 90 % машиностроения | `d`, `length`, `s`, `head_h` | **частично**: `screw drive=шестигранник` даёт слепой карман, но только на потайной/полукруглой/наружно-шестигранной головке и с острым концом самореза; тупого конца и цилиндрической головки нет |
| винт потайной (ISO 10642), полупотайной | утопленные крепления | `d`, `length`, `head` | **частично**: `screw head=потай` есть, но винт остроконечный |
| винт с крестовым шлицем (ISO 7045) | бытовая техника | `drive=ph|pz` | `screw drive=крест` есть (как саморез) |
| болт с фланцем, полукруглой головкой, квадратным подголовком | машиностроение | `head=variant` | `bolt` — только наружный шестигранник (head — это высота, не форма) |
| шпилька, резьбовая шпилька | фланцы, сборка насквозь | `d`, `length` | `thread` |
| гайка с нейлоновой вставкой, корончатая, фланцевая | вибростойкость, шплинт | `d`, `type` | `nut` |
| заклёпка (вытяжная, резьбовая) | листовые соединения | `d`, `grip`, `type` | нет |
| штифт, шплинт, шпонка (DIN 6885) | фиксация от проворота | `d`, `length`, `type` | нет |
| стопорное кольцо (circlip) | подшипниковые узлы | `d`, `shaft|bore` | нет |
| термовтулка, дюбель, анкер | пластик и бетон | `d`, `length` | нет |
| хомут, стяжка, крюк-карабин, талреп | крепление труб и тросов | `d`, `length` | `крюк` есть |
| валик сварного шва | показать шов на чертеже и в рендере | `path`, `leg`, `convex` | `weld` — булева, шва не даёт |

### 6.4 Подшипники и линейные пары (P0)

Есть: ничего. `bushing` нет, `bearing` нет.

| Чего нет | Зачем | Параметры |
|---|---|---|
| шарикоподшипник 60xx/62xx (ISO 15) | любой вал в корпусе | `d`, `D`, `B`, `shield` |
| роликовый, игольчатый, упорный | нагрузки | `type`, `d`, `D` |

габариты нельзя выдумывать — они стандартные.

## 10. Как мерить покрытие (и не спорить вкусами)

Предлагается набор из 100 объектов: по 8–10 на область (12 областей), каждый
описан одной фразой, как его назвал бы пользователь.

Метрика на объект:

* **покрыт** — собрано ≤ 3 командами, все проверки проходят;
* **частично** — 4–8 команд или ручная подгонка координат;
* **не покрыт** — нужна ручная геометрия или отсутствующая команда.

Цель: 70 % «покрыт» на P0-областях (быт, механика, стройка, узлы с валом) и
40 % на остальных. Такой набор одновременно служит eval для ИИ (см. пробел
«нет оценки качества ИИ» из прошлого разбора).

## 11. Риски расширения

1. **Перегруз выбора.** 227 → 400 команд ухудшат выбор ИИ. Лечение: семейства с
   `variant`, категории, справочник «что выбрать» (`RECIPES.md` уже начат).
2. **Дубли.** `скоба` и `sheet` уже наполовину швеллер и уголок. Прежде чем
   добавлять `channel`, надо решить: это отдельная команда или
   `скоба shape=швеллер`?
3. **Стоимость поддержки.** Каждая команда — тесты, документация, алиасы,
   обработка ошибок. 26 новых команд ≈ 26 × (тест + пример + строка в справке).
4. **Ложное чувство полноты.** Примитив не заменяет проверку: ведро из `lathe`
   всё равно надо проверять на стенку и герметичность.
5. **Стандарты устаревают.** ГОСТ/ISO таблицы нужно хранить данными, а не
   кодом, чтобы обновлять без релиза.

## 13. Итог в трёх строках

* База сильна там, где форма — **деталь машины или знак**; слаба там, где форма —
  **среда, тело, ткань или стандартное изделие**.
* Самый дешёвый крупный шаг — **эскиз с дугами и сплайнами**: он снимает
  ограничение со всех четырёх слоёв сразу.
* Самый ценный по смыслу — **стандартные изделия** (подшипник, сортамент,
  фитинги, ремень/рейка/звёздочка): их нельзя «собрать из кубиков», и именно их
  чаще всего просят.
