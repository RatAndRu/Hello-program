# Улучшение правил: пересечения деталей, свободный ход, автоотчёт

Патч к `forma` добавляет три вещи, которых не хватало при сборке механизмов
(ножницы, дверца, петля, рычаг):

1. **правило `collision`** — «эта деталь во что-то влезла?» с точным объёмом;
2. **правило `motion`** — «деталь поворачивается на заданный угол или
   заклинивает, и на каком градусе»;
3. **автоматическое предупреждение о пересечениях** в `analyze` — без того,
   чтобы об этом просили командой.

Всё считается на `manifold3d`, то есть теми же булевыми операциями, что и
сама геометрия. Никаких новых зависимостей.

Мотив. В покое сборка из двух подвижных деталей может быть «чистой»:
замкнутой, без тонких стенок, без нависаний — и при этом не двигаться, потому
что детали врезались друг в друга. Раньше это выяснялось только командой
`interference`, то есть если автор сцены вспомнил её вызвать. Теперь это
видно по умолчанию.

---

## 1. Как это считается

`manifold3d` — библиотека булевых операций над замкнутыми телами. Каждое тело
в `forma` — это `Manifold`: набор треугольников, который гарантированно
замкнут (нет дыр, нет самопересечений). Отсюда три операции, на которых стоит
патч:

| Операция | Код | Смысл |
|---|---|---|
| Объединение | `a + b` | сумма тел |
| Разность | `a - b` | вычитание |
| Пересечение | `a ^ b` | **общий объём** — именно он нужен для проверки |
| Объём | `abs(x.volume())` | мм³, точно |
| Поворот | `mf.Manifold.rotate(x, [0, 0, deg])` | поза для проверки хода |

Порядок проверки пересечений:

```
для каждой пары деталей:
    AABB не пересекаются         → пара пропускается (0,01 мс)
    AABB пересекаются            → точный объём (a ^ b), 0,1–3 мс
    объём ≤ допуска              → не дефект
    объём > допуска и > доли     → дефект с числом
```

AABB (габаритная коробка) — только быстрый фильтр: у половины нормальных
сборок коробки пересекаются (деталь в пазу, ручка над столом), а тела — нет.
Вердикт всегда по объёму.

## 2. Что именно добавлено

### 2.1. `forma/collide.py` — одна математика на всех

Раньше логика пар жила внутри команды `interference`. Теперь она вынесена в
модуль и используется тремя местами, чтобы числа не расходились:

```python
scan_pairs(solids, tolerance=0.01, allow=None,
           skip_parts=True, share=0.0)   -> (pairs, stats)

overlap_pairs(...)                        -> pairs          # удобная обёртка
pair_volume(a, b)                         -> float          # объём пересечения
root("нож.лезвие")                        -> "нож"          # корень сборки
```

`skip_parts=True` — детали одной сборки (`корпус.дно`, `корпус.стенка`) не
считаются дефектом: они касаются друг друга по построению. `allow` — маски
разрешённых пар, как в `interference`. `share` — относительный порог (доля
меньшей детали), чтобы не ловить шум сетки.

Команда `interference` переведена на этот модуль; её отчёт не изменился
(`objects`, `candidates`, `pairs`, `count`, `allowed`, `skipped_parts`,
`truncated`, `tolerance`) — это закреплено регрессионным тестом.

### 2.2. Правило `collision`

```
check нож collision                    # допуск 0.01 мм³
check нож collision 1                  # прощаем шум до 1 мм³
check нож collision allow="втулка:вал"
check нож collision share=0.01         # только если больше 1 % меньшей детали
```

Ответ:

```
пересечения: нет — при допуске 0.01 мм³
пересечение с «armB»: 1 980 мм³ — при допуске 0.01 мм³
```

В результат попадает `actual` (худший объём) и `pairs` (все пары, до 5) —
машиночитаемо, без разбора текста.

### 2.3. Правило `motion`

```
check лезвие ход axis=z до=90 step=5
check дверца ход ось=z центр=[0,0,0] до=110 допуск=1
```

Крутим деталь шагом `step` до угла `до`, в каждом положении считаем точный
объём пересечения с остальными деталями. Первое положение, где объём выше
допуска, — заклинивание.

```
ход: свободно до 90° (ось z, 18 положений, шаг 5°)
ход: заклинивает на 15° — «armA», пересечение 166.9 мм³ (допуск 0.5)
```

В результат добавляются `blocked_at`, `blocked_by`, `blocked_mm3`. Ограничения
(с понятной ошибкой, а не таймаутом): не больше 72 положений и не больше 12
деталей в сцене.

### 2.4. Автоматическое предупреждение в `analyze`

```python
if gparts > 1 and 1 < len(visible) <= 24:
    pairs = overlap_pairs(visible, tolerance=1.0, share=0.005, limit=3)
    for pair in pairs:
        warnings.append(
            f"Детали пересекаются: «{a}» ↔ «{b}» — {V} мм³. "
            f"Объедините (`union`) или разрешите пару "
            f"(`interference allow=\"{a}:{b}\"`).")
```

Порог двойной: абсолютный 1 мм³ (шум сетки) **и** 0,5 % объёма меньшей
детали. Детали одной сборки пропускаются, объединённые (`union`) тела — тем
более: у них просто нет пары.

## 3. Замеры

| Проверка | Было | Стало |
|---|---|---|
| Ножницы, плечи в разных слоях (правильно) | 2 предупреждения, пересечения не видны | 2 предупреждения, `collision` — «нет», `ход` — свободно до 90° |
| Ножницы, плечи в одном слое (дефект) | 2 предупреждения, дефект **не виден** | предупреждение «Детали пересекаются: 1 980 мм³», `collision` — провал, `ход` — заклинивает на 5° |
| Два куба 10³ со сдвигом 5 мм | объём только через `interference` | предупреждение «500 мм³» и `check a collision` → ровно **500 мм³** (сверено с ядром) |
| 10 типовых сцен (кронштейн, стакан, шестерня, шайба, коробка, болт, ваза, держатель, ручка, кубик) | — | **0 ложных срабатываний** на новое предупреждение |
| Время проверки пересечений, 2 детали без касания | — | 0,01 мс |
| Время проверки хода, 18 положений | — | 9 мс |
| Анализ сцены целиком (2 детали) | 12–14 мс | 14,5 мс |
| Полный набор тестов | 1237 (336 с) | 1265 (326 с), 16 новых тестов идут 0,2 с |

Ложные срабатывания важнее пропусков: после пятой тревоги на нормальной
детали предупреждения перестают читать. Поэтому порог относительный и
настраиваемый, а `allow`/`union` снимают пару.

## 4. Тесты

`tests/test_rules_upgrade.py` — 16 тестов, три группы:

* **правило `collision`**: чистая сборка молчит; пересечение ловится и
  показывает объём; допуск прощает шум; `allow` снимает пару; объём совпадает
  с ядром (500 мм³);
* **правило `motion`**: свободный ход до 90°; заклинивание сообщает угол,
  деталь и объём; неверная ось и слишком мелкий шаг объясняются по-русски;
* **автоотчёт и регрессия**: предупреждение появляется без команды; чистая
  сборка молчит; `union` не дефект; детали одной сборки пропускаются; отчёт
  `interference` сохранил поля и объёмы.

Прогон:

```bash
cd forma
python -m pytest -q tests/test_rules_upgrade.py      # 16 passed, 0.2 с
python -m pytest -q                                  # 1265 passed, 5 м 25 с
```

## 5. Как перенести в другую ветку

Патч лежит рядом с репозиторием: `forma-rules-upgrade.patch` (в рабочей
папке, вне git). Он содержит один коммит: код, тесты и этот документ.

```bash
# в клоне своей ветки
git am --3way forma-rules-upgrade.patch     # сохранит авторство и сообщение

# если ветка разошлась и am ругается на контекст
git apply --3way forma-rules-upgrade.patch
git add -A && git commit -m "правила: пересечения деталей и свободный ход"

# проверить, что применилось
cd forma && python -m pytest -q tests/test_rules_upgrade.py
```

Файлы патча:

| Файл | Что делает | Строк |
|---|---|---|
| `forma/collide.py` | **новый**: единая математика пересечений | ~150 |
| `forma/checks.py` | правила `collision` и `motion`, алиасы, метки | +230 |
| `forma/metrics.py` | автоматическое предупреждение в `analyze` | +20 |
| `forma/ops_interior.py` | `interference` переведён на общий модуль | −40 |
| `tests/test_rules_upgrade.py` | **новый**: 16 тестов | ~200 |
| `forma/docs/rules_upgrade.md` | этот документ | — |

Зависимостей нет: только `manifold3d`, который уже есть. Совместимость: новые
правила добавляются в `RULES`, существующие 25 не меняются; отчёт
`interference` не меняется; новые предупреждения появляются только при
`parts > 1`.

## 6. Ворота приёмки

Патч считается принятым, если:

1. `pytest -q` — 1265+ зелёных, 0 падений (включая 16 новых);
2. на 10 типовых сценах из §3 новое предупреждение не появляется ни разу;
3. на сцене с заведомым пересечением оно появляется ровно одно, с объёмом;
4. `check <деталь> collision` на двух кубах 10³ со сдвигом 5 мм даёт 500 ± 1 мм³;
5. `check <деталь> ход` на правильной сборке отвечает «свободно до 90°» и
   укладывается в 20 мс;
6. анализ сцены из 2–3 деталей не медленнее 30 мс.

## 7. Чего в патче нет

Честный список, чтобы не ждать лишнего:

* **профили технологии** (FDM 2,4 мм / SLA 0,8 / лист / зазор 0,2) — пороги
  всё ещё зашиты; это следующая правка, и она меняет поведение существующих
  предупреждений, поэтому требует отдельной калибровки;
* **роли деталей** (`роль=лезвие`, `роль=ось`) — без них нельзя проверить
  «правильность ножниц», только их собираемость;
* **автопочинка** — предупреждение пока только советует `union`/`interference`,
  но не возвращает готовую команду;
* **гейт экспорта** — блокировка выгрузки при дефектах описана в
  `topology_automation.md`, но в коде её нет: в `ops_io.py` нет проверки
  предупреждений перед `export`;
* **шум метрики стенки** — на торе выдаёт «минимум 0,11 мм» при реальной
  трубке 15 мм; это артефакт сэмплирования (36 точек, `consistency=0.5`), и
  его надо чинить отдельно, а не поднимать порог.

Оценка по этим четырём пунктам — от половины дня (гейт экспорта) до недели
(роли и калибровка профилей). Ни один из них не требует обучения сети.
