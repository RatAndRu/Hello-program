# Пересечения деталей и свободный ход

Добавлены три связанных механизма:

1. `check деталь collision` — утверждение об отсутствии значимых пересечений;
2. `check деталь ход` — дискретная проверка поворота с первым столкновением;
3. автоматическое предупреждение `Детали пересекаются` в `analyze`.

Общая математика находится в `forma/collide.py`. Команда `interference`, правила
и автоматический анализ используют один broad/narrow phase и одинаковые маски
разрешённых пар. Новых зависимостей нет: используется уже подключённый
`manifold3d`.

## Что именно означает «точный объём»

Для двух `Manifold` вычисляется `a ^ b`, затем `abs(intersection.volume())`.
Единица сцены — мм, поэтому объём — мм³. AABB проверяется только до булева:
пересечённые габаритные коробки сами по себе не являются дефектом. Касание
поверхностей имеет нулевой объём и не считается пересечением.

`NoError`/замкнутость отдельного тела не заменяет эту проверку: это статус
топологии тела, а не доказательство отсутствия столкновений между разными
объектами, правильного зазора или работоспособности механизма.

## `collision`

```forma
check нож collision
check нож collision 1
check нож collision tolerance=0.01 share=0.005
check нож collision allow="нож:втулка"
check нож collision against=[рамка, вал]
```

- Позиционный аргумент и `tolerance`/`допуск` задают абсолютный порог в мм³;
  значение по умолчанию — `0.01`.
- `share`/`доля` — дополнительный порог как доля объёма меньшей детали, от 0 до
  1. Например, `share=0.005` означает 0,5 %. Пара отклоняется только если она
  прошла оба порога.
- `allow`/`разрешено` принимает пары `a:b,c:d` и маски `*` в любом порядке.
  Опечатка без разделителя является ошибкой, а не молчаливым разрешением.
- `against`/`препятствия` ограничивает проверку указанными объектами или
  группами. Без него берутся остальные видимые тела.
- Пары с общим корнем имени (`корпус.дно` и `корпус.стенка`) по умолчанию
  пропускаются как внутрисборочные контакты; `parts=да` включает их проверку.

В результате есть `actual`, `pairs` (до пяти пар выбранной детали), `ok` и
человекочитаемый текст. Для этого булева правила `actual` всегда равен нулю:
объёмы нужно читать из каждой записи `pairs[].volume_mm3`, а не из одного
«худшего» скаляра. В тексте перечисляются все возвращённые пары. Фильтр по
детали выполняется **до** ограничения числа пар, поэтому большие чужие
пересечения не могут скрыть её дефект.

## `ход`

```forma
check лезвие ход axis=z до=90 step=5
check дверца ход ось=[0,0,1] центр=[0,0,0] до=-110 допуск=1
check рычаг ход axis=[1,1,1] до=120 step=10 against=[упор]
```

`axis`/`ось` принимает `x`, `y`, `z` или вектор. Вектор нормируется общим
преобразованием `forma.ops.rotate`, то есть это настоящий axis-angle поворот,
а не три независимых Euler XYZ угла. `pivot`/`центр`/`точка` задаёт центр
поворота в мм. Угол `до` может быть отрицательным; `step` всегда положительный.

Проверяются исходная поза и sampled-положения с заданным шагом. Последняя поза
всегда имеет ровно угол `до`, даже если он не делится на шаг. Поэтому при
`до=18 step=5` проверяются 5, 10, 15 и 18°, а не 20°. Не больше 72 moving-поз
и 12 препятствий на одну проверку; `against` позволяет сузить сборку.

При столкновении результат содержит:

- `blocked_at` — угол первой sampled-позы, где есть дефект; `0` означает
  исходную позу;
- `blocked_by` — список всех деталей, пересекающих движущуюся в этой позе;
- `blocked_mm3` — список точных объёмов в том же порядке;
- `blocked_pairs` — полные записи этих пар, `blocked_pair` — первая (наибольшая)
  запись для совместимости с одиночным потребителем;
- `positions_checked` — число проверенных поз, включая исходную.

При успехе `actual` равен запрошенному конечному углу, а `blocked_at` равен
`null`. Текст перечисляет все пары первой проблемной позы и намеренно говорит
«свободно в проверенных положениях»: между
шагами столкновение может быть пропущено. Для более плотного контроля уменьшите
`step`; это не полноценный continuous collision detection, динамика, расчёт
сил или автоматическое доказательство работоспособности механизма.

## Автоматическое предупреждение и разрешённые пары

При 2–24 видимых объектах `analyze` ищет пары с объёмом больше 1 мм³ и не
меньше 0,5 % объёма меньшей детали. В предупреждение попадают до трёх пар;
полный список доступен через `interference`.

```forma
interference allow="дверца:упор,вал:втулка"
```

`allow` в этой команде сохраняется в `Scene.collision_allow`. Поэтому совет в
предупреждении действительно работает: при повторном анализе разрешённая пара
не сигналит снова. На уже сформированный отчёт `interference` влияют только его
собственные аргументы — старые поля и независимость отчётов сохранены.

`union` убирает исходные объекты из списка видимых, поэтому объединённое тело не
считается «двумя пересекающимися деталями». Это не разрешение скрывать дефект:
при необходимости проверяйте детали до объединения или используйте `parts=да`.

## Регрессионные проверки

`tests/test_rules_upgrade.py` содержит минимальные сцены для:

- кубов 10³ со сдвигом 5 мм — ровно 500 мм³;
- касания, допуска, масок allow и внутрисборочных имён;
- фильтрации target до limit;
- исходного столкновения (`blocked_at=0`) и столкновения на промежуточном угле;
- отрицательного угла, произвольной оси и неделимого конечного угла;
- автоматического предупреждения и сохранения полей старого отчёта.

```bash
cd forma
python -m pytest -q tests/test_rules_upgrade.py
python -m pytest -q tests/test_v052.py tests/test_stage3_origami.py tests/test_v033.py
```

Проверки не утверждают нулевое число ложных срабатываний на всех возможных
сценах и не задают универсальный временной бюджет: это зависит от сложности
тел и числа AABB-кандидатов. Полный регресс выполняется отдельно в CI.
