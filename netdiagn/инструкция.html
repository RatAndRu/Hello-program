NET DOCTOR · инструкция

Телефон не видит мои Python-серверы:
как найти причину за 10 минут

Ситуация: на ноутбуке свой сервер открывается по http://192.168.0.60:5000/, а с телефона в той же Wi-Fi — нет. Ниже — как запустить диагностику, как читать результат и что делать на каждом шаге.

1Если коротко

1Запустите инструмент

Двойной клик по start_netdoctor.bat в папке netdiagn.
Окно должно остаться открытым — не закрывайте его.

2Откройте адрес с телефона

На экране появятся адреса и QR-код. Наведите камеру телефона на QR — откроется тестовая страница. Появилась страница — канал жив.

3Прочитайте «где провал»

В конце — таблица из 8 этапов и вердикт с процентами: что именно виновато. Отчёт сохранится в netdoctor_report.txt.

🐍 Python-сервер→ 💻 ноутбук (адрес + брандмауэр)→ 📶 Wi-Fi / роутер→ 📱 телефон

2Как запустить

Самый простой способ (Windows): откройте папку netdiagn и дважды щёлкните по start_netdoctor.bat. Скрипт сам найдёт Python и всё сделает.

Вручную (если хочется задать ключи):

:: проверить свой сервер на порту 5000 и указать адрес телефона
python net_doctor.py --check-port 5000 --phone 192.168.0.61

:: подготовить починку (создаст netdoctor_fix.ps1, он сам попросит права)
python net_doctor.py --fix

:: только проверки, без тестового сервера
python net_doctor.py --no-server

Что произойдёт: инструмент соберёт конфигурацию Windows, проверит сеть и брандмауэр, поднимет тестовый сервер на порту 8770 и будет ждать запрос с телефона (по умолчанию 2 минуты). Затем напечатает вердикт.

Ничего в системе не меняется. Файлы-починка создаются только с ключом --fix.

3Что вы увидите и как это читать

Инструмент проходит ровно ту же цепочку, что и ваш телефон, и отмечает каждый этап значком ✔ (ок), ! (внимание) или ✖ (проблема). В конце — таблица:

#ЭтапЕсли ✖ или ! — что это значит и что делать
1Сеть ноутбука (получены адреса) Адрес вида 169.254.* — ноутбук не получил IP от роутера. «Забудьте» Wi-Fi на ноутбуке и подключитесь заново; перезагрузите роутер.
2Профиль сети (Public / Private) «Общедоступный» (Public) — Windows режет входящие подключения. Это причина №1 после поездок. Лечение: --fix (переведёт в Private) или вручную: Параметры → Сеть и Интернет → Wi-Fi → свойства сети → «Частная».
3Брандмауэр (входящие) Если включено «Блокировать все входящие подключения» — не помогают даже разрешающие правила. Снимите галочку в «Брандмауэр Защитника Windows» → «Дополнительные параметры» (wf.msc) → Свойства.
4Разрешение для python.exe Когда Python впервые слушает порт, Windows спрашивает «Разрешить доступ?». Если когда-то нажали «Отмена» (или правило было только для Private, а сеть стала Public) — входящие молча блокируются. Лечение: --fix.
5Порт свободен и слушается Порт занят другим процессом (двойной запуск, остался старый сервер). Посмотрите, кто: python net_doctor.py --check-port 5000.
6Ответ по 127.0.0.1 Даже локально нет ответа — проблема в самом приложении (ошибка в коде, не тот порт), а не в сети.
7Ответ по 192.168.x.x (с ноутбука) Ноутбук не отвечает сам себе по своему сетевому адресу: адрес/адаптер в порядке? При 169.254.* телефон его всё равно не найдёт.
8Запрос с другого устройства Если запрос не пришёл — обрыв на участке «телефон → роутер → ноутбук». Смотрите топ-5 причин ниже (WARP/VPN, профиль сети, брандмауэр, гостевая сеть/изоляция клиентов).

Как понять, что всё хорошо: откройте тестовую страницу с телефона. Если она открылась — в журнале появится строка 📱 запрос … [ДРУГОЕ УСТРОЙСТВО], а вердикт скажет: «канал “телефон → ноутбук” работает». Значит дело в вашем приложении — почти всегда в том, что оно слушает только 127.0.0.1.

4Топ-5 причин именно «после отпуска»

1. Остатки Cloudflare WARP (1.1.1.1) или другого VPN

WARP любят включать в поездке. Даже если «VPN выключен», WARP оставляет службу, виртуальный адаптер и локальный прокси 127.0.0.1:40000. Особенность WARP: на самом ноутбуке всё открывается, а входящие из локальной сети не доходят — ровно ваши симптомы.

Как проверить: инструмент отдельной строкой «Cloudflare WARP / VPN». Вручную:
• трей (правый нижний угол) → значок Cloudflare → выход;
• ncpa.cpl → есть ли адаптер «Cloudflare WARP»;
• services.msc → служба CloudflareWARP.

Что делать: выключить/выйти из WARP, а лучше — «Забыть сеть» в клиенте и перезагрузиться. Если WARP больше не нужен — удалить приложение. Тест: остановить службу и сразу проверить с телефона.

2. Сеть снова помечена как «Общедоступная» (Public)

Когда вы подключились к чужому Wi-Fi (в отеле), Windows пометила профиль как Public. При возвращении домой профиль может остаться «общедоступным» — и тогда входящие режутся.

Лечение: Параметры → Сеть и Интернет → Wi-Fi → свойства сети → «Частная». Или просто: python net_doctor.py --fix.

3. Нет правила брандмауэра для Python

Правило могло быть создано только для профиля Private, а сейчас сеть Public — тогда оно не работает. Или вы когда-то отказались от окна «Разрешить доступ?».

Лечение: --fix добавит входящее TCP-правило только для локальной подсети. Откат — netdoctor_undo.ps1.

4. Приложение слушает только 127.0.0.1

Тогда его видит только сам ноутбук — и по 127.0.0.1 всё прекрасно, а по 192.168… с телефона нет. В коде должно быть:

# Flask
app.run(host="0.0.0.0", port=5000)

# стандартная библиотека
from http.server import HTTPServer
HTTPServer(("0.0.0.0", 5000), Handler).serve_forever()

Инструмент покажет это в строке «Адрес прослушивания» и подскажет порты.

5. Роутер: гостевая сеть или изоляция клиентов

Если телефон подключён к «гостевому» SSID или на роутере включена изоляция клиентов (AP isolation), устройства физически не видят друг друга, даже находясь «в одной сети».

Как проверить: сравните SSID и первые три числа IP на телефоне и ноутбуке (например, 192.168.0. и там, и там). В настройках роутера отключите «Guest network» / «AP isolation» / «Изоляция клиентов».

5Проверки вручную (если хочется своими глазами)

Кто слушает порт и на каком адресе (ищите 0.0.0.0:5000 — хорошо, 127.0.0.1:5000 — плохо):

netstat -ano | findstr :5000

Профиль сети:

powershell -NoProfile -Command "Get-NetConnectionProfile | Format-Table InterfaceAlias, NetworkCategory"

Состояние брандмауэра по профилям:

netsh advfirewall show allprofiles

Правила для Python:

powershell -NoProfile -Command "Get-NetFirewallRule -DisplayName '*python*' |
  Select-Object DisplayName, Enabled, Direction, Action, Profile"

Видит ли ноутбук телефон (ARP/ping):

ping 192.168.0.61
arp -a | findstr 192.168.0.

Проверка «в лоб» на 1 минуту (потом обязательно вернуть!):

netsh advfirewall set allprofiles state off   :: выключить
:: ... проверьте с телефона ...
netsh advfirewall set allprofiles state on    :: включить обратно

6Почему на ноутбуке открывается, а с телефона — нет?

Когда ноутбук обращается сам к себе по 192.168.0.60, трафик не выходит в сеть — он идёт «внутри» системы, и его не проверяет фильтр входящих подключений. А запрос с телефона приходит извне — и проходит через брандмауэр, профиль сети, VPN-адаптеры и роутер. Поэтому «у меня всё открывается» ничего не говорит о доступности с телефона. Именно этот зазор и закрывает NET DOCTOR.

7Безопасность

Инструмент не открывает ваш сервер в интернет. Правило брандмауэра создаётся только для локальной подсети (-RemoteAddress LocalSubnet) — это значит «домашние устройства» (телефон, планшет, второй ноутбук) и ничего больше. Откат всех изменений — один файл netdoctor_undo.ps1.

Инструмент ничего не отправляет в интернет, не собирает личные данные и работает только на вашем компьютере. Отчёт netdoctor_report.txt — обычный текстовый файл, который вы можете прочитать сами, прежде чем кому-то показывать.

8Если не помогло

1. Убедитесь, что тест прошёл до конца: телефон открыл тестовую страницу, и в журнале появилась строка со словом ДРУГОЕ УСТРОЙСТВО.

2. Сохраните netdoctor_report.txt — он лежит рядом со скриптом.

3. Запустите ещё раз с адресом телефона и своим портом и пришлите отчёт:

python net_doctor.py --check-port 5000 --phone 192.168.0.61

В отчёте есть всё: адаптеры, адреса, профили, правила брандмауэра, слушающие порты, соседи в сети и список всех запросов с IP — по нему видно, где именно застряло.
