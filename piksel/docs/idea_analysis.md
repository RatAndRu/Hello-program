# Анализ идеи «Пиксель как универсальный примитив»

Дата: 2026-11-07  
Автор: Arena Agent + RatAndRu  
Статус: оценка + план для приложения ПИКСЕЛЬ

---

## 1. Формулировка твоей идеи своими словами

> Любое изображение — это пиксели. Пиксель-арт — это когда пиксели крупные и видны. Обычный растр — просто более плотная сетка тех же пикселей. Монитор — тоже микропиксели. Значит, нейросеть может:
> 1) по текстовому сценарию **или по координатам** сгенерировать грубый пиксельный рисунок (например 32×32);
> 2) потом «уплотнить» сетку (×2, ×4, ×8 …) и детализировать каждый крупный пиксель в множество мелких, получив аниме-арт или живопись, но сохранив композицию.

Дополнительно: анимация = последовательность таких «уплотнений» во времени.

## 2. Свежесть идеи — честно

### Что НЕ ново
- «Всё есть пиксели» — базовая компьютерная графика с 70-х.
- Генерация пиксель-арта нейросетью — есть: **Pixel Art Diffusion, Pix2Pix, Stable Diffusion с промптом `pixel art`**, репозитории `pixel-art-generator` на Hugging Face.
- Super-resolution — индустрия с 2017: ESRGAN, Real-ESRGAN, SwinIR, Stable Diffusion x4 Upscaler.
- ControlNet Tile / IP-Adapter для сохранения композиции при апскейле — стандартный приём с 2023.

Если подать патент «генерировать пиксели, потом увеличивать» — не пройдёт.

### Что ДЕЙСТВИТЕЛЬНО свежо и ценно
1. **Пиксель как редактируемый семантический чертёж.**  
   Обычно делают наоборот: HD → пиксель (пикселизация). Ты предлагаешь инвертировать: *сначала* грубый ручной/нейросетевой «чертёж» из крупных色-клеток, где каждая клетка — это объект («кожа», «небо», «меч»), а потом HD — это детализация *внутри* клетки. Это аналог `contour2d → extrude` в ФОРМЕ, только для 2D. Удобно для контроля: пользователь правит 5 пикселей, а не перерисовывает 4K.

2. **Координаты как язык.**  
   «Банально по координатам» — это DSL вида:
   ```
   пиксель x=4 y=9 цвет=#ff4d4d
   линия x=2..10 y=5 цвет=#3a86ff
   заливка x=0..31 y=0..31 цвет=небо палитра=16
   промпт "девочка с катаной, закат" стиль=аниме
   детализация x2 стиль=аниме шум=0.35
   ```
   Такого узконаправленного «пиксельного языка» в открытом доступе почти нет. ФОРМА доказала, что люди любят команды-строки.

3. **Анимация через пиксельный Tween.**  
   Идея: ключевые кадры — это 32×32, а нейросеть интерполирует между ними уже на HD. Это дешевле и стабильнее, чем гонять AnimateDiff на 512×512. Похоже на `living_room_diorama` + `animation_tracks.forma`, но для спрайтов.

**Итог по свежести: 6.5/10 как технология, 8.5/10 как продукт/UX.**  
Техника известна, но связка «координатный редактор + пиксель-чертёж + контролируемое уплотнение» — свободная ниша. Делать стоит, позиционируя как *инструмент контроля*, а не как «ещё один генератор картинок».

## 3. Надёжность — где сломается, а где нет

### Надёжно (можно обещать пользователю)
| Этап | Почему надёжно |
|---|---|
| **Текст → пиксель 32×32/64×64** | Модели `pixel-art-XL`, `SDXL + prompt: pixel art, 32x32, limited palette` дают стабильный результат. Можно зафиксировать палитру (NES, GameBoy, 16 цветов) и получить предсказуемость. |
| **Ручной пиксель-редактор** | Чистый Canvas2D, без нейросети — 100% надёжность. Координатная запись — детерминирована. |
| **Пиксель → ×2 nearest-neighbor** | Детерминированный алгоритм, без AI. |
| **Экспорт PNG/GIF/APNG/ASE** | Отлажено, как в ФОРМЕ экспорт GLB. |
| **Офлайн-работа редактора** | Как ФОРМА: локальный сервер, всё работает без интернета. |

### Умеренно надёжно (нужны хитрости)
| Этап | Риск | Митигация |
|---|---|---|
| **Пиксель → HD ×4 с детализацией** | Нейросеть может «забыть» палитру и композицию, начать галлюцинировать новые объекты. | ControlNet Tile (0.55–0.75), IP-Adapter для стиля, фиксация seed, prompt с `retain composition, pixel art as structure`. Вес `denoise 0.35–0.55`. |
| **Временная консистентность анимации** | Персонаж «плывёт» между кадрами: лицо меняется, одежда прыгает. | Использовать один и тот же seed + LoRA персонажа, + AnimateDiff / RIFE для интерполяции. Ключевые кадры — пиксельные, HD — генерировать пакетом. |
| **Подбор палитры** | AI любит добавлять 100500 оттенков, ломая пиксель-стиль. | Квантование после генерации (Median Cut), проверка `check палитра <=32` как в ФОРМЕ `check` |
| **Производительность локально** | SDXL ×4 на CPU — минуты, на слабом GPU — тоже долго. | Дать переключатель «быстро/качество»: быстрый = Real-ESRGAN (без diffusion), качество = SD upscale. |

### Ненадёжно (не обещать в v1.0)
- «Любой стиль одной кнопкой» — аниме, масло, акварель требуют разных LoRA/промптов. В v1 делаем 3–4 проверенных пресета.
- «Идеальная анатомия на HD из 16×16» — нейросеть додумает руки/пальцы криво. Нужна ручная правка пикселей (как в ФОРМЕ `note` + `cut`).
- «4K 60fps анимация на ноутбуке» — только через облако или с ожиданием.

**Итог по надёжности: 7/10 для статики, 5/10 для анимации.**  
Запускать как: *надёжный пиксель-редактор + экспериментальная HD-детализация* (честно писать «бета»).

## 4. Три варианта реализации

### Вариант A — Web-first на Fly.io (рекомендую первым)

**Архитектура:** твой `fly.toml` уже настроен на `forma3d-ratandru`. Делаем второе приложение `piksel-ratandru` по тому же `forma/showcase/Dockerfile` (Python slim → Nginx).

- Frontend: `piksel/web/` — статика, как `forma/showcase/static/` (без Python в runtime).
- Backend выносим в serverless: **Replicate** (`fofr/pixel-art-xl`, `stability-ai/sdxl`), **Hugging Face Inference** (бесплатно до лимита), или **Stability API** (токен кладём в `FLY_API_TOKEN` аналог).
- Локально ничего не грузит GPU. Платишь только за вызовы API ($0.001–0.01 за картинку).

Плюсы: за неделю до первого деплоя, Fly уже оплачен, HTTPS из коробки, не нужен EXE.  
Минусы: зависимость от внешнего API, без интернета не работает HD.  
Кому: показать друзьям, собрать фидбек.

### Вариант B — Desktop PC (как ФОРМА 3D)

**Архитектура:** копия ФОРМЫ 1-в-1:

```
piksel/server.py  ← форк forma/forma/webui.py (тот же TOKEN, то же user_data_dir)
piksel/web/       ← форк forma/web/ (тот же app.css, panels.js, viewer.js → canvas.js)
piksel/packaging/piksel.spec ← тот же PyInstaller без scipy/skimage
```

- Локальная SD через `diffusers` + `ONNX` или `ComfyUI` в фоне (как у ФОРМЫ `forma/blender.py` запускает Blender).
- Требует 8+ ГБ VRAM для комфорта, но работает офлайн. Папки `projects/`, `exports/frames/`, `palettes/` рядом с exe — как `forma-data/`.

Плюсы: офлайн, приватность, полный контроль, раздаёшь ZIP как ФОРМУ.  
Минусы: тяжёлый EXE, нужен GPU или ждать на CPU.  
Кому: художники, которым важна приватность.

### Вариант C — Гибрид (идеал на 2–3 месяца)

Объединить A+B: один и тот же frontend (`piksel/web`) умеет переключать бэкенд:

```js
if (settings.backend === 'local')  call('/api/local/upscale')
else call('https://api.replicate.com/...')
```

- Код `server.py` уже содержит оба пути: если `LOCAL_SD=1` — грузит diffusers, иначе — проксирует на облако.
- Пользователь выбирает в настройках: «Быстро (облако)» / «Приватно (локально)» / «Эконом (Real-ESRGAN)».

Это повторяет философию ФОРМЫ: локальный редактор + статический showcase. Только здесь showcase — это галерея пиксель→HD.

**Моя рекомендация порядка:**
1. **Неделя 1–2:** вариант A (web, Replicate/HF) + ручной пиксель-редактор. Выкати на Fly, дай ссылку — уже можно пользоваться.
2. **Неделя 3–4:** добавь `server.py` и `piksel.spec` → собери первый `Пиксель.exe.zip` (как `Forma3D.exe`).
3. **Месяц 2:** гибрид + анимация (таймлайн как в ФОРМЕ 0.71).

## 5. Что именно взять из оформления ФОРМЫ 3D

Мы уже частично перенесли, но зафиксируем чек-лист для разработчика:

**Обязательно:**
- [ ] `app.css` — переменные `--bg`, `--panel`, `--line`, `--text`, `--accent` (сменить accent на пиксель-оранжевый)
- [ ] Topbar с лого «П» и кнопками `▶`, `↶`, `↷`, `🕘` (история)
- [ ] 3 колонки с `panels.js` (редактор | холст | отчёт), сворачивание
- [ ] Gutter + `code` textarea + `error-bar` + `cursor-pos` + `script-stats`
- [ ] История `history-panel` (откат к любому шагу)
- [ ] Экспорт-меню `menu-wrap` с форматами PNG/GIF/WebM/ASE/ZIP
- [ ] `webui.py` → `server.py`: token, `serve_in_thread`, `user_data_dir()`, `/api/build`, `/api/state`, `/api/export`
- [ ] Папки рядом с exe + `paths.py` + `describe()`
- [ ] `version.py` + `__version__` + бейдж `ОНЛАЙН-ДЕМО` когда `FLY_DEMO=1`

**Желательно (из 0.70–0.72):**
- [ ] `face_visibility` → выбор пикселей кистью (синие = снаружи, красные = внутри объекта)
- [ ] `check` система: `check холст размер 32x32`, `check палитра 16`, `check кадр fps 12`
- [ ] `section`/`probe` → `slice` пиксельной области для проверки
- [ ] `animate` клипы + scrub + `preview3d` → `previewHD`
- [ ] `tools-modal` с карточками примитивов: линии, заливки, градиенты, палитры NES/GB
- [ ] `tex-modal` → палитра-редактор с пресетом
- [ ] `render` 4 вида → 4 масштаба ×1 ×2 ×4 ×8 в PNG

**Не брать:**
- `manifold3d`/`trimesh` (3D-ядро) — заменить на `Pillow` + `numpy` + `opencv` для пикселей
- `sdf`, `origami`, `contour2d` — не нужны для 2D

## 6. Технический скетч пайплайна

```
[Промпт / координаты] 
   → (A) Пиксель-генератор 32×32 (SD-pixel / ручной холст)
   → (B) Квантование палитры (опционально, 4/16/32 цвета)
   → (C) Апскейл ×2 nearest-neighbor (детерминирован)
   → (D) Детализация HD (ControlNet Tile + IP-Adapter, denoise 0.4)
       ↕ можно повторить ×2 → ×4 → ×8
   → (E) Пост-обработка: шарп, удаление артефактов, квантование обратно если нужно
   → Экспорт PNG/WebM/GIF
```

Для анимации:
```
Кадр1 32×32 ─┐
Кадр2 32×32 ─┤→ RIFE/AnimateDiff интерполяция → HD кадры → WebM
Кадр3 32×32 ─┘
```

## 7. Риски и как их честно показать пользователю

- Не обещать «один клик — шедевр». Показывать сравнение: слева пиксель, справа HD, слайдер «сила детализации».
- Добавить `checks` как в ФОРМЕ: если палитра >32 — жёлтое предупреждение, если размер не степень 2 — подсказка.
- Логировать каждый шаг в `actions[]` — как ФОРМА делает отчёт для нейросети.
