# Сценарий для пиксельного редактора — каким он должен быть?

> Заказ: простой редактор (графически легче ФОРМЫ), но со сценарием который любая нейросеть может написать, пользователь копирует и получает картинку.

Дата: 2026-11-07

---

## 1. Почему с пикселями не как с 3D

В ФОРМЕ 3D всё строится из примитивов: `cylinder`, `cube`, `lathe`, `sweep`. Каждый примитив — замкнутый объём, ядро `manifold3d` делает булевы операции. Нейросеть учится комбинировать 10–20 команд и получает сложную модель.

С пикселями иначе. Художники почти не мыслят примитивами «нарисовать круг радиусом 7». Они ставят пиксели поштучно, потому что на 32×32 круг из примитива выглядит «слишком идеально» и не в стиле. Пиксель-арт — это ручной контроль каждого квадрата: антиалиасинг делается вручную, палитра — 4–16 цветов, дизеринг — точками.

Но это не значит что примитивы бесполезны. Они нужны как **сокращение** для нейросети: вместо 1024 строк `пиксель x,y цвет` можно написать `прямоугольник 5,5-20,12 #306230 заливка` — и это развернётся в пиксели. А для финальных штрихов останется точечная правка.

Поэтому наш DSL должен поддерживать **оба уровня**: высокоуровневый (заливка, линия, прямоугольник) и низкоуровневый (пиксель).

## 2. Что уже придумано в мире

| Формат / Идея | Как выглядит | Плюсы / Минусы для LLM |
|---|---|---|
| **PICO-8 spritesheet** (Lexaloffle) | 128×128 лист из 8×8 спрайтов, хранится как hex `0x112233` + Lua-код. 16 цветов фиксированы. [3](https://huggingface.co/datasets/Fraser/pico-8-games) | + Очень компактный, + LLM видела много PICO-8 кода. − Нужен инструмент для разбора, не читаемый глазами |
| **Aseprite .ase / .json + CLI** — `pixel-plugin` для Claude, 18 инструментов `pixelart_draw {op:line, x,y}` [2](https://skillsllm.com/skill/pixel-plugin) + `dsh-cli-anything-aseprite` с `pixelart_new/draw/line/rect` [4](https://awesome-dsh-plugin.com/p/KongChengZhi/dsh-pixel-studio--dsh-cli-anything-aseprite/) | JSON-команды: `{op:"rect", x:10, y:7, w:12, h:7, color:"#1d2b53"}` | + Ближе всего к ФОРМЕ: команда = объект. + Понятно LLM. − Нужен рантайм Aseprite |
| **CSS box-shadow пиксель-арт** | Один `<div>` + `box-shadow: 1px 0 #f00, 2px 0 #0f0...` | + Одна строка, + видно в браузере. − Нечитаемо, 1000 теней = огромный CSS |
| **XPM / ASCII matrix** | `/* XPM */` + строки `"..##.."`, `"..11.."` | + LLM обучалась на ASCII-арте, + компактно (≈1 токен на 4 пикселя). − Нет семантики, только индексы |
| **RLE / Run-Length** | `row 5: 3*., 2*#, 5*.` или `заливка 0,0-31,31 #000` | + Супер-компактно для больших заливок. − Хуже для органики |
| **VQ-VAE токены** (VQGAN, MAGVIT) [1](https://ijcai.org/proceedings/2025/167) + Pixel VQ-VAE [4](https://www.exag.org/papers/Pixel%20VQ-VAEs%20for%20Improved%20Pixel%20Art%20Representation.pdf) | Картинка → дискретные токены `1024 884 12...` → декодер | + Лучшая компрессия, + LLM нативно понимает токены. − Не читаемо человеком, требует обученного токенайзера |
| **Base64 PNG** | `data:image/png;base64,iVBOR...` | + Точная передача. − LLM не умеет генерировать валидный base64, токены огромные |
| **Sorceress Quick Sprites + True Pixel** [5](https://sorceress.games/blog/drop-in-an-ai-pixel-sprite-generator-no-aseprite) | Промпт → HD спрайт → квантование в палитру GameBoy/PICO-8/NES | + Кнопка «промпт → пиксель». − Нет редактируемого сценария |

Вывод: для **копипаст-сценария** нужны читаемые команды, как в ФОРМЕ, но адаптированные под пиксельную сетку.

## 3. Три кандидата на наш DSL

### Вариант A — «Только пиксели» (координата + цвет)

Самый прямой:

```
размер 32
палитра #0f380f #306230 #8bac0f #9bbc0f
пиксель 14,14 #8bac0f
пиксель 15,14 #9bbc0f
пиксель 16,15 #306230
...
```

*Плюсы:* 100% контроль, просто парсить, как `cylinder radius=...` в ФОРМЕ — одна строка = один факт.
*Минусы:* **токен-ад**. 32×32 без фона = ~400 строк. 64×64 = 2000 строк. LLM часто «съезжает» на 300-й строке — теряет координаты. Человеку тоже неудобно читать.

*Когда использовать:* только как **внутренний экспорт** (кнопка «Скопировать как пиксели»), не как основной язык для LLM.

---

### Вариант B — «Матрица + палитра» (ASCII)

Самый LLM-дружелюбный — LLM видела ASCII-арт миллионы раз:

```
размер 16
палитра 0:#0f380f 1:#306230 2:#8bac0f 3:#9bbc0f
# цвета по индексам, 0=фон можно как .
карта:
................
.....111........
....12221.......
...122221.......
....11111.......
................
```

Или с символами:

```
карта:
..##..
.####.
##..##
```

*Плюсы:* 16×16 = 16 строк, 32×32 = 32 строки. Токенов в 5–8 раз меньше чем вариант A. LLM не путает координаты — строки уже позиционированы. Легко визуально проверить.
*Минусы:* Нет семантики — нельзя сказать «это герой, это фон». Правка одного пикселя = править строку целиком. Палитра ограничена цифрами/буквами (до 36 цветов без костылей).

*Когда использовать:* для **иконок, спрайтов 8×8 — 32×32**, где важна форма, а не слои.

---

### Вариант C — «Области» (заливка + прямо + линия + пиксель-оверрайд) — **рекомендую**

Гибрид: высокоуровневые заливки как в ФОРМЕ, но **привязанные к пиксельной сетке** (snap). То, что ты называешь «примитивы» — здесь они **не гладкие круги, а пиксельные** (ступеньками):

```
размер 32
палитра gameboy   # алиас на 4 цвета GameBoy
фон #0f380f

# высокоуровневое — как в ФОРМЕ, но 2D и с пиксельным снапом
заливка 0,0-31,11 #9bbc0f        # небо — прямоугольник
прямо 5,12-26,20 #306230 заливка # земля
линия 8,12-24,12 #0f380f 2       # горизонт толщиной 2px
круг 16,16 r=6 #8bac0f заливка контур=#0f380f  # пиксель-круг ступеньками

# точечная правка поверх
пиксель 14,14 #0f380f
пиксель 15,14 #0f380f

# мета для HD — не рисует пиксели, а подсказывает нейросети
промпт "девочка с катаной, закат" стиль=аниме
детализация x4 сила=0.40
check палитра <=4
```

*Плюсы:*
- LLM может выбрать уровень абстракции: лениво — 3 строки `заливка/прямо`, точно — 20 `пиксель`.
- Токенов мало: большой фон — одна строка вместо 1024.
- Читаемо и редактируемо: видишь «земля», меняешь её цвет одной строкой.
- Легко расширять: `дизеринг 5,12-26,20 #0f380f #306230 шахматы`, `контур 1px`, `тень 1,1`.
- Прямая аналогия ФОРМЕ: `заливка/прямо/круг/линия` ≡ `cube/cylinder/sphere` в 3D, только с `snap=пиксель`.

*Минусы:* нужен парсер который развернёт примитивы в пиксели (просто — Bresenham для линии, midpoint для круга, fill rect — циклы).

**Это наш базовый выбор.** Он покрывает 90% пиксель-артов и при этом позволяет «дописать пикселями».

---

### Бонус — «Семантика» для персонажей (надстройка над C)

Для анимации — описываем объекты, а не просто заливки:

```
объект герой 16x16 at 8,8 палитра=pico8
  слой тело: прямо 4,6-12,14 #ff004d заливка
  слой глаза: пиксель 6,7 #fff; пиксель 9,7 #fff
анимация герой: кадр idle [0,0,1,0] fps=4
```

Это уже ближе к `human = biped(...)` в ФОРМЕ. Делаем позже, когда статика готова.

## 4. Рекомендуемый синтаксис (v0.1) — уже можно копипастить

```
# заголовок
размер 32                    # квадрат; или размер 32x24
палитра #0f380f #306230 #8bac0f #9bbc0f   # или палитра gameboy / pico8 / sweet16
фон #0f380f                  # сахар для заливка 0,0-31,31

# 2D-примитивы с пиксельным снапом (координаты — целые пиксели, 0,0 — левый верх)
заливка 0,0-31,11 #9bbc0f
прямо 5,12-26,20 #306230 заливка          # заливка=залит, без — только контур
прямо 5,12-26,20 #0f380f                  # контур поверх
линия 8,12-24,12 #0f380f 2
круг 16,16 r=6 #8bac0f заливка контур=#0f380f
поли 5,5 10,2 15,5 12,10 8,10 #ff004d заливка  # пиксель-полигон

# точечные правки (поверх примитивов, порядок важен)
пиксель 14,14 #0f380f
пиксель 15,14 #0f380f

# проверки — как check в ФОРМЕ
check размер 32
check палитра <=4
check заливка <80%           # не больше 80% заливки (для читаемости)

# подсказки для HD (не влияют на пиксель-рендер)
промпт "девочка с катаной, закат, ветер" стиль=аниме
детализация x4 сила=0.42 палитра=сохранить
```

**Парсинг:** сверху вниз, каждый примитив рисует в буфер `размер×размер`. `пиксель` перезаписывает. `фон` — первый слой. Это детерминировано, как `build()` в ФОРМЕ.

**Экспорт:** внутренне храним массив `size*size` цветов + список команд. При «Сохранить» — пишем исходные команды (не развёрнутые пиксели), поэтому файл остаётся коротким и редактируемым.

## 5. Как из пикселя в растр (HD)

Твоя идея «плотная сетка = детализация» реализуется в 3 шага — уже заложил в прототип как `силу детализации`:

```
[Пиксель 32×32] → (1) nearest ×N → [HD 128×128 пиксельный] → (2) Diffusion с контролем → [HD 128×128 детализированный]
```

1. **Детерминированный апскейл** `×2/×4/×8` nearest-neighbor — без AI, сохраняет каждый крупный пиксель как блок. Это «скелет».
2. **Палитра-лок** (опционально): если `палитра=сохранить` — после AI квантуем обратно в исходную палитру (как True Pixel [5]), если `палитра=свободно` — даём AI добавить оттенки.
3. **Диффузия с контролем** — ключевой шаг:
   - Вход: апскейленный пиксель как `control image` для `ControlNet Tile` (вес 0.55–0.75). Tile специально обучен сохранять структуру при апскейле.
   - Промпт: `промпт + ", retain pixel art composition, detailed, {стиль}"`
   - Параметры: `denoise 0.35–0.55` (сила). 0.35 = почти пиксель, 0.55 = уже живопись. `IP-Adapter` держит стиль.
   - На сайте: вызов `replicate/sdxl-controlnet-tile` или `huggingface/sd-x4-upscaler`. Локально: `diffusers + controlnet`.

*Почему это надёжно:* Tile-ControlNet тренирован именно на «сохрани композицию, добавь детали» — он не придумает новый объект, пока вес Tile высокий. Если снизить силу — получим «фантазию», но это уже выбор пользователя (слайдер силы).

*Анимация (позже):* та же схема покадрово, но с одним `seed` + `AnimateDiff` для интерполяции между HD-кадрами. Пиксельные ключевые кадры — лёгкие, HD — тяжёлые, поэтому экономим.

## 6. Что берём из ФОРМЫ 3D технически

Не графику, а **архитектуру**:

- `server.py` как `forma/webui.py`: `TOKEN` в `?token=`, `user_data_dir()` → `piksel-data/projects/`, `/api/parse`, `/api/render`, `/api/upscale`, `/api/export` — тот же контракт, только вместо `manifold3d` — `Pillow` + `numpy`.
- `fly.toml` + `Dockerfile (Python→Nginx)` + `healthz` — как `forma/showcase`, деплой одной командой `flyctl deploy`.
- Парсер сценария — как `forma/run.py: build()` — построчно, с `error-bar` и `check`.
- История `actions[]/notes[]` — как в ФОРМЕ, только `note к пикселю x,y`.
- Сборка EXE — как `forma.spec`, но без `manifold/trimesh`, легче (~25 МБ).

Графически — наоборот упрощаем: вместо 3 панелей ФОРМЫ делаем 2: слева код (textarea + gutter), справа превью (пиксель + HD слайдер). Без 12 меню, без 3D-вьювера.

## 7. Следующий шаг — сайт

Сайт уже как `piksel/web/index.html` (прототип на https://8000-...e2b.app) — переделаю под этот DSL:

- Верх: `размер | палитра | [Собрать]`
- Лево: редактор сценария (как в ФОРМЕ, но проще) — с подсветкой `заливка/прямо/пиксель`
- Право: два канваса — сверху пиксель 1:1, снизу HD ×4 с ползунком силы
- Низ: `check` и `Журнал` + кнопка «Скопировать отчёт для нейросети» (как в ФОРМЕ)

Нейросеть пишет:

```
размер 32
палитра pico8
заливка 0,0-31,31 #000
прямо 10,8-22,20 #ff004d заливка
пиксель 13,12 #fff
пиксель 18,12 #fff
детализация x4 сила=0.4 стиль=аниме
```

Пользователь вставляет → жмёт `Собрать` → видит пиксель → жмёт `Детализировать` → получает HD (сначала mock, потом реальный вызов Replicate).

Если ок — скажи, фиксируем вариант C (области + пиксели) и я обновлю сайт под него + подключу первый реальный апскейл на Fly.io.
