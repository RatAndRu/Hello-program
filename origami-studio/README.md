# Origami Studio

Отдельное специализированное приложение для пошаговых инструкций оригами и планирования модульных сборок.

## Что реально работает

### Журавлик из одного листа

- 10 учебных шагов интерфейса, содержащих 12 точных операций движка;
- 13 ключевых состояний и рассчитанные промежуточные состояния операций;
- **одна связанная поверхность**, а не отдельно смоделированные крылья, тело и шея;
- каждая грань хранит исходный полигон на квадратной развёртке;
- 144 грани в финальном состоянии;
- фактическая карта граней и складок, а не приблизительный декоративный рисунок;
- 3D-просмотр, схемы шагов, проигрывание, перемотка и скорость;
- экспорт листа PNG, печать/PDF и видео WebM.

Геометрия и последовательность рассчитаны ядром **Origamio, Hannes Gao, MIT**: <https://github.com/hannesgao/Origamio>. Исходный revision интеграции: `c28937855e8d4b08cd10c83b66689f3e94b924b2`. Лицензия и используемые TypeScript-файлы сохранены в `tools/origamio/`.

`data/crane.validation.json` содержит отчёт для каждой операции:

- разорванных соседних граней: **0**;
- исходная площадь: **1**, сохраняется на всех шагах;
- максимальная относительная ошибка длины ребра: **0,221%**;
- число граней и максимальное число слоёв.

Это строгая проверка топологии и геометрических ограничений выбранного движка, но не гарантия поведения любой реальной бумаги. Между рассчитанными кадрами выполняется интерполяция; трение, усталость и прочность материала не моделируются.

### Модульный планировщик Golden Venture

- выбор числа модулей и рядов;
- размеры исходных прямоугольников;
- шаг по кольцу и автоматический радиус;
- прямая/перевёрнутая ориентация и смещение на ½ модуля;
- список деталей, площадь бумаги, таблица сборки;
- SVG-схема позиций и экспорт плана JSON.

Планировщик отвечает на вопрос **«какие детали и в каком порядке разместить»**. Он не утверждает, что складка модуля, вставка выступов и прочность конструкции уже подтверждены. Это явно написано в его интерфейсе и в поле `verification` экспортируемого JSON. Остальные семейства в библиотеке пока являются справкой и не выдаются за готовые конструкторы.

## Запуск

Нужен Node.js 18+ для приложения; генерация геометрии использует установленный dev-пакет `tsx`.

```bash
npm run dev
# http://localhost:3000
```

Проверки:

```bash
npm test
npm run check
```

Повторная генерация связанной геометрии:

```bash
npm install
npm run generate:crane
```

## Структура

- `index.html`, `styles.css`, `planner.css` — интерфейс и печать;
- `js/scene.js` — рендер одной связанной поверхности и её анимация;
- `js/data.js` — русские инструкции;
- `js/diagrams.js` — векторные схемы и фактическая карта складок;
- `js/modular.js` — детерминированный модульный планировщик;
- `js/app.js` — взаимодействие и экспорт;
- `data/crane.geometry.json` — рассчитанные состояния листа;
- `data/crane.validation.json` — метрики проверки;
- `tools/export-crane.ts` — воспроизводимый генератор;
- `tools/origamio/` — интегрированное MIT-ядро и его лицензия;
- `tests/` — проверки связности, UV-развёртки, инструкций и планировщика;
- `examples/` — готовые PNG и WebM;
- `Dockerfile`, `fly.toml` — production на Fly.io;
- `../.github/workflows/deploy-origami-studio.yml` — тесты, ZIP, публикация и внешняя приёмка.

## Следующий этап для «идеального» редактора

1. Общий редактор произвольных линий сгиба и выбора слоёв, а не только готовая последовательность.
2. Проверка столкновений и доступности действий на всей непрерывной траектории.
3. Учёт толщины, жёсткости, трения и допусков конкретной бумаги.
4. Типизированные карманы/выступы и insertion solver для модульных систем.
5. Генератор рядов с прибавками/убавками и проверкой замыкающих соединений.
6. Экспорт FOLD и физическая проверка эталонных инструкций на бумаге.

Нейросеть должна выбирать шаблон и параметры после этих проверок, а не заменять геометрическое ядро.
