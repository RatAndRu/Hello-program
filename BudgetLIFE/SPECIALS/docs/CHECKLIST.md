# Чек-лист нового проекта (для человека и для нейросети)

Коротко: **создать через `new_project.py` → заполнить паспорт → проверить по списку.**

```bash
python SPECIALS/tools/new_project.py "Моё Приложение" [--port-base 5130]
cd "Моё Приложение"
python -m pip install -r requirements.txt
start_debug.bat            # первый запуск: видно ошибки
start.vbs                  # обычный запуск
python ../SPECIALS/tools/check_ports.py   # конфликтов быть не должно
```

---

## A. Каркас (обязательное)

- [ ] `app.py` — единственная точка входа; всё остальное импортируется.
- [ ] `start.vbs` — тихий запуск; `stop.vbs` — остановка только своего процесса.
- [ ] `start_debug.bat` — запуск с консолью и `pause` (окно не исчезает).
- [ ] `requirements.txt` — `flask`, `pystray`, `pillow`, `psutil` (+ опциональные закомментированы).
- [ ] `readme.txt` — как запустить, где данные, что делать при проблемах.
- [ ] Папки: `data/`, `static/`, `templates/`, `logs/` (+ `.gitkeep` в пустых).
- [ ] `appcore/` скопирован в проект (проект самодостаточен).
- [ ] В `data/` попадают **только** изменяемые файлы; код в `data/` не читается.

## B. Паспорт приложения

- [ ] `APP_ID` — уникальный, латиницей, без пробелов (он же в `ports.json`).
- [ ] `APP_NAME` — человеческое имя (трей, диспетчер задач, автозапуск).
- [ ] `APP_VERSION` — версия; при выпуске меняется в одном месте.
- [ ] `APP_LETTER` — буква для иконки.
- [ ] `HOST` — `127.0.0.1` по умолчанию; `0.0.0.0` только если нужен телефон.
- [ ] `HOT_RELOAD` / `MEMORY_LIMIT_MB` — заданы явно.

## C. Запуск и порты

- [ ] Порт берётся из своего блока: `ports.candidates(APP_ID)`.
- [ ] В проекте есть свой `ports.json` (его создаёт `new_project.py`) — иначе блок
      берётся «по хэшу» из зоны 5200+ и не совпадает с реестром.
- [ ] Сервер поднимается синхронно: `flask_integration.serve_with_fallback(...)`
      (никаких `app.run()` в отдельном потоке без обработки `OSError`).
- [ ] Порт записан в `data/port.txt` (`ports.write_port_file`).
- [ ] `/api/identity` и `/api/health` подключены (`flask_integration.install`).
- [ ] Повторный запуск **не плодит процессы**, а поднимает окно существующего
      (`ports.find_running` + `windowing.focus_or_open`).
- [ ] Порт-лок и мьютекс взяты (`singleton.acquire_lock_port`, `acquire_mutex`).

## D. Windows-интеграция

- [ ] `windowing.set_app_user_model_id(...)` — имя в уведомлениях/панели задач.
- [ ] `windowing.ensure_named_interpreter(...)` — имя в диспетчере задач.
- [ ] Автозапуск: `autostart.set_autostart(APP_NAME, autostart.launcher_command(base), …)`.
- [ ] Пункт «Автозапуск» в трее с галочкой (`checked`).
- [ ] URI-протокол — только если реально нужен; схема уникальна (проверьте реестр).
- [ ] Доступ с телефона — через `firewall.ensure_rule` (profile=private, localsubnet),
      никогда не «разрешить всем».

## E. Данные

- [ ] Все JSON — через `jsonstore.JsonStore` (атомарно, `.bak`, карантин битого файла).
- [ ] БД (SQLite) — в `data/`; соединение открывается на операцию, а не глобально.
- [ ] Пользовательский текст: `ensure_ascii=False`, `encoding="utf-8"`.
- [ ] Файлы пользователя (картинки, принятое «Поделиться») — в `data/`, имя
      очищается через `Path(name).name`.
- [ ] Никаких секретов (пароли, токены) в репозитории: только в `data/`.

## F. Логи и ошибки

- [ ] `logutil.setup(APP_NAME, paths.log_file())` — ротация 1 МБ × 3.
- [ ] `logutil.log_uncaught()` — падения (в т.ч. в потоках) попадают в лог.
- [ ] В начале лога — версия, pid, путь к Python (видно, чем запущено).
- [ ] Ошибки в фоновых циклах не убивают процесс, но логируются (с ограничением частоты).
- [ ] HTML отдаётся с `no-store` (`flask_integration`).

## G. PWA

- [ ] `/manifest.json` отдаётся сервером и зависит от User-Agent (телефон/ПК).
- [ ] `/sw.js` с `Service-Worker-Allowed: /` и `Cache-Control: no-store`.
- [ ] Иконки 192/512/maskable генерируются (`pwa.ensure_icons`).
- [ ] `offline.html` — «нет связи с ПК», а не белый экран.
- [ ] Регистрация SW с `?v=<timestamp>`.
- [ ] Кнопка «Поделиться» с фолбэком на копирование.
- [ ] QR на адрес: `/api/qr` (работает и без пакета `qrcode` — свой кодировщик в
      `appcore.qr`), в трее — пункт «QR-код для телефона».
- [ ] Если нужен «Поделиться» из системы — `share_target` GET/POST по платформе
      и перехват POST в service worker (иначе Safari ломается).

## H. Трей и выход

- [ ] Трей: версия · Открыть (default) · Копировать адрес · QR · Папка данных ·
      Автозапуск · Доступ с телефона · Перезапустить · Выход.
- [ ] Уведомления (`notify`) на действия без видимого результата.
- [ ] Без `pystray` приложение работает и пишет в лог, что установить.
- [ ] «Выход»: остановить сервер → снять иконку → освободить лок → `os._exit(0)`.
- [ ] После выхода процесс исчез из диспетчера задач, порт освобождён.

## I. Разработка

- [ ] `HOT_RELOAD = True` на время разработки (сохранение файла → перезапуск).
- [ ] Memory-guard включён (растёт память — перезапуск с записью причины).
- [ ] `data/` не попадает в hot-reload (иначе цикл перезапусков от сохранения данных).

## J. Финальная проверка

- [ ] `python SPECIALS/tools/check_ports.py` — нет конфликтов и неограниченных сканеров.
- [ ] `python SPECIALS/tools/audit_windows.py` — порт «наше», автозапуск без дублей,
      `data/port.txt` без устаревших записей.
- [ ] Приложение запущено одновременно с 2-3 другими — все работают, порты разные.
- [ ] Телефон открывает страницу, PWA устанавливается, «Поделиться» доходит.
- [ ] Перезагрузка ПК: приложение подхватывается автозапуском и само открывает окно.

## K. Фишки из проектов (по желанию — но именно они делают приложение удобным)

Подробный разбор «что откуда взято» — в [PROJECTS.md](PROJECTS.md) и в
разделе 2.11 [../README.md](../README.md).

- [ ] Приложение управляет ПК (клавиши/мышь/громкость) → `appcore.keyinput`;
      доступ с телефона закрыт токеном/паролем и брандмауэром `localsubnet`.
- [ ] Есть действие «за секунду» → `appcore.hotkeys` (свой хоткей, не занятый
      другими — таблица в README §4).
- [ ] Работа с буфером → `appcore.clipboard` (номер изменения, вставка без
      затирания, фильтр мусора); буфер чужой программы не «дёргать» зря.
- [ ] Текстовые мелочи (раскладка, регистр, ссылка, HEX, числа словами) →
      `appcore.textutil`, а не свои регулярки.
- [ ] Запуск без консоли (`pythonw`) и есть что показать пользователю →
      `appcore.gui.overlay` / `gui.report` (иначе результат не виден).
- [ ] Диалоги (папка/вопрос/выбор) → `appcore.gui.ask_folder` / `ask_yes_no`
      (один Tk-root, окна не «зависают»).
- [ ] Данные в SQLite → `appcore.sqlite_store` (миграции, бэкап при старте и
      перед опасным действием, восстановление со страховочной копией).
- [ ] Приложение открывают с телефона и с ПК одновременно → `appcore.events`
      (SSE: состояние не «разъезжается», видно, сколько устройств подключено).
- [ ] «Поделиться» с телефона → просмотр приёмника и дедупликация файлов
      (`clipboard.Deduplicator`), папка `data/shared/`.
- [ ] Есть что терять (настройки, база, картинки) → бэкап архивом
      (`versioning.create_backup`) и восстановление со страховочной копией;
      в интерфейсе — кнопка «Сделать бэкап».
- [ ] Нужны команды извне (ярлык, Win+R, QR, другое приложение) → `uri.Router`
      + `/api/uri` + регистрация схемы `uri.normalize_scheme(APP_ID)`;
      второй запуск передаёт команду работающему и **не поднимает второй сервер**.
- [ ] Приложение должно «жить само» → `watchdog.ThreadWatchdog`
      (поток сервера + `/api/health`, перезапуск через `start.vbs`).
- [ ] Есть учёба/повторение (карточки, слова, техобслуживание) → `spaced`
      (SM-2), а не свой таймер «через 3 дня».
- [ ] Данные собираются в один файл для переноса → `versioning.export_json`
      / `import_json` (как в Cooker).

## Готовый промпт для нейросети

> Сделай проект «<Имя>» по стандарту SPECIALS.
> Каркас уже создан: `python SPECIALS/tools/new_project.py "<Имя>"`.
> Требования: логика в `app.py`, UI в `templates/index.html` + `static/`;
> использовать `appcore` (`ports`, `flask_integration`, `jsonstore`, `tray`,
> `autostart`, `hotreload`, `pwa`), не изобретать свои порты/трей/автозапуск.
> Фишки из проектов подключай по надобности: `textutil` (раскладка, регистр,
> калькулятор без eval, ссылки), `clipboard` (файлы, вставка без затирания),
> `keyinput` (клавиши/мышь), `gui` (оверлеи и диалоги), `hotkeys`, `sqlite_store`
> (миграции и бэкапы), `events` (живые обновления SSE). Разбор всех 14 проектов —
> `SPECIALS/docs/PROJECTS.md`.
> Порт — из своего блока (см. `SPECIALS/ports.json`), данные — через `JsonStore`,
> логи — через `logutil`, PWA — через `flask_integration.install`.
> Обязательные маршруты: `/api/identity`, `/api/health`, `/manifest.json`, `/sw.js`.
> Трей: Открыть · Копировать адрес · QR · Автозапуск · Перезапустить · Выход.
> В конце прогони `SPECIALS/tools/check_ports.py` и пройди чек-лист
> `SPECIALS/docs/CHECKLIST.md`.

## Частые ошибки, которые чек-лист ловит

| Симптом | Причина | Пункт |
|---|---|---|
| «Порт занят», приложение молчит | `app.run()` в потоке без обработки `OSError` | C |
| Два окна при двойном клике | нет проверки `/api/identity` | C |
| В диспетчере задач снова `pythonw.exe` | не создан именованный exe / нет штампа | D |
| Автозапуск перестал работать после обновления Python | в Run записан путь к pythonw.exe | D |
| Данные пропали после выключения ПК | запись JSON «в лоб» | E |
| Падение без следов (pythonw) | нет `log_uncaught` / `sys.stdout is None` | F |
| Старый интерфейс после правок | HTML/sw.js кэшируются | G/F |
| «Поделиться» пустая страница на iOS | POST не перехвачен в SW | G |
| Процесс остался после «Выхода» | `sys.exit()` вместо `os._exit()` и без остановки сервера | H |
| Телефон управляет ПК без пароля | `0.0.0.0` без токена/брандмауэра | D |
| Вставка текста затёрла буфер пользователя | Ctrl+V «в лоб», без сохранения буфера | K |
| Буфер «дёргается» каждые полторы секунды | чтение буфера без проверки номера изменения | K |
| Отчёт о работе некуда показать (нет консоли) | не используется `gui.report`/`overlay` | K |
| База «поехала» после обновления или падения | нет миграций/бэкапа `sqlite_store` | K |
| Телефон и ПК показывают разные списки | нет шины событий (`events`), интерфейс обновляется вручную | K |
