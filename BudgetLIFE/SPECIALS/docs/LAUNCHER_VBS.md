# start.vbs: разбор и золотой стандарт

Пользователь запускает приложение двойным кликом по `start.vbs`. Всё, что
происходит между кликом и появлением иконки в трее, определяет, будет приложение
работать или «тихо не запустится». Здесь — разбор всех 14 VBS-файлов репозитория
и итоговый стандарт (`SPECIALS/template/start.vbs`).

## 2. Итоговый стандарт

`start.vbs` умеет и то, и другое, и третье — в правильном порядке:

```
1. app.py рядом со скриптом?          нет → MsgBox и выход
2. чем запускать:
   а) <Имя>.exe + штамп <Имя>.launcher  →  его (имя в диспетчере задач)
   б) py -3.12-64 / -3.12 / -3.13 …     →  pythonw.exe рядом с найденным python.exe
   в) типовые пути (LOCALAPPDATA, C:\PythonXX, Program Files)
   г) where pythonw.exe
   нет → MsgBox с инструкцией + запись в logs\launch.log
3. cmd = "pythonw.exe" "app.py" <аргументы…>
4. shell.Run cmd, 0, False            (скрыто, не ждать)
5. ошибка → MsgBox с командой и текстом ошибки
6. строка в logs\launch.log           (что, когда, какой командой)
```

## 3. Почему каждая деталь важна

**Папка от самого скрипта.** `GetParentFolderName(WScript.ScriptFullName)` вместо
`C:\AI_Projects\...`: приложение запускается из любой папки, копируется на флешку,
переносится на другой диск.

**Только `pythonw.exe`.** `python.exe` открывает чёрное окно консоли, которое
пугает и мешает; приложение задумано «трей + браузер». Для отладки есть
`start_debug.bat` — он специально запускает `python.exe` и не закрывает окно.

**`py`-лаунчер (`py -3.12-64`) — первый способ поиска.** `cmd /c py … > файл`
выполняется с флагом `0` (окно скрыто), результат читается из временного файла.
Так LanguageYOI находит Python, даже когда его нет в PATH. Важно: проверяем
наличие `pythonw.exe` рядом с найденным `python.exe` — иначе консоль всё же мигнёт.

**Штамп сборки.** Именованный `exe` (копия `pythonw.exe`, см. `windowing.py`)
используется только при наличии файла `<Имя>.launcher`. Урок LanguageYOI: без
штампа можно запустить недописанную копию — она молча ничего не сделает. В
стандарте штамп пишется ПОСЛЕ успешного копирования.

**Типовые пути.** Пользователи ставят Python куда угодно: `%LOCALAPPDATA%\Programs\
Python\Python3XX`, `%LOCALAPPDATA%\Python\pythoncore-3.14-64`, `C:\Python3XX`,
`Program Files\Python3XX`. Список из Трекера — рабочий; в стандарте он шире.

**Аргументы.** `For i = 0 To WScript.Arguments.Count - 1` → каждый аргумент в
кавычках. Это нужно для URI-протоколов: `tracker://add?...` приходит как `%1` из
реестра, и Трекер передаёт команду уже запущенному приложению.

**Сообщение об ошибке.** Пустота — худший вариант: пользователь думает, что
«программа сломалась». `MsgBox` должен говорить, ЧТО нашёл скрипт и что делать.

**Лог.** `logs\launch.log` с автобрезкой: видно, что скрипт вообще запускался,
какой Python выбран и с какой командой. Первое, что нужно смотреть при «не работает».

**`Option Explicit`** — опечатка в имени переменной становится ошибкой, а не
пустым значением (иначе VBS-скрипты «мистически» не работают).

## 4. Чего в VBS не должно быть

* **Установки зависимостей** (`pip install` в момент запуска) — приложение должно
  запускаться мгновенно; установка — отдельный шаг (`install_ocr.bat` у LanguageYOI
  это делает правильно, но не из `start.vbs`).
* **Сборки exe** — если exe нет, просто запускаем `pythonw.exe` и пишем в лог.
  Запуск не должен зависеть ни от каких дополнительных шагов.
* **Ждать завершения** (`waitOnReturn = True`) — приложение долгоживущее, клик по
  ярлыку должен сразу освобождать рабочий стол.
* **`cmd /k` в релизном запуске** — окно остаётся висеть.

## 5. `stop.vbs`: останавливать только своё

Плохо: `taskkill /F /IM python.exe` или `taskkill` по порту без проверки — однажды
убьёт чужой сервер.

Хорошо (взято из `SHADOW GAME/stop_ar_servers.vbs` и развито в шаблоне):

1. читаем `data\port.txt` → порт приложения;
2. на этом порту берём PID слушателя;
3. через `Win32_Process.CommandLine` проверяем, что в командной строке есть путь
   к нашему `app.py`;
4. только тогда `Terminate`;
5. если порт неизвестен — ищем `python*-процессы` с нашим `app.py` в командной строке;
6. результат пишем в `logs\launch.log`.

Так `stop.vbs` безопасно нажимать всегда: он ничего не сделает, если приложение
не запущено, и не тронет чужие процессы.

## 6. Порядок запуска в приложении (для полноты картины)

```
start.vbs → pythonw.exe app.py
    ├── logutil.setup()                 (логи + безопасные потоки pythonw)
    ├── logutil.log_uncaught()          (падения в потоках — в лог)
    ├── windowing.set_app_user_model_id (имя в диспетчере задач)
    ├── windowing.ensure_named_interpreter (exe + штамп для start.vbs)
    ├── ports.find_running()            (уже запущено? → фокус окна → выход)
    ├── singleton.acquire_lock_port()   (защита гонки)
    ├── serve_with_fallback()           (свой блок портов, синхронный bind)
    ├── ports.write_port_file()         (data/port.txt)
    ├── tray.TrayApp(...).run()         (главный поток)
    └── hotreload.HotReloadWatcher()    (перезапуск при правках, memory-guard)
```
