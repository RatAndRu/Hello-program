# Трей, диспетчер задач, реестр, один экземпляр

Всё, что делает приложение «настоящим приложением для Windows», а не «консольным
скриптом, который где-то висит».

---

## 1. Трей

### Как в проектах

| Проект | Реализация | Особенность |
|---|---|---|
| Cooker | pystray, иконка рисуется в памяти | пункт «Автозапуск» с галочкой `checked` |
| DeployAgent | pystray + отдельный GUI-поток (Tk) | горячий перезапуск и memory-guard, «Автозапуск» в меню |
| Телепульт | pystray | пункты управления звуком/курсором |
| BLIND_PC | pystray | пункт с QR-кодом и озвучкой адреса |
| Трекер | **свой Win32-трей**: `tkinter` + `Shell_NotifyIconW` + подмена `WndProc` | полный контроль над левым/правым кликом, всплывающие «баллоны» |
| SHADOW GAME | pystray | сервер на `http.server`, меню «Открыть на ПК / По Wi-Fi» |
| LanguageYOI | pystray | уведомления `notify`, повторный запуск → фокус окна |
| DnD's | pystray + отдельный процесс сервера | «надзиратель»: если сервер упал — поднять заново |

### Стандарт

* Иконка — **в памяти** (`appcore.tray.make_icon`): нет файла `.ico` → нет ошибок
  «иконка не найдена»; Pillow опционален, при его отсутствии трей просто
  отключается с записью в лог.
* Меню — из данных (`tray.TrayItem`), обязательные пункты:
  версия (не кликается) · Открыть (левый клик) · Копировать адрес · QR-код ·
  Открыть папку данных · Автозапуск (галочка) · Доступ с телефона · Перезапустить · Выход.
* Обратная связь — `notify()`: действие без видимого результата пользователь
  считает сломанным.
* `pystray` работает **в главном потоке** (`icon.run()` блокирует), Flask — в daemon-потоке.
* Отдельное окно (Tkinter) — только через **один общий Tk-root** в своём потоке
  (Tcl/Tk не потокобезопасен; DeployAgent пришёл к этому после редких падений).
* Пункт, который не может работать, — `enabled=False` (LanguageYOI: не серая
  кнопка-загадка), а вместо него уведомление с объяснением.

### «Баллоны» (всплывающие уведомления)

`pystray` → `icon.notify(...)`. Если трей недоступен, уведомление уходит в лог.
Пример — Трекер: напоминание показывается баллоном (`show_balloon` через
`Shell_NotifyIconW(NIM_MODIFY)`).

## 2. Диспетчер задач: чтобы приложение было узнаваемо

Проблема: в диспетчере задач десять одинаковых `pythonw.exe`, и непонятно, кто есть кто.

Три приёма (все три — в `appcore.windowing`):

1. **AppUserModelID**
   ```python
   ctypes.windll.shell32.SetCurrentProcessExplicitAppUserModelID("RatAndRu.Specials.specials_demo")
   ```
   Приём LanguageYOI: без него Windows путает уведомления, закрепление на панели
   задач и подсказки трея между проектами.

2. **Копия интерпретатора с именем приложения**
   ```python
   windowing.ensure_named_interpreter(paths.base, "SpecialsDemo")   # → SpecialsDemo.exe + .launcher
   ```
   Приём DeployAgent. В диспетчере задач видно «SpecialsDemo.exe», в трее — то же
   имя. Штамп `.launcher` нужен, чтобы `start.vbs` не запустил недописанную копию
   (приём LanguageYOI).

3. **Заголовок консоли** (`SetConsoleTitleW`) — для отладочного запуска
   (`start_debug.bat`), чтобы окно консоли тоже было подписано.

Итог: приложение видно как **`Имя.exe`**, а не как `pythonw.exe`, и его не
перепутать с другими проектами.

## 3. Один экземпляр: три уровня

```
                  ┌ уже запущено? ────────────────────────────────┐
 ① мьютекс        │ CreateMutexW / OpenMutexW (Local\appcore_<id>) │  ← мгновенно
 ② порт-лок       │ bind 127.0.0.1:189xx (SO_EXCLUSIVEADDRUSE)     │  ← защита гонки
 ③ /api/identity  │ GET → {"app_id": "...", "pid": ...}            │  ← истина в последней инстанции
                  └───────────────────────────────────────────────┘
```

Почему три: мьютекс отвечает быстро, но не переживает перезапуск с задержкой;
порт-лок надёжен, но о нём знает только наше приложение; HTTP-проверка — самая
честная (она же позволяет отличить наше приложение от чужого на том же порту).

Второй запуск должен:

1. найти работающий экземпляр (`ports.find_running`);
2. **поднять его окно** (`windowing.focus_or_open`): ищем окно браузера, в
   заголовке которого есть имя приложения, и вызываем `ShowWindow(SW_RESTORE)` +
   `SetForegroundWindow`;
3. если окна нет — открыть вкладку на фактическом порту (из `/api/identity`);
4. выйти, не поднимая сервер.

Фильтр окон (урок LanguageYOI): проверяем и класс окна, и имя процесса-владельца —
иначе «Проводник: папка LanguageYOI» или папка с похожим именем принимается за
наше окно. Системные классы (`CabinetWClass`, `Progman`, `WorkerW`,
`Shell_TrayWnd`, `TaskManagerWindow`) исключаются всегда.

## 4. Автозапуск

| Способ | Плюсы | Минусы | Кто в репозитории |
|---|---|---|---|
| `HKCU\...\Run` → `wscript start.vbs` | без админа; пути динамические; видно в «Диспетчере задач → Автозагрузка» | нужен запуск при входе в сеанс | Cooker, DeployAgent, BLIND_PC, Трекер (частично) |
| Ярлык в `%APPDATA%\...\Startup` | пользователь видит и может удалить | нужен COM (или PowerShell) для .lnk | shedevrum_bot, swipe_review |
| Планировщик заданий | отложенный старт, права | сложно, требует прав | не используется |
| `HKLM\...\Run` | для всех пользователей | **нужен админ** | не используется (правильно) |

Стандарт — первый способ, и обязательно на `wscript start.vbs`, а **не** на
`pythonw.exe`: тогда обновление Python, переезд папки и переименование exe ничего
не ломают (ровно та ошибка, из-за которой `BLIND_PC` не переезжает).

```python
command = autostart.launcher_command(paths.base)      # wscript.exe "…\start.vbs"
autostart.set_autostart(APP_NAME, command, enable=True)
```

Убрать дубли и лишние записи: `python SPECIALS/tools/audit_windows.py` — покажет
всё, что осталось в автозапуске от проектов.

## 5. URI-протокол (`myapp://`)

Так делают Трекер (`tracker://`) и BLIND_PC (`blindpc`): ссылка из браузера,
ярлыка или QR-кода попадает в **уже запущенное** приложение.

```python
autostart.register_uri_protocol(
    "tracker",
    f'wscript.exe "{paths.base / "start.vbs"}" "%1"',   # %1 подставит Windows
    display_name="URL:Tracker Protocol")
```

Готовые помощники (чтобы не собирать команду руками):

```python
from appcore import autostart, uri

scheme = uri.normalize_scheme(APP_ID)          # specials_demo → specials-demo (RFC 3986)
autostart.register_uri_protocol(scheme, autostart.uri_launcher_command(paths.base))

router = uri.Router(name=scheme)
@router.command("notes/add")                   # specials-demo://notes/add?text=привет
def add(text: str = ""): ...

# при запуске: если приложение уже работает — передать команду и выйти
raw = uri.argv_uri(scheme=scheme)
if raw and uri.send_to_running(raw, port) is not None:
    singleton.exit_process(0)
```

Детали, которые нельзя терять:

* ключ лежит в `HKCU\Software\Classes\<scheme>` — без прав администратора;
* обязательны значения `URL Protocol` (пустая строка) и `shell\open\command`;
* приложение получает URI в `sys.argv` (Трекер: `arg[4:] if arg.startswith("uri:")`);
* если приложение уже запущено, аргумент надо **передать работающему экземпляру**
  по HTTP (Трекер: `/api/uri/<команда>`), а не пытаться обработать «не имея сервера»;
* удалять ключ нужно **рекурсивно** — `winreg.DeleteKey` не удалит ключ с
  подключами (готово в `autostart.unregister_uri_protocol`, как в BLIND_PC);
* схемы из разных проектов не должны совпадать: последний установивший «победит»
  молча, а старый протокол перестанет работать;
* в схеме допустимы только латиница, цифры, «+», «-», «.» (иначе реестр примет,
  а браузеры и другие программы — нет), поэтому имя приложения прогоняют через
  `uri.normalize_scheme()`;
* команды лучше перечислять пользователю (`uri.Router.help_text()`, маршрут
  `/api/uri/help`) — иначе про них никто не узнает.

## 6. Брандмауэр: доступ с телефона

```python
ok, detail = firewall.ensure_rule(port, f"{APP_NAME} (домашняя сеть)")
# netsh advfirewall firewall add rule name=… dir=in action=allow protocol=TCP
#       localport=<port> profile=private remoteip=localsubnet
```

* `profile=private` — только домашняя/рабочая сеть, в общественном Wi-Fi порт закрыт;
* `remoteip=localsubnet` — только своя подсеть;
* перед добавлением — проверка `show rule` (не требует админа);
* без прав администратора netsh не сработает: показываем готовую команду в
  уведомлении трея, а не «тихую ошибку» (приём LanguageYOI).

## 7. Завершение: без «зомби» в диспетчере задач

Порядок выхода (важно соблюдать именно такой):

1. выставить флаг остановки (`STOP.set()`), чтобы фоновые циклы не начали новую работу;
2. остановить сервер: `server.shutdown(); server.server_close()`;
3. снять иконку трея (`icon.stop()`);
4. освободить порт-лок и мьютекс;
5. сбросить логи (`logging.shutdown()`);
6. `os._exit(0)`.

Почему `os._exit`: daemon-потоки (pystray, pynput, watchdog, Flask) не завершаются
мгновенно, и обычный `sys.exit()` оставляет процесс живым. Тогда «закрытое»
приложение держит порт, и следующий запуск получает «порт занят» (в репозитории
эта проблема лечится тем, что Трекер при старте убивает старый процесс по файлу
`_tracker.pid` — рабочий, но грубый приём; в стандарте порядок выхода честнее).

Проверка: после «Выхода» в диспетчере задач не должно остаться процесса, а
`netstat -ano | findstr :<порт>` — пустым.

## 8. Надзиратель: приложение поднимает себя само

Приём DnD's (там отдельный процесс следит за сервером и перезапускает его).
В стандарте за это отвечает `appcore.watchdog`:

```python
watchdog.ThreadWatchdog(
    thread=getattr(SERVER["instance"], "server_thread", None),   # поток Flask-сервера
    health_url=netutil.url_for("127.0.0.1", port, "/api/health"),
    on_down=hotreload.make_restart_handler(paths.base),          # start.vbs + os._exit
    interval=30.0, failures=2, logger=logger,
).start()
```

* одиночная неудача ничего не делает (загрузка ПК, антивирус) — нужны `failures`
  подряд;
* есть «льготное время» после старта (`startup_grace`) и предохранитель
  `max_restarts` на окно времени — чтобы не уйти в бесконечный цикл перезапусков;
* событие попадает в лог с причиной: видно, что именно упало («поток сервера
  завершился» или «сервер не отвечает»).
