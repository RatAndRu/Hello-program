# Разбор проектов: на чём стоит каждое приложение и в чём его крутость

Этот документ — «инвентаризация талантов» репозитория. Он отвечает на вопрос:
**что именно в каждом проекте было придумано хорошо и что из этого стоит брать в
следующий проект**. Все ссылки вида `файл:строка` проверены по коду.

Как читать:

* **Позиционирование** — зачем приложение существует, в чём его смысл для человека.
* **Крутость** — приёмы, которые действительно сделаны хорошо (а не «работает и ладно»).
* **Взято в appcore** — где этот приём живёт теперь как переиспользуемый код.
* **Осталось в проекте** — что специфично и почему не стало общим (и как копировать, если нужно).

Сводные таблицы «фишка → проект → модуль» — в [../README.md](../README.md).
Карта портов и пересечения — в [PORTS.md](PORTS.md).

## 1. DeployAgent — 3173 строки, самый «инженерный» проект

**Позиционирование.** Инструмент разработчика: следит за буфером обмена, видит в
нём ответ ИИ с маркерами `# FILE:` / `# PATCH:`, сам создаёт и правит файлы
проекта, а рядом разбирает «Загрузки» — распаковывает архивы и раскладывает файлы
по папкам. Это не «ещё один скрипт», а рабочий станок: 6.7 версий, 3000+ строк.

**Крутость (по пунктам, с адресами):**

1. **Единый GUI-поток.** `_GuiManager` (`app.py:238`) — один Tk-root в отдельном
   потоке, задачи через очередь: `submit()` (не ждать) и `call()` (дождаться
   результата для модальных диалогов). Это лечит редкие падения Tkinter при
   создании окон из чужих потоков. → `appcore/gui.py`.
2. **Оверлеи-отчёты.** Полупрозрачное окно без рамки сверху экрана
   (`show_overlay` `app.py:670`, `show_report_overlay` `app.py:693`): по одной
   строке ✓/✕ на операцию, клик — копирует отчёт в буфер, наведение мыши — пауза
   автозакрытия. Идеальное решение «под `pythonw` нет консоли, а показать
   результат надо». → `appcore/gui.py` (`overlay`, `report`).
3. **Безопасный вычислитель без `eval`.** `_calculate_expression` (`app.py:1625`)
   разбирает выражение в AST и выполняет только разрешённые узлы; лимит длины,
   количества узлов и величины результата. Проверено: `__import__('os')...` не
   проходит. → `appcore/textutil.py` (`safe_eval_math`).
4. **Быстрая проверка буфера.** `GetClipboardSequenceNumber` (`app.py:2971`):
   сравнили номер — и только потом читаем буфер. При опросе раз в 1.5 секунды это
   разница между «почти незаметно» и «постоянные дёргания буфера». →
   `appcore/clipboard.py` (`sequence_number`, `changed_since`).
5. **Файлы из буфера (CF_HDROP).** `_get_clipboard_files` (`app.py:751`) через
   `DragQueryFileW` — с явными `argtypes/restype` (иначе 64-битный Python падает).
   → `appcore/clipboard.py` (`get_files`).
6. **Ожидание «файл дозаписан».** `_wait_file_ready` (`app.py:997`): размер
   перестал расти — значит, браузер закончил скачивание. Мелочь, без которой
   половина файлов обрабатывалась «на половине». → `appcore/paths.py`-логика
   перенесена в проекты; в `appcore` есть аналогичная проверка в `hotreload`
   (settle) и `ports` (ожидание готовности сервера).
7. **Логика архивов.** Не просто «распаковать»: `_wait_file_ready`,
   `_flatten_single_subfolder` (`app.py:1029`, убрать лишний вложенный уровень),
   `_purge_auto_delete_folders` (прибрать мусорные папки-контейнеры),
   `_move_contents_to` (`app.py:1040`) — раскладка по типам.
8. **Порт-лок (`app.py:374`).** Защита от двух запусков не мьютексом, а **портом**:
   `bind` не даёт «утечь» экземпляру, даже если приложение убили. →
   `appcore/singleton.py`.
9. **Memory-guard.** `_mem_mb` / `_log_mem` (`app.py:165,192`) + авто-перезапуск
   при утечке. Вместе с hot-reload это «приложение чинит себя само». →
   `appcore/hotreload.py`.
10. **Именованный процесс.** Копия `pythonw.exe` с именем приложения
    (`DeployAgent.exe`) + штамп сборки, чтобы не запустить недописанную копию. →
    `appcore/windowing.py` (`ensure_named_interpreter`).
11. **Сканер проекта** (`_scan_project` `app.py:2280`) с диалогом выбора папки и
    расширений, прогрессом и разбором кода по AST (`_analyze_code` `app.py:1761`:
    ищет «следы ИИ», дубли, длинные функции). → идея перенесена в инструменты
    SPECIALS (аналогичную роль играет `tools/check_deps.py`).
12. **Текстовые утилиты буфера.** Смена раскладки (`_switch_layout`
    `app.py:1395`, с фильтром путей/URL/кода/хештегов и порогом «≥70 % букв»),
    починка регистра (`_fix_case_variants` `app.py:1452`), чистка ссылки
    (`_clean_url` `app.py:1463`), HEX→HSL (`app.py:1648`). → `appcore/textutil.py`.

**Осталось в проекте:** маркеры и парсер операций `# FILE:` / `# PATCH:`
(`extract_operations` `app.py:508`, `find_range_indices` `app.py:583`) и watcher
загрузок (`DownloadEventHandler` `app.py:1262`). Это предметная логика конкретного
инструмента; забирать её целиком не нужно, но **приём «бэкап перед каждой правкой»
(`backup_file` `app.py:411`, папка `_backup/`)** стоит помнить.

## 2. LanguageYOI — 14 339 строк, самый большой проект

**Позиционирование.** Персональный тренажёр и дневник для английского и японского:
словарь, интервальные повторения, библиотека чтения, 8 режимов тренировок,
грамматика, статистика — и всё офлайн, в одном SQLite рядом с программой.
Второе приложение (`OCRapp.py`) — экранный переводчик: рамка на экране, OCR,
перевод, оверлей поверх всех окон.

**Крутость:**

1. **SM-2 (интервальные повторения)** — `shared.py:570`. Честный алгоритм с
   `ease_factor`, порогом 1.3 и градацией «Забыл / Трудно / Хорошо»; на нём
   строится вся мотивация приложения.
2. **Конвейер OCR** — `ocr_image_pipeline` (`shared.py:3122`) + группировка
   блоков `group_ocr_blocks` (`shared.py:2743`, включая вертикальный японский
   текст), склейка строк `join_ocr_lines` (`shared.py:751`), починка артефактов
   `_fix_ocr_artifacts`, оценка качества `_outcome_quality`, повторный проход с
   авто-языком `_auto_language_retry`. Это уровень «продукта», а не «вызвал
   tesseract».
3. **Бэкапы базы со safety-копией** — `app.py:3346-3425`: `create_backup_api`,
   `list_backups_api`, `restore_backup_api`. Перед восстановлением текущая база
   сохраняется как `languages_before_restore_<дата>.db`. → `appcore/sqlite_store.py`.
4. **Живое обслуживание БД:** миграции, бэкапы по времени, экспорт в CSV / Anki
   CSV / Markdown / ZIP — то, что делает локальное приложение «настоящим».
5. **TTS с чанкингом и кэшем** — `split_tts_chunks` (`shared.py:1336`),
   `fetch_tts_audio` (`shared.py:1383`): режем текст по 180 символов, кэшируем
   байты, не тянем тяжёлые библиотеки. Приём перенесён в идеи, код специфичен.
6. **Поиск примеров и чтения** — Tatoeba (`shared.py:994`), Gutenberg,
   Wikisource (с подстраницами-главами), Aozora, Syosetu (официальный API),
   archive.org. Из любого текста можно «выдернуть» предложение с целевым словом
   (`find_example_in_texts` `shared.py:940`).
7. **Порты и процессы как в учебнике:** `port_listener_pids` (`shared.py:2105`),
   `process_image_name` (`shared.py:2132`, имя процесса по pid),
   `process_belongs_to_app` (`shared.py:2316`) — убиваем только «своё»,
   `serve_wsgi_until_ready` (`shared.py:2273`) — ждём готовности сервера,
   а не «спим 2 секунды». → `appcore/ports.py`, `appcore/processes.py`.
8. **Брандмауэр по-честному** — `firewall_rule_command`/`firewall_rule_exists`
   (`shared.py:6136`), проверка `netsh interface ipv4 show excludedportrange`
   (`app.py:3712`): узнаём диапазоны, которые Windows заняла под себя (иначе
   «порт свободен, а bind падает»). → `appcore/firewall.py`.
9. **Поиск и фокус окна с фильтром** — проверяются и класс окна, и процесс-владелец,
   системные классы исключаются. → `appcore/windowing.py` (`find_app_window`,
   `focus_or_open`).
10. **Словарь как данные, а не как код:** таблицы уровней (JLPT/CEFR) и флаги
    Jisho, офлайн-определение уровня, дозаполнение «в фоне» (`shared.py:1882-2084`).

**Осталось в проекте:** OCR/TTS/переводчики и структура страниц — это его
предметная область; переносить целиком бессмысленно. Границы приложения описаны
в его `docs/REVIEW-2026-10-02.md`.

## 3. bridge — 1674 строки, «мост ПК ↔ телефон»

**Позиционирование.** Обмен файлами, ссылками и текстом между Windows и
Android/iPhone **без интернета и облаков** — прямо по Wi-Fi. Ставится как PWA на
телефон, живёт в трее ПК.

**Крутость:**

1. **Пароль + токены устройств** (`auth_required` `app.py:171`, `api_auth_login`
   `app.py:621`, `secrets.token_urlsafe(32)`): первое подключение требует пароль,
   дальше каждое устройство носит свой токен и своё имя; устройства можно
   отозвать. Это готовый рецепт «как безопасно открыть порт в домашнюю сеть»
   для любого приложения. → `docs/PORTS.md` §6, идея для будущего `appcore.auth`.
2. **Хоткеи без затирания буфера** (`_on_send_to_phone` `app.py:1325`,
   `_on_paste_from_phone` `app.py:1367`): сначала отпустить модификаторы, запомнить
   буфер, сделать чистый Ctrl+C / Ctrl+V, вернуть буфер как было. → `appcore/clipboard.py`
   (`paste_text`, `release_modifiers` в `appcore/keyinput.py`).
3. **Фильтр «мусора» от системного «Поделиться»** (`looks_like_app_name`
   `app.py:313`): «Ножницы», «Поделиться», «Снимок экрана» больше не засоряют
   историю. Плюс дедупликация файлов по хешу содержимого. →
   `appcore/clipboard.py` (`is_noise`, `content_hash`, `Deduplicator`).
4. **SSE-события** (`broadcast` `app.py:350`, `/api/events` `app.py:1279`):
   телефон и ПК видят одно состояние, тосты и счётчик подключённых устройств. →
   `appcore/events.py`.
5. **Манифест по User-Agent** (`/manifest.json` `app.py:481`): Android получает
   GET-вариант «Поделиться» (только текст/ссылки), ПК — POST с файлами. →
   `appcore/pwa.py` + `appcore/flask_integration.py`.
6. **Автоочистка по возрасту** (`_cleanup_loop` `app.py:370`, `run_autocleanup`
   `app.py:400`): «1 день / 7 / 30 / никогда» — настройка, а не бесконечный рост
   папки входящих.
7. **Папки «входящие/исходящие»** (`api_inbox` `app.py:987`, `api_outbox`
   `app.py:1010`) с превью картинок и открытием папки в Проводнике.

**Осталось в проекте:** вся «почтовая» модель (входящие/исходящие, история,
устройства) — это его суть. Если понадобится в другом проекте, брать как образец
разделов, а не как библиотеку.

## 4. Трекер — 1759 строк, «привычки + таймеры + задачи»

**Позиционирование.** Локальное приложение привычек: трекеры с напоминаниями,
таймер/секундомер/помодоро, задачи, темы оформления. Сервер живёт в трее,
браузер — пульт.

**Крутость:**

1. **Свой Win32-трей** (`NOTIFYICONDATAW` `app.py:145`, `show_balloon` через
   `Shell_NotifyIconW`): полный контроль над левым/правым кликом и «баллонами»
   напоминаний. Это то, чего не умеет pystray из коробки. → идея зафиксирована в
   `docs/TRAY_TASKMGR.md` (в `appcore` используется pystray, потому что он
   кроссплатформенный, но приём с баллонами берётся, когда нужен трекер-нативный
   трей).
2. **URI-протокол `tracker://` с 18 командами** (`setup_uri_protocol`
   `app.py:459`, `URI_COMMANDS.md`): из Win+R, ярлыка, браузера или другого
   приложения можно запустить таймер, отметить задачу, сменить тему. Аргументы
   приходят в уже работающий экземпляр. → `appcore/autostart.py`
   (`register_uri_protocol`) + `docs/TRAY_TASKMGR.md` §5.
3. **Расчёт «когда сработает»** (`compute_next_fire` `app.py:371`) — учитывает
   интервал, окно дня, паузы и пропущенные срабатывания. Это самая сложная
   логика приложения, и она хорошо изолирована.
4. **Жизненный цикл задач** (`calculate_task_stats` `app.py:603`,
   `_lifecycle_periods`): задачи «закончились», «приостановлены», «были активны
   в такие-то периоды» — статистика считается по истории, а не по текущему флагу.
5. **Принудительная замена старого процесса** (`kill_old_server` `app.py:304`)
   и отдельный PID-файл: грубый, но рабочий способ не получить два сервера.
   В стандарте заменён на порт-лок + `/api/identity` (см. `docs/TRAY_TASKMGR.md` §3).
6. **Фокус существующего окна** (`focus_tracker_window` `app.py:230`): повторный
   клик по ярлыку не открывает вторую вкладку, а поднимает уже открытую. →
   `appcore/windowing.py`.
7. **Идеи на будущее в `IDEAS.md`:** офлайн-режим PWA с IndexedDB и синхронизацией,
   catch-up уведомления после простоя («за время отсутствия сработало 6
   напоминаний»). Это готовый roadmap для «умных» локальных приложений.

## 5. Телепульт — 534 строки, маленький и очень полезный

**Позиционирование.** Телефон превращается в пульт для компьютера: клавиатура,
мышь, громкость, медиа-клавиши, ярлыки, системные действия.

**Крутость:**

1. **`keybd_event` вместо pyautogui** (`key_event` `app.py:141`, карта
   VK-кодов `app.py:127`): работает там, где pyautogui «промахивается»
   (игры, окна с повышенными правами, медиа-клавиши). → `appcore/keyinput.py`.
2. **Громкость двумя путями** (`set_volume_pycaw` `app.py:204` →
   `fallback_set_volume_with_media_keys` `app.py:235`): сначала честная регулировка
   через Core Audio, если pycaw нет — нажатия VK_VOLUME_*. → идея в
   `appcore/keyinput.py` (`volume_up`/`volume_down` в таблице кодов).
3. **Вставка текста через буфер** (`paste_text` `app.py:179`): юникод не
   печатается посимвольно — кладём в буфер и жмём Ctrl+V. → `appcore/clipboard.py`
   (`paste_text`).
4. **Пользовательские ярлыки** (`ensure_shortcuts_file` `app.py:324` …
   `run_shortcut` `app.py:364`): `app` / `url` / `script` — из телефона можно
   запускать что угодно на ПК. Нормализация данных при загрузке (`normalize_shortcut`).
5. **Доступность:** временное увеличение системного курсора через реестр
   (`read_cursor_size`/`write_cursor_size` `app.py:273-298`) — приём, который
   стоит помнить, если приложением пользуется человек с плохим зрением (ср. BLIND_PC).
6. **COM init/uninit под потоки** (`init_com`/`uninit_com` `app.py:186`): без этого
   обращения к системному звуку из разных потоков ломаются.

**Важно (безопасность):** приложение слушает `0.0.0.0` **без пароля** и умеет
выключать/перезагружать ПК. Это самый яркий пример того, почему в стандарте
появилось правило «управление ПК — только с токеном» (`docs/PORTS.md` §6).

## 7. swipe_review — 613 строк, «Tinder для картинок»

## Чек-лист «что взять в новый проект» (сверху вниз по приоритету)

1. **Каркас:** `new_project.py` → свой блок портов, `start.vbs`, `stop.vbs`, `data/`.
2. **Трей, автозапуск, один экземпляр** — из `appcore.tray` / `autostart` / `singleton`.
3. **Хранилище:** JSON через `jsonstore`, тяжёлые данные — SQLite через `sqlite_store` (с бэкапом при старте и перед опасными операциями).
4. **PWA:** `flask_integration.install` (manifest по UA, sw.js, «Поделиться», QR).
5. **Живое состояние:** `events.EventBus` — если приложение открыто с телефона и с ПК.
6. **Тексты и буфер:** `textutil` (раскладка/регистр/калькулятор/ссылки) и `clipboard` (файлы, вставка без затирания).
