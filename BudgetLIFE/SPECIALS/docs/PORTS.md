# Порты: карта, конфликты, план переезда

> Проверено скриптом `python SPECIALS/tools/check_ports.py` (он же умеет `--json`).
> Актуально на момент анализа репозитория.

## 1. Правило

1. У проекта есть **блок из 10 портов** в `SPECIALS/ports.json`.
2. Основной порт — база блока; при занятости берётся следующий **из своего** блока.
3. Свободность проверяется **bind-ом** на том же адресе, где будет слушать сервер
   (`appcore.ports.port_is_free`), а не `connect_ex` на 127.0.0.1.
4. Даже если порт свободен — приложение проверяет, **кто на нём отвечает**
   (`/api/identity`). Совпал `app_id` → второй экземпляр не поднимается, а
   открывает окно уже работающего.
5. Фактический порт пишется в `data/port.txt` (`appcore.ports.write_port_file`).
6. Сервер поднимается **синхронным bind-ом** (`flask_integration.serve_with_fallback`),
   поэтому «занят» видно сразу, и приложение молча не превращается в «не работает».

Зачем это всё: динамический `find_free_port` создаёт гонку (проверили — закрыли —
заняли), а `flask_app.run()` при занятом порте падает в отдельном потоке так, что
снаружи это выглядит как «приложение не запустилось без ошибки».

### Конфликт 1. Порт 5000 занят ТРЕМЯ приложениями

| Файл | Строка | Код |
|---|---|---|
| `swipe_review/app.py` | 74 | `PORT = 5000` |

Последствия: одновременно запустятся максимум одно-два; остальные получат
`OSError: [WinError 10048]` в потоке сервера (на Linux/NTFS-разные ОС — свой текст).
Хуже всего, что ошибка попадает «в никуда», если нет обработки: приложение
выглядит запущенным (иконка в трее есть), а сайт не открывается.

### Конфликт 2. Порт 5001: bridge против сканера Cooker

| Файл | Строка | Код |
|---|---|---|
| `bridge/app.py` | 77 | `PORT = 5001` |
| `Cooker/app.py` | 40 | `def get_free_port(start=5001):` |
| `Cooker/app.py` | 438 | `PORT = get_free_port(start=5001)` |

Cooker ищет **любой** свободный порт от 5001 и выше, поэтому может занять 5002
(BLIND_PC), 5100 (Трекер) и вообще любой чужой. При этом сам Cooker пишет
`connect_ex` — сервер, слушающий не на 127.0.0.1, для него «свободен».

### Конфликт 3. 5678: LanguageYOI против PlotMaker (и переплетение с переводчиком)

| Файл | Строка | Код |
|---|---|---|
| `LanguageYOI/shared.py` | 2241 | `DASHBOARD_PORTS = (5678, 5681, 5682, 5683)` |

| `LanguageYOI/OCRapp.py` | 3484-3486 | `TTS_PORT = 5679`, `TTS_PORT_FALLBACK = 5680`, `PANEL_PORTS = (5679, 5680)` |

Тут целый клубок: PlotMaker сканирует 5678-5777, то есть может занять порты

держит фолбэки, которые пересекаются с портами переводчика. Правильно:
**словарь** 5660-5679 (основной 5678), **переводчик** 5680-5699 (основной 5680),

### Риск 4. 8080 внутри диапазона DnD's

| Файл | Строка | Код |
|---|---|---|
| `DnD's/backend/main.py` | 62 | `def find_free_port(start=8000, end=8100):` |
| `SHADOW GAME/tray_server.py` | 13 | `PORT = 8080` |

DnD's поднимается первым и занимает 8080 → SHADOW GAME печатает «Не удалось
запустить сервер на порту 8080» и ждёт Enter (то есть без консоли процесс просто
умирает). Решение: DnD's 8000-8009, SHADOW GAME 8010-8019.

### Наблюдения (не конфликты, но грабли)

* `DeployAgent` — порт 18523 как **лок**, а не HTTP. Это правильно; но в коде
  используется `SO_REUSEADDR` (`DeployAgent/app.py:386-388`) — на Windows это
  позволяет сесть поверх чужого сокета, поэтому лок может ложно «сработать».
  В `appcore` для локов используется `SO_EXCLUSIVEADDRUSE`.
* `Cooker/app.py:43` и `PlotMaker/app.py:45` закрывают проверочный сокет и только
  потом слушают порт — классическая гонка (TOCTOU).
* `SHADOW GAME/tray_server.py:13` — фиксированный порт без проверки: если занят,
  сервер не поднимается и приложение не работает.
* Ни одно приложение (кроме LanguageYOI) не пишет `data/port.txt`, поэтому
  ярлыки/трей/`stop.vbs` вынуждены знать порт заранее — при смене порта ломается.
* `BLIND_PC/start.vbs` содержит жёсткий путь `C:\AI_Projects\BLIND_PC\app.py` —
  проект нельзя перенести в другую папку.

## 4. Почему нельзя просто «взять любой свободный порт»

1. **Гонка.** Между проверкой и запуском порт может занять кто угодно (Cooker и
   PlotMaker делают именно так).
2. **Ложная свобода.** `connect_ex(("127.0.0.1", port))` не видит сервер,
   слушающий только на другом интерфейсе или на конкретном IP.
3. **Чужие данные.** На занятом порту может быть чужой сервер: приложение
   откроет его страницу и будет считать, что «всё работает».
4. **PWA-ярлык.** На телефоне установленное приложение привязано к origin
   (`http://IP:ПОРТ`). Если порт «уехал», ярлык открывает **другой проект**.
   Поэтому основной порт должен быть фиксированным и уникальным.
5. **Автозапуск и ярлыки.** Скрипты и ярлыки ссылаются на порт: динамика требует
   общего `data/port.txt` (в стандарте он есть).

## 5. Миграция существующего проекта на блоки (10 минут)

1. Добавьте свой блок в `SPECIALS/ports.json` (или создайте проект через
   `new_project.py` — он сам это сделает).
2. Замените поиск порта на стандартный код:

```python
from appcore import ports, flask_integration

server, port = flask_integration.serve_with_fallback(
    flask_app, app_id=APP_ID, host=HOST,
    candidate_ports=ports.candidates(APP_ID))          # только свой блок
if server is None:
    ...  # сообщить в трей и выйти, а не падать
ports.write_port_file(paths.data, port, APP_ID)         # data/port.txt
```

3. Подключите `/api/identity` (`flask_integration.install`) — без него не работает
   проверка «уже запущено» и второй запуск откроет второе окно на другом порту.
4. В `start.vbs` ничего менять не нужно: он просто запускает `app.py`.
5. Проверьте: `python SPECIALS/tools/check_ports.py` — ваш порт больше не конфликтует.

### Если хочется оставить «динамику»

Тогда она обязана быть **ограниченной** (свой блок) и **проверяемой по личности**:

```python
for port in ports.candidates(APP_ID):           # ровно 10 портов своего блока
    if not ports.port_is_free(HOST, port):
        continue
    ...
```

Сканер «от 5001 и до 65535» (Cooker, PlotMaker) в стандарт не входит: однажды он
займёт порт другого приложения, и разбираться в этом будет очень неприятно.

## 6. Безопасность: 0.0.0.0 без пароля

Сейчас на `0.0.0.0` слушают: `shedevrum_bot` (5000), `Телепульт` (5000),
`swipe_review` (5000 по умолчанию), `BLIND_PC` (5002), `bridge` (5001),
`DnD's` (8000-8100), `SHADOW GAME` (8080), `LanguageYOI`-словарь (5678).

Любое устройство в той же Wi-Fi сети может открыть эти страницы. Для Телепульта
это означает управление мышью и клавиатурой компьютера, для `bridge` — доступ к
буферу обмена и файлам.

Как правильно:

1. по умолчанию `HOST = "127.0.0.1"` (так делают Cooker, Трекер, PlotMaker,
   LanguageYOI-переводчик);
2. перевод на `0.0.0.0` — осознанным переключателем (`--host 0.0.0.0 --lan`);
3. правило брандмауэра — только `profile=private remoteip=localsubnet`
   (`appcore.firewall.ensure_rule`), а не «разрешить всем»;
4. для управления чужими устройствами — токен/пароль. Образец — `bridge`:
   `/api/auth/login` с паролем, токен устройства (`secrets.token_urlsafe(32)`),
   cookie на год, список устройств в `data/devices.json`;
5. никогда не открывать порт в публичной сети: `profile=private` это и защищает.
