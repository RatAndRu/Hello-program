# SPECIALS — золотой стандарт локальных PWA-приложений

Эта папка — **эталон**. Здесь собрано всё лучшее, что накопилось в проектах этого
репозитория (14 приложений), разложено по полочкам, описано и оформлено так,
чтобы новый проект делался сразу правильно — и человеком, и нейросетью.

```
SPECIALS/
├── README.md            ← вы здесь: стандарт, правила, откуда что взято
├── ports.json           ← реестр портов: у каждого проекта свой блок
├── appcore/             ← библиотека «общий код»: 26 модулей с комментариями
│     инфраструктура: paths, logutil, jsonstore, ports, processes, singleton,
│                     autostart, firewall, windowing, tray, hotreload, pwa,
│                     flask_integration, netutil, processes
│     фишки проектов: textutil (раскладка/регистр/калькулятор/ссылки),
│                     clipboard (файлы, вставка без затирания, фильтр мусора),
│                     keyinput (клавиши/мышь WinAPI), gui (один Tk-root,
│                     оверлеи, отчёты), hotkeys (глобальные сочетания),
│                     sqlite_store (миграции, бэкапы, восстановление),
│                     events (живые обновления SSE), qr (QR-код без зависимостей),
│                     versioning (бэкапы архивом), uri (команды myapp://),
│                     spaced (SM-2), watchdog (надзиратель за сервером)
├── template/            ← готовый каркас нового проекта (запускается «как есть»)
│     app.py + app.txt, start.vbs + start.txt, templates/index.html + index.txt
│     (.txt-копии — привычный формат «отдать нейросети»)
├── tools/
│   ├── new_project.py   ← создать новый проект из шаблона одной командой
│   ├── check_ports.py   ← аудит портов по всему репозиторию (находит конфликты)
│   ├── check_deps.py    ← импорты vs requirements.txt: чего не хватает проекту
│   ├── check_vbs.py     ← проверка VBS-скриптов (кавычки, Dim, блоки, пути)
│   ├── audit_windows.py ← что сейчас запущено: порты, процессы, автозапуск
│   ├── win_task.py      ← действия: остановить/перезапустить своё, автозапуск, URI
│   ├── make_txt_mirrors.py ← .txt-копии исходников (для передачи нейросети)
│   └── self_test.py     ← самопроверка appcore и эталона без Windows и сервера
└── docs/
    ├── PORTS.md          ← карта портов, конфликты, план переезда
    ├── LAUNCHER_VBS.md   ← разбор start.vbs: почему он такой и что в нём важно
    ├── TRAY_TASKMGR.md   ← трей, диспетчер задач, реестр, автозапуск, один экземпляр
    ├── PWA_SHARE.md      ← PWA, «Поделиться», QR, офлайн, кэш
    ├── PROJECTS.md       ← разбор всех 14 проектов: в чём крутость каждого
    └── CHECKLIST.md      ← чек-лист нового проекта + готовый промпт для нейросети
```

Быстрый старт:

```bash
python SPECIALS/tools/new_project.py "Моё Приложение"     # создать проект
cd "Моё Приложение" && start_debug.bat                   # запустить с консолью
python SPECIALS/tools/check_ports.py                     # проверить порты
```

## 1. Из чего собирается проект

Обязательный каркас (так устроены все проекты, и так должно остаться):

| Файл / папка | Обязательно | Зачем |
|---|---|---|
| `app.py` | да | вся логика: Flask + API + трей + фоновые задачи |
| `start.vbs` | да | тихий запуск без консоли; сам находит `pythonw.exe` |
| `stop.vbs` | да | корректная остановка **только своего** приложения |
| `start_debug.bat` | да | запуск с консолью: видно ошибки, окно не пропадает |
| `data/` | да | всё изменяемое: JSON/БД, `port.txt`, картинки, `shared/`, `.bak` |
| `static/` | да | иконки PWA (генерируются сами), файлы интерфейса |
| `templates/` | да | HTML (Jinja2) |
| `logs/` | да | `log.txt` (ротация), `launch.log` (что и как запускалось) |
| `appcore/` | да | скопированная библиотека SPECIALS (вендорится в проект) |
| `ports.json` | да | свой блок портов (tiny-копия записи из `SPECIALS/ports.json`): `appcore` читает файл рядом с собой, поэтому проект знает свой блок и вне репозитория |
| `requirements.txt` | да | зависимости: `flask`, `pystray`, `pillow`, `psutil` |
| `readme.txt` | да | как запустить, где данные, что делать при проблемах |

Правило: **код и данные разделены**. `data/` можно удалить — приложение
запустится и создаст всё заново; код при этом не пострадает.

## 2. Правила, из которых всё состоит

### 2.1 Запуск (VBS) — «двойной клик и всё работает»

Единый `start.vbs` умеет всё, что было найдено по частям:

1. берёт папку **от собственного файла** (`GetParentFolderName(WScript.ScriptFullName)`) —
   проект запускается с любого диска и из любой папки;
2. ищет `pythonw.exe` по цепочке:
   именованный exe приложения (со штампом сборки) → `py -3.12-64/-3.12/…` →
   типовые пути (`%LOCALAPPDATA%\Programs\Python\…`, `C:\PythonXX`, `Program Files`) →
   `where pythonw.exe`;
3. **никогда не запускает `python.exe`** — только `pythonw.exe` (окно консоли не мигает);
4. пробрасывает аргументы (`start.vbs "%1"`) — так работают URI-протоколы
   вида `myapp://...`;
5. если Python не найден — показывает `MsgBox` с инструкцией (а не «молчит»);
6. пишет строку в `logs\launch.log`: что, когда и какой командой запускалось —
   это первое, что нужно смотреть, когда «не работает».

Подробный разбор всех 14 VBS-файлов репозитория и допущенных в них ошибок —
в [docs/LAUNCHER_VBS.md](docs/LAUNCHER_VBS.md).

### 2.2 Один экземпляр — три уровня защиты

| Уровень | Что делает | Источник |
|---|---|---|
| Именованный мьютекс | мгновенная проверка «уже запущено?» | LanguageYOI (`CreateMutexW`) |
| Порт-лок с повторами | защищает гонку при перезапуске (старый процесс ещё держит сокет) | DeployAgent (`acquire_lock`) |
| `/api/identity` | главный: если ответил — открываем окно и выходим | LanguageYOI (`find_running_server`) |

Почему проверять **именно личность**, а не занятость порта: порт может быть занят
чужой программой, и тогда «второй запуск» откроет не наше окно. В `appcore` это
`ports.find_running()` + `ports.check_identity()`.

### 2.3 Порт — только из своего блока

* У каждого проекта в `SPECIALS/ports.json` **свой блок из 10 портов**; копия
  своей записи лежит в `ports.json` внутри проекта (`new_project.py` создаёт
  её сам) — иначе `appcore` возьмёт «блок по хэшу», и порт разъедется с реестром.
* Приложение пробует основной порт и, если он занят, — следующий **из своего блока**
  (никогда не заходит в чужой).
* Порт проверяется bind-ом на том же адресе, по которому будет слушать сервер
  (`appcore.ports.port_is_free`), а не connect-ом на 127.0.0.1.
* Выбранный порт пишется в `data/port.txt` (первая строка — число, ниже JSON) —
  его читают трей, ярлыки, `stop.vbs` и скрипты аудита.
* `stop.vbs` и любой «убей процесс на порту» **сверяют командную строку** процесса
  (там должен быть путь нашего `app.py`) — приём SHADOW GAME.

Найденные в репозитории конфликты (5000 ×3, 5001 ×2, 5678 ×2 + динамические
сканеры) и план переезда — в [docs/PORTS.md](docs/PORTS.md).

### 2.4 Имя в диспетчере задач

Чтобы Windows показывала «Specials Demo», а не «pythonw.exe»:

1. `AppUserModelID` (`RatAndRu.Specials.<app_id>`) — приём LanguageYOI;
2. копия `pythonw.exe` с именем приложения рядом с `app.py` + файл-штамп
   `.launcher` (штамп гарантирует, что копия доделана) — приём DeployAgent;
3. `SetConsoleTitleW` для отладочного запуска.

### 2.5 Трей — «приложение, а не консоль»

* Иконка **рисуется в памяти** (Pillow): не бывает «нет файла — нет трея».
* Меню описывается данными (`tray.TrayItem`), поэтому не зависит от версии pystray.
* Обязательные пункты: версия, «Открыть» (левый клик), «Копировать адрес»,
  «QR-код», «Автозапуск» (галочка), «Перезапустить», «Выход».
* Обратная связь — `notify()` (всплывающее уведомление), иначе пользователь
  думает, что клик не сработал.
* Без `pystray` приложение **не падает**: пишет в лог точную команду установки и
  продолжает обслуживать веб-интерфейс.
* `pystray` запускается в **главном потоке**; Flask-сервер — в отдельном.

### 2.6 Реестр — только HKCU, только через `appcore`

| Что | Где | Кто делает так |
|---|---|---|
| Автозапуск | `HKCU\...\CurrentVersion\Run` → `wscript start.vbs` | Cooker, DeployAgent, BLIND_PC, Трекер |
| URI-протокол | `HKCU\Software\Classes\<scheme>` | Трекер (`tracker://`), BLIND_PC (`blindpc`) |
| Ярлык в «Автозагрузке» | `%APPDATA%\...\Startup\*.lnk` | shedevrum_bot, swipe_review |
| Брандмауэр | `netsh advfirewall … profile=private remoteip=localsubnet` | LanguageYOI |
| Системный курсор | `HKCU\Control Panel\Cursors` | Телепульт (с восстановлением) |

Правила: не писать в `HKLM` (не нужен администратор), удалять ключи **рекурсивно**
(URI-протокол — дерево, `winreg.DeleteKey` сам не убирает под ключи),
автозапуск ставить не на `pythonw.exe`, а на `wscript start.vbs` — тогда переезд
папки и обновление Python ничего не ломают.

### 2.7 Hot-reload: сохранил файл — приложение само перезапустилось

`appcore.hotreload.HotReloadWatcher` следит за `.py/.vbs/.js/.css/.html`, ждёт
«успокоения» файла (защита от частичной записи), игнорирует `data/`, логи и
`__pycache__`, а при изменении:

```
остановить фоновые задачи → освободить порт-лок и мьютекс → запустить start.vbs → os._exit(0)
```

Плюс **memory-guard**: если процесс распух больше `MEMORY_LIMIT_MB` и не занят
операцией — перезапуск с записью причины в лог (приём DeployAgent).

### 2.8 PWA: установка на телефон, «Поделиться», офлайн

* `/manifest.json` отдаётся **динамически** и зависит от User-Agent:
  телефону — `share_target` методом `GET` (Android отдаёт только текст/ссылку),
  ПК — `POST multipart` с файлами (приём bridge);
* `/sw.js` с заголовками `Service-Worker-Allowed: /` и `Cache-Control: no-store`;
* в service worker — перехват POST-«Поделиться» (иначе Safari ломается);
* HTML отдаётся с `no-store` — правки видны сразу, старая версия не «залипает»;
* `icon-192/512` + `maskable` генерируются автоматически; `launch_handler:
  focus-existing` не даёт плодить окна;
* страница `offline.html` — «нет связи с ПК», а не белый экран.

Подробности и подводные камни Android/iOS — в [docs/PWA_SHARE.md](docs/PWA_SHARE.md).

### 2.9 Данные не теряются

* `appcore.jsonstore.JsonStore`: запись через временный файл + `fsync` + `os.replace`
  (атомарно), бэкап `.bak`, карантин битого файла в `.corrupt-<дата>`, восстановление
  из бэкапа. Взято из LanguageYOI (там это делалось для конфига переводчика).
* Чтение/запись под одним `RLock` (Flask-поток + трей + фоновые задачи).
* `ensure_ascii=False` + `encoding="utf-8"` — русский текст читаемый.
* Логи — с ротацией (1 МБ × 3 файла) и обрезкой; исключения — через
  `sys.excepthook`/`threading.excepthook` (иначе pythonw падает молча).

### 2.10 Выход без «зомби»

`«Выход»` в трее и `stop.vbs` должны: остановить сервер (`server.shutdown()`),
снять иконку, освободить порт-лок/мьютекс, сбросить логи и вызвать `os._exit(0)`.
Обычный `sys.exit()` не помогает: потоки `pystray`/`pynput`/Flask держат процесс,
и он остаётся в диспетчере задач, занимая порт.

### 2.11 Полезные мелочи, из которых складывается удобство

Эти приёмы не обязательны для запуска, но именно они отличают «работает» от
«приятно пользоваться». Все лежат в `appcore` и включаются одной строкой.

| Модуль | Что даёт | Откуда |
|---|---|---|
| `textutil` | смена раскладки («ghbdtn» → «привет»), починка регистра, калькулятор без `eval` (понимает «2 плюс 3 умножить на 4»), HEX→RGB/HSL, чистка ссылки, безопасное имя файла, «сто двадцать три» → 123 | DeployAgent, BLIND_PC |
| `clipboard` | файлы из буфера (`CF_HDROP`), номер изменения (не читать буфер зря), вставка **без затирания** буфера, фильтр мусора («Ножницы», «Поделиться»), дедупликация по хэшу | bridge, DeployAgent |
| `keyinput` | клавиши и мышь через WinAPI (работает там, где пасует pyautogui), отпускание зажатых модификаторов, медиа-клавиши и громкость | Телепульт, bridge |
| `gui` | один Tk-root на всё приложение (Tcl/Tk не потокобезопасен), оверлеи-отчёты ✓/✕ (важно при запуске без консоли), простые диалоги | DeployAgent |
| `hotkeys` | глобальные сочетания клавиш с перепривязкой и честным сообщением, когда библиотеки нет | bridge, PromptSystem |
| `sqlite_store` | миграции по `user_version` (идемпотентно), бэкап при старте и перед опасным действием, восстановление **со страховочной копией**, `integrity_check`, экспорт в JSON | LanguageYOI, DnD's, Cooker |
| `events` | живые обновления без WebSocket: телефон и ПК видят одно состояние, счётчик подключённых, тосты | bridge, swipe_review |
| `qr` | QR-код вообще без зависимостей (SVG и PNG), `/api/qr` больше не отказывает | bridge, BLIND_PC, DnD's |
| `versioning` | бэкап данных одним ZIP-ом (с манифестом), восстановление **со страховочной копией**, защита от zip-slip, экспорт/импорт JSON | LanguageYOI, Cooker, DnD's |
| `uri` | команды `myapp://…`: разбор, таблица команд, передача команды работающему экземпляру | Трекер, BLIND_PC |
| `spaced` | интервальные повторения SM-2: интервалы 1 → 6 → 15 дней, `ease` не ниже 1.3 | LanguageYOI |
| `watchdog` | упал поток сервера или сервер молчит — приложение перезапускается само | DnD's, DeployAgent |

Пример «как это выглядит в жизни» — в эталонном приложении
(`template/app.py`): карточка «Инструменты (фишки из проектов)» в интерфейсе и
маршруты `/api/tools*`, а `/api/events` — поток событий (SSE).

1. **Новый проект** — попросите: «сделай проект по стандарту SPECIALS, каркас уже

   `SPECIALS/template/templates/index.html`». Нейросети проще один раз сослаться на

2. **Проверка чужого кода** — прогоните `check_ports.py` и сверьтесь с чек-листом
   из п.6: почти все «детские болезни» проектов ловятся именно этими пунктами.
3. **Правки `appcore`** — меняйте в `SPECIALS/appcore`, затем переносите в проекты
   копированием (проекты самодостаточны: `appcore` лежит внутри проекта).
   Для сверки версий в `appcore/__init__.py` есть `__version__`.
4. **Передача файлов нейросети** — `python SPECIALS/tools/make_txt_mirrors.py`
   обновит `.txt`-копии (`app.txt`, `start.txt`, `index.txt`) рядом с исходниками —
   привычный для этого репозитория формат. У эталона копии уже лежат
   (`template/app.txt`, `template/start.txt`, `template/templates/index.txt`);
   обновить их после правок: `--root template --all`, проверить: `--check`.

## 9. Ограничения и честные замечания

* Windows-специфичные части (реестр, брандмауэр, трей, мьютекс) на Linux/macOS
  тихо отключаются — приложение продолжает работать, в лог пишется причина.
* Трей требует `pystray` + `pillow`; память/процессы — `psutil` (всё опционально
  и проверяется перед использованием). QR **не требует ничего**: если пакета
  `qrcode` нет, работает свой кодировщик `appcore.qr` (проверен модуль в модуль
  с библиотекой на всех 8 масках и прочитан настоящим декодером).
* `hot-reload` по умолчанию включён в эталонном шаблоне (удобно при разработке):
  в «релизе» поставьте `HOT_RELOAD = False`.
* Копия `pythonw.exe` с именем приложения — трюк Windows; антивирусы иногда
  относятся к «необычному exe» настороженно, поэтому он создаётся рядом с `app.py`
  и легко удаляется (проект работает и без него).
* Правило брандмауэра требует прав администратора: приложение честно скажет об
  этом уведомлением и предложит готовую команду `netsh`.
