================================================================
  BudgetLIFE — что это и как этим пользоваться
================================================================
Версия: 1.0.0
Порт:   5130 (свой блок 5130–5139, см. ports.json и SPECIALS/ports.json)

КАК ЗАПУСТИТЬ
-------------
НИЧЕГО УСТАНАВЛИВАТЬ НЕ НУЖНО: готовая сборка лежит в папке dist/, а раздаёт
её server.ps1 — сервер на встроенном в Windows PowerShell. Node.js, Python и
какие-либо загрузки из интернета не требуются.

1. Обычный запуск: двойной клик по start.vbs (окно консоли не появляется).
   Скрипт поднимет скрытый сервер и откроет отдельное окно приложения —
   без адресной строки, как обычная программа.
   Если на компьютере установлен Node.js, он будет использован автоматически
   (сервер поднимается быстрее, а правки исходников собираются сами).
2. Ярлык на рабочий стол (и в меню «Пуск», и в автозапуск): tools\Ярлык.vbs.
3. Если что-то не работает: start_debug.bat — консоль с ошибками, окно не
   исчезает; tools\Диагностика.vbs — полный отчёт (порт, процесс, автозапуск).
4. Остановить: stop.vbs (завершает только процессы ЭТОГО проекта).

ГДЕ ЧТО ЛЕЖИТ
-------------
server.ps1        — локальный сервер БЕЗ зависимостей (PowerShell + .NET):
                    порт из своего блока, /api/identity, /api/health, лог
server.js         — то же самое на Node.js (если он установлен)
dist/             — готовая сборка (в репозитории, чтобы npm не требовался)
start.vbs         — тихий запуск (сам находит node.exe)
stop.vbs          — корректная остановка только своего процесса
start_debug.bat   — запуск с консолью (отладка)
Обновить.cmd      — npm install (если нужно) + npm run build
ports.json        — свой блок портов (копия записи из SPECIALS/ports.json)
data/             — изменяемые данные: port.txt (актуальный порт)
logs/             — server.log (сервер), launch.log (запуски), log.txt (трей)
src/, public/     — исходники и иконки
dist/             — собранное приложение (появляется после npm run build)
tools/            — Ярлык.vbs, Автозапуск.vbs, Диагностика.vbs, tray.py
SPECIALS/         — эталон стандарта (не меняется проектом)

ЧТО УМЕЕТ (по золотому стандарту SPECIALS)
------------------------------------------
* Одно окно приложения: Edge/Chrome в режиме --app, свой профиль, размер 1500×940.
* Один экземпляр: повторный запуск поднимает уже открытое окно, а не плодит
  процессы (проверка по /api/identity, а не по занятости порта).
* Порт из своего блока 5130–5139: основной фиксирован (от него зависит origin
  установленного PWA), при занятости — следующий порт блока; порт пишется
  в data\port.txt, его читают лаунчер, ярлыки и трей.
* Остановка «только своего»: stop.vbs сверяет командную строку процесса.
* Автозапуск: HKCU\...\Run → wscript.exe start.vbs (tools\Автозапуск.vbs),
  прав администратора не нужно.
* Имя в диспетчере задач: копия node.exe под именем BudgetLIFE.exe + штамп.
* PWA: устанавливается, работает офлайн, иконки 192/512/maskable/ico.
* Логи: logs\server.log (ротация 1 МБ × 3) и logs\launch.log (запуски).
* Диагностика одной кнопкой: tools\Диагностика.vbs.
* По желанию — иконка в трее: python tools\tray.py (Python + pystray/pillow).

ЧАСТЫЕ ВОПРОСЫ
--------------
«Порт занят» — сервер сам возьмёт следующий порт своего блока и запишет его
   в data\port.txt; start.vbs найдёт его сам (проверяет весь блок).
«Окно не открылось» — смотрите logs\launch.log: там видно, найден ли node.exe,
   была ли сборка и на каком порту сервер ответил.
«Данные пропали» — данные живут в браузере (IndexedDB) в профиле окна
   приложения: не чистите «данные сайтов» и делайте экспорт JSON
   в «Настройки → Резервные копии».
«После правок показывается старая версия» — нажмите Ctrl+F5: HTML, sw.js и
   манифест отдаются с no-store; файлы сборки кешируются по имени (хеш).
«Не найден Node.js» — для обычного запуска он и не нужен: сервер поднимает
   PowerShell. Node.js требуется только для пересборки dist/ (Обновить.cmd)
   и для режима разработки (MODE = dev).
«Недопустимый знак» (Invalid character 800A0408) — файл .vbs сохранён в UTF-8:
   Windows Script Host такие файлы не понимает. Запустите
   python tools\vbs_encoding.py — он перекодирует все .vbs в UTF-16LE с BOM.
   Только после этого двойной клик по start.vbs сработает.
