# BudgetLIFE

Персональное PWA-приложение для планирования бюджета: доходы с плавающими датами, счета с процентами,
подписки, кредиты с беспроцентными периодами, календарь выплат и конвертер валют с актуальными курсами.

Всё работает **локально в браузере** (IndexedDB) — без сервера, регистрации и отправки данных наружу.
Приложение устанавливается как обычная программа (ярлык, трей, отдельное окно) и работает офлайн.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5131 (dev-порт из своего блока)
npm run build      # production-сборка в dist/
npm run preview    # предпросмотр production-сборки (порт 5132)
npm run start      # раздать dist/ локальным сервером (порт 5130 — им запускает start.vbs)
npm run tray       # необязательная иконка в системном трее (Python)
npm test           # проверки ядра (движок) и интерфейса (рендер всех страниц в jsdom)
```

Первый запуск предложит два варианта: **загрузить демо-данные** (готовый жизненный сценарий) или
**начать с чистого листа**. Демо в любой момент можно перезагрузить в «Настройки → Приложение».

## Что умеет

### Обзор
Сводка на сегодня: общий баланс, доходы и расходы периода (план и факт отдельно), прогноз баланса на конец
периода, пассивный доход по счетам. График динамики баланса на 1/3/6/12 месяцев с учётом процентов,
ближайшие события, структура расходов с лимитами по категориям, сводка по подпискам и кредитам.

### Календарь
Месячная сетка с операциями по дням: доходы, подписки, кредиты, проценты, плановые траты.
Видны итоги дня и прогноз баланса, фильтры по типам событий и счетам, отметка «уже произошло».
Двойной клик по дню — быстрая операция на эту дату.

### Доходы
- **Несколько дней выплат в месяце**: аванс + зарплата, несколько заказчиков, премии.
  У каждой выплаты — своя метка, день месяца, доля (в процентах) или фиксированная сумма.
- **Плавающие даты**: день можно задать как «последний день месяца» или «предпоследний»,
  а правило переноса сдвинет выплату на ближайший рабочий день (учтены выходные и праздники РФ).
- **Корректировки по месяцам**: у каждого месяца можно изменить сумму, перенести конкретную выплату
  на другую дату, изменить сумму выплаты, отметить выплату полученной или отменить её.
- **Сдельная работа**: флаг «сумма меняется» — такие выплаты помечаются «уточнить», пока не введена сумма.
- Удержание налога на уровне источника (например НДФЛ 13%) — в план попадает сумма на руки.
- Сетка выплат на полгода по всем источникам.

### Расходы и план бюджета
Плановые и фактические операции с датами, категориями, счетами и повторениями (каждую неделю/месяц/год,
с опциональной датой окончания). Сортировка по дате, названию, категории и сумме, фильтры по категориям,
счетам и статусу, поиск. Отдельная вкладка «Лимиты» — месячные бюджеты по категориям с прогрессом
и подсветкой перерасхода.

### Счета
- Типы: карта, наличные, накопительный счёт, вклад, брокерский, крипто, кредитный счёт.
- **Проценты**: годовая ставка, капитализация — ежедневно / раз в месяц / квартал / год / в конце срока,
  день зачисления процентов, режим «капитализация» или «выплата на другой счёт».
- **Автопополнение**: сумма, день и месяц начала — участвует в прогнозе и календаре.
- Прогноз баланса по каждому счёту на 12 месяцев, эффективная доходность, переводы между счетами.

### Подписки
Любые регулярные списания с произвольным циклом (дни/недели/месяцы/годы): сервисы, связь, спортзал, ЖКХ.
Эквивалент «в месяц» и «в год», ближайшее списание, пробный период, дата окончания, напоминание,
история изменения цены, пауза/возобновление.

### Кредиты
- **Классические кредиты и рассрочки**: аннуитетный или дифференцированный платёж, график платежей
  с разбивкой «проценты / тело / остаток», переплата, дата закрытия, досрочное погашение.
- **Кредитные карты**: лимит, задолженность, дата выписки, длина беспроцентного периода,
  крайний день платежа, минимальный платёж. Отдельный виджет показывает, сколько дней осталось
  и какую сумму нужно внести, чтобы не платить проценты. Стратегия погашения: полностью / минимум / своя сумма.

### Конвертер
Конвертация любой суммы с учётом актуального курса, обратный курс, быстрый пересчёт в несколько валют
и мини-график динамики пары (история копится при обновлениях). Источники: ЦБ РФ, ЕЦБ (Frankfurter),
ExchangeRate API, резервный CDN — с автоматическим перебором при сбоях. Есть ручные курсы с приоритетом
над загруженными: они же используются, когда интернета нет.

### Аналитика
Доходы/расходы по месяцам, чистый денежный поток, план против факта, структура доходов и расходов,
топ крупных трат, сводные показатели (средний расход, норма сбережений, самый дорогой день).
Фильтры по периоду, счетам, категориям и статусу, сортировка по любому столбцу, поиск.

### Настройки
Базовая валюта, начало «финансового месяца» (например, от аванса до аванса), первый день недели,
приватность (скрытие сумм), управление категориями (цвет, иконка, лимит), экспорт/импорт JSON,
автоматические и ручные резервные копии с восстановлением, установка PWA.

## Как всё считается

- **Движок** (`src/lib/engine.ts`) превращает правила в конкретные события по датам, а затем
  проецирует баланс по дням: поступления, списания, проценты (ежедневное начисление с зачислением
  по выбранной капитализации), автопополнения.
- **Факт перекрывает план** по стабильному ключу события (`sourceKey`): как только вы отмечаете
  операцию выполненной, она заменяет плановую в расчётах, календаре и графиках — без дублей.
- **Мультивалютность**: все сводки приводятся к базовой валюте по текущему курсу; при отсутствии курса
  сумма показывается в исходной валюте, а в конвертере подсвечивается «нет курса».
- **Даты выплат** считаются по правилу переноса с выходных с учётом общероссийских праздников.

## Данные и приватность

- Хранилище — IndexedDB (Dexie) с автоматическим фолбэком на localStorage.
- Автосохранение с задержкой 0.6 с и ежедневная резервная копия (хранятся последние 12).
- Экспорт и импорт JSON, восстановление из любой копии — в «Настройки → Данные».
- Сеть используется только для загрузки курсов валют и шрифтов.

## Установка как приложение

1. Откройте приложение в Chrome/Edge (или любом браузере с поддержкой PWA).
2. В адресной строке нажмите «Установить» либо меню → «Установить приложение…».
   Кнопка установки также есть в сайдбаре и в «Настройки → Приложение».
3. Готово: отдельное окно без адресной строки, ярлык, запуск из трея/поиска, работа офлайн.

## Запуск на Windows (по стандарту SPECIALS)

Каркас запуска повторяет «золотой стандарт» из [`SPECIALS/`](SPECIALS/README.md):
двойной клик — и приложение открывается отдельным окном, сервер поднимается скрыто,
окно консоли не появляется.

| Файл | Роль (аналог из стандарта) |
|---|---|
| `start.vbs` | тихий запуск: находит `node.exe`, при необходимости собирает `dist/`, поднимает скрытый сервер, ждёт `/api/health`, открывает окно приложения |
| `stop.vbs` | остановка **только своего** процесса: порт из `data/port.txt` + проверка командной строки |
| `start_debug.bat` | запуск с консолью (видно ошибки, окно не исчезает) |
| `Обновить.cmd` | `npm install` (если нужно) + `npm run build` |
| `server.ps1` | сервер **без внешних зависимостей**: раздаёт готовую `dist/` на встроенном PowerShell (работает на любой Windows 7/10/11, Node.js не нужен) |
| `server.js` | то же самое на Node.js — используется автоматически, если Node.js установлен (быстрее); в режиме `dev` поднимает Vite |
| `ports.json` | свой блок портов `5130–5139` (копия записи из `SPECIALS/ports.json`) |
| `data/`, `logs/` | изменяемые данные (`port.txt`) и логи (`server.log`, `launch.log`, `log.txt`) |
| `tools/Ярлык.vbs` | ярлык на рабочий стол / в меню «Пуск» / в автозагрузку (на `start.vbs`, а не на `node.exe`) |
| `tools/Автозапуск.vbs` | включить/выключить автозапуск (`HKCU\…\Run` → `wscript start.vbs`, без прав администратора) |
| `tools/Диагностика.vbs` | что происходит: порт, процесс, личность сервера, автозапуск, хвосты логов |
| `tools/tray.py` | необязательная иконка в системном трее (Python + `pystray`) с надзирателем за сервером |
| `tools/vbs_encoding.py` | перекодирует `.vbs` в UTF-16 (см. ниже, это важно) |

**Ничего устанавливать не нужно.** Готовая сборка приложения лежит прямо в
репозитории (`dist/`), а раздаёт её `server.ps1` — сервер на встроенном в Windows
PowerShell (на чистом .NET, без Node.js, Python и каких-либо загрузок).
Если Node.js на компьютере всё же установлен, `start.vbs` предпочтёт его: так
сервер поднимается быстрее, а правки исходников собираются автоматически.

Первый запуск:

1. Скачайте проект (zip или `git clone`) и распакуйте в удобную папку.
2. Запустите `tools/Ярлык.vbs` и ответьте на два вопроса (меню «Пуск», автозапуск).
3. Дальше — ярлык **BudgetLIFE** на рабочем столе (окно открывается за 1–3 секунды).

`Обновить.cmd` и `npm run build` нужны только тому, кто меняет исходники:
для пересборки `dist/` требуется [Node.js 20+](https://nodejs.org/). Обычному
пользователю они не нужны.

Какой сервер работает, видно в `/api/identity` (поле `engine`: `powershell`
или `node`) и в отчёте `tools/Диагностика.vbs`.

Что делает приложение «настоящей программой» (пункты чек-листа
[`SPECIALS/docs/CHECKLIST.md`](SPECIALS/docs/CHECKLIST.md), которые здесь соблюдены):

* **один экземпляр** — повторный запуск поднимает уже открытое окно; решение
  принимается по `/api/identity` (проверяется личность, а не занятость порта);
* **порт только из своего блока** — `5130` основной, `5131` dev, `5132` preview,
  `5133–5139` резерв; занят — берётся следующий из блока, чужой процесс не трогается.
  Основной порт фиксирован: от него зависит origin установленного PWA;
* **`data/port.txt`** — актуальный порт; его читают лаунчер, ярлыки и трей;
* **остановка только своего** — по порту из `port.txt` + сверка командной строки;
* **автозапуск** — `HKCU\…\Run` → `wscript start.vbs` (переезд папки и обновление
  Node.js ничего не ломают);
* **имя в диспетчере задач** — копия `node.exe` под именем `BudgetLIFE.exe` + файл-штамп
  (приём DeployAgent/LanguageYOI, отключается флагом `TASKMGR_NAME`);
* **логи** — `logs/server.log` (ротация 1 МБ × 3) и `logs/launch.log`;
* **PWA** — манифест, иконки 192/512/maskable/ico, service worker, работа офлайн;
  HTML, `sw.js` и манифест отдаются с `no-store`.

> ⚠ **Кодировка `.vbs` — ловушка №1.** Windows Script Host понимает в `.vbs`
> только ANSI и UTF-16LE с BOM. Файл в UTF-8 (даже с BOM) падает при запуске с
> ошибкой компиляции **«Недопустимый знак» / Invalid character (800A0408)**.
> Поэтому `.vbs` в репозитории хранятся в UTF-16LE+BOM с переводами CRLF
> (GitHub показывает их как бинарные — это нормально и ожидаемо). После правки
> в любом редакторе/Git запустите `python tools/vbs_encoding.py` — скрипт
> вернёт правильную кодировку;`--check` только проверит.

Настройки запуска — константы в начале `start.vbs`:

```vbscript
Const REMOTE_URL = ""        ' внешний адрес: тогда Node.js и сборка не нужны
Const MODE       = "build"   ' "build" — dist/ ; "dev" — Vite с автоперезагрузкой
Const SERVER     = "auto"    ' auto | powershell | node — чем раздавать готовую dist/
Const HOST       = "127.0.0.1"
Const PORT_MAIN  = 5130      ' основной порт блока
Const BROWSER    = "auto"    ' auto | edge | chrome | default
Const SEPARATE_PROFILE = True
Const TASKMGR_NAME     = True ' копия node.exe под именем приложения
```

Иконка в трее (необязательно): `python -m pip install -r tools/requirements.txt`,
затем `python tools/tray.py` — меню «Открыть · Копировать адрес · QR-код ·
Папка данных · Автозапуск · Перезапустить · Выход» и надзиратель, который
поднимает сервер, если тот упал. Без Python всё работает через `start.vbs`.

Проверка VBS-файлов инструментом стандарта: `python SPECIALS/tools/check_vbs.py --root .`.

## Стек

React 18 + TypeScript, Vite, Tailwind CSS, Zustand, Dexie, Recharts, date-fns, lucide-react,
vite-plugin-pwa (service worker, манифест, иконки).

## Структура

```
src/
  components/      UI-кит, графики, карточки событий, календарные и модальные компоненты
  hooks/           период (финансовый месяц), установка PWA, онлайн-статус
  lib/             даты (с праздниками), деньги и формат, курсы валют, кредиты, движок денежного потока
  pages/           Обзор, Календарь, Доходы, Расходы, Счета, Подписки, Кредиты, Конвертер, Аналитика, Настройки
  store/           состояние (Zustand), IndexedDB, демо-данные, значения по умолчанию
scripts/           генерация иконок PWA, проверки ядра и интерфейса
server.ps1         локальный сервер без зависимостей: PowerShell + .NET, раздача dist/
server.js          то же на Node.js (используется, если Node.js установлен)
dist/              готовая сборка приложения (в репозитории — чтобы не требовался npm)
start.vbs          тихий запуск на Windows (стандарт SPECIALS)
stop.vbs           остановка только своего процесса
tools/             Ярлык.vbs, Автозапуск.vbs, Диагностика.vbs, tray.py
data/              port.txt и прочие изменяемые файлы (не в git)
logs/              server.log, launch.log, log.txt (не в git)
```

## Горячие клавиши

- `Ctrl/⌘ + K` — быстрая операция
- `Esc` — закрыть модальное окно
- Двойной клик по дню в календаре — новая операция на эту дату
