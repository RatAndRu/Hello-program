## AirMouse 0.18.0 — тело теперь видно: скелет поверх человека, кадр «по пояс», настройки

Три вопроса были такие: работает ли детект тела (скелета не видно), распознает
ли оно человека, видимого только по пояс, и где настройки режима тела.

### 1. Детект тела работал, но его не было видно — теперь видно

Модель Pose считала позу и писала строку в панель (`тело: стоит · приседаний 3`),
но **поверх человека ничего не рисовалось**. Отсюда и ощущение, что детекта нет.

Теперь в окне рисуется **скелет**: корпус зелёный, левая сторона голубая, правая
оранжевая, голова жёлтая, суставы — белые точки с цветной обводкой. Шея
дорисовывается отдельной линией (у Pose нет такой точки).

Режим тела включается **сам**, если рядом лежит модель позы
`models/pose_landmarker.task` (в собранном EXE она есть всегда). Плюс:

* клавиша **`T`** — включить/выключить тело на ходу, без перезапуска (движок
  пересоздаётся за доли секунды, камера не останавливается);
* `--body` при старте и `body.enabled = true` в конфиге — как раньше;
* `body.show_skeleton = false` — считать позу, но не рисовать.

### 2. «Видно только по пояс» — работает (и рисуется без ног)

Раньше требовались **все** ключевые точки: плечи, таз, колени и стопы. Человек,
видимый по пояс, не распознавался вообще — `visible = False`.

Теперь для позы нужны только **плечи и хотя бы один тазобедренный сустав**;
остальное — по возможности:

| Что видно | Что считается | Строка в окне |
|---|---|---|
| целиком | наклон, руки вверх, приседания и повторы | `тело: стоит · приседаний 3` |
| по пояс | наклон и руки вверх; приседания — **нет** (глубину не из чего взять) | `тело: стоит · видно по пояс · наклон 4°` |
| без таза | ничего (масштаб и наклон не определить) | `тело: не вижу — встаньте в кадр` |

**Ничего не дорисовывается**: если колени и стопы не видны, скелет просто
кончается на тазе. Это и честнее, и полезнее — сразу видно, что счётчик
приседаний в таком кадре не работает и почему (нет глубины, а не «сломался»).

Технически: у `BodyMetrics` появились `torso_ok / legs_ok / arms_ok / head_ok`,
`joints` и свойства `partial` («по пояс») и `where` — по ним и рисуется скелет,
и строится текст. Угол в колене считается только при видимых коленях и стопах,
иначе остаётся «разогнуто» — иначе невидимая нога давала бы ложный присед.
Наклон корпуса берётся из вектора «таз → плечи» и от ног не зависит.

### 3. Настройки режима тела

Новая страница **«Тело»** в панели `C` (клавиша `6`) — `docs/overlay-settings-body.png`:

| Ползунок | Что делает |
|---|---|
| порог видимости точки | насколько уверенно точка должна быть видна (0.50 по умолчанию) |
| считать позу раз в N кадров | 2 — вдвое меньше CPU, поза обновляется 15 раз в секунду |
| глубина «присел» / «встал» | пороги приседа с гистерезисом (0.45 / 0.18) |
| минимальный повтор, с | короче не считается повтором (0.35) |
| наклон корпуса, градусы | с какого угла это наклон (25°) |
| руки вверх: сколько держать | удержание, чтобы случайно поднятая рука не считалась (0.8 с) |

Плюс переключатель **«Тело: скелет и упражнения»** на странице «Режимы»: он
меняет `body.enabled`, а приложение замечает это и пересоздаёт движок само
(`AirMouseApp._reconcile_body`) — без перезапуска и без правки конфига руками.

### 4. Действий от тела нет — и это намеренно

Пока нужен только детект: тело распознаётся, рисуется и **считает повторы**, но
ни один жест тела ничего не нажимает. Команда выполняется только если вы сами
её привяжете:

```bash
python -m airmouse config set actions.mapping.squat_rep=toggle_pause
python -m airmouse config set actions.mapping.arms_up_hold=left_click
```

Счётчик повторов (гистерезис «вниз/вверх» + минимальная длительность) — это
заготовка под упражнения: приседания уже считаются, отжимания и прочее добавим,
когда будет понятный счётчик по нужным точкам.
