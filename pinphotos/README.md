# 📌 ЗакрепФото — нативное Android-приложение (+ отдельная PWA для браузера)

> **С версии 1.0 приложение внутри APK полностью нативное на Kotlin.** WebView и веб-интерфейс из APK убраны: сетка фото, просмотр, импорт, метаданные, шаринг, виджет и иконки — всё родное Android. Папка `pinphotos/*.html/js/css` осталась только как отдельная браузерная PWA-версия для экспериментов и в APK больше не попадает.

## Что умеет нативное приложение (папка `android-widget/`)

- Минималистичный тёмный интерфейс без лишнего текста: сетка фото, закрепление 📌, просмотр, изменить название/альбом/теги/заметку, поделиться, удалить.
- Импорт нескольких фото из галереи нативным Android-пикером; данные — файлы в `files/photos` + `meta.json` (совместимо с данными гибридной версии, приложение с тем же `applicationId` их подхватит).
- Бэкап/восстановление JSON через системные диалоги (меню ⋮).
- Смена иконки (обычная / 🔥 / 😴) через `activity-alias`, как у Duolingo — варианты зашиты в APK, видимая иконка всегда одна.

## Виджет: размеры и ротация

- При добавлении виджета система показывает **4 варианта размера: 2×2, 3×2, 4×2 и 4×3** — размер выбирается сразу при установке (виджеты остаются растягиваемыми и потом).
- Из приложения: карточка «Виджет» → **Добавить** → выбор размера → подтверждение лаунчера (`requestPinAppWidget`; если лаунчер не умеет — ручное добавление через «Виджеты»).
- Виджет **сам подхватывает закреплённые фото**. Несколько закреплённых — виджет листает их по таймеру обновления Android (~30 мин, `updatePeriodMillis` — чаще система виджетам не разрешает без ручного обновления).
- Заглушки: нет фото вообще — «Добавьте фото в ЗакрепФото»; фото есть, но не закреплены — «Закрепите фото 📌». Та же заглушка-картинка стоит в пустой сетке приложения.
- Фото в виджете **всегда квадратное по центру** (центральный кроп в квадрат в коде), прямоугольный виджет его не растягивает. По бокам — стрелки **‹ ›**: листать закреплённые можно прямо на виджете, тап по фото/подписи открывает приложение. Свайпы по виджету Android не отдаёт приложениям — только тапы по зонам.
- Дизайн с v1.1: тёплая светлая гамма (кремовый фон, бирюзовый акцент, мягкие карточки) вместо чёрно-серой.
- С v1.2: фото в виджете снова на весь виджет (`centerCrop`), кнопка 🔍 в правом верхнем углу включает увеличенный центральный фрагмент (второе нажатие — обычный вид). В приложении фото зумятся щипком и двойным тапом, есть кнопки «Копировать» (в буфер обмена) и «Поделиться».
- Альбомы: создание, фильтр-чипсы, импорт сразу в выбранный альбом, массовое перемещение (долгое нажатие — выбор нескольких — «В альбом»), альбом у одного фото меняется в окне «Изменить».
- «ЗакрепФото» принимает фото извне: в системном «Поделиться» у фотографий есть пункт «Сохранить в ЗакрепФото» (одно и несколько фото).
- Кнопка ⏻ на главном экране полностью закрывает приложение (`finishAndRemoveTask`) — в списке недавних оно не остаётся. Все технические окна (изменение, удаление, размер виджета, меню ⋮) оформлены общей диалоговой темой.
- С v1.3: светлая и тёмная темы (кнопка 🌙/☀️ и пункт в меню ⋮), кнопка закрытия — красный ✕ слева от названия. Альбомы переехали вниз главного экрана плитками с обложкой по последнему фото (без фото — заглушка), альбомов по умолчанию нет («Без альбома» — это отсутствие альбома). Плитки фото на главном экране со скруглёнными углами.

## Сборка

Локально: открыть `android-widget/` в Android Studio → Run. Без компьютера: GitHub Actions (`.github/workflows/build-pinphotos-android.yml`) собирает debug APK и кладёт его в GitHub Releases при каждом пуше в `pinphotos/**`.

## Что уже работает (PWA, папка `pinphotos/`)

- Установка на телефон («Добавить на главный экран» / кнопка «Установить»), полностью **офлайн** (Service Worker).
- Добавление фото из галереи через системный диалог. **Самостоятельно сканировать галерею PWA не может** — таковы правила безопасности Android; копии выбранных фото лежат в IndexedDB, оригиналы не трогаются.
- Закрепление 📌, альбомы, теги, заметки, поиск, просмотр на весь экран, шаринг.
- Кнопка «📱 На виджет»: в PWA показывает превью виджета сверху главного экрана.
- Бейдж с числом закреплённых фото на иконке приложения (Badging API, где поддерживается).
- Экспорт/импорт резервной копии одним JSON-файлом. Делай бэкап: браузер вправе почистить данные PWA при нехватке места.

Запуск для проверки: `python3 -m http.server 8000` в этой папке → открыть `http://<IP-компа>:8000` с телефона (первая загрузка — по сети, дальше офлайн). Для установки на домашний экран нужен HTTPS или localhost.

## Единое Android-приложение: одна иконка + виджет (папка `android-widget/`)

Чистое PWA **не может** создать виджет рабочего стола и **не может** менять свою иконку — у браузера нет такого API. Duolingo — нативное приложение, поэтому у него это есть. Поэтому PWA завёрнуто в тонкую нативную оболочку внутрь **того же APK** (аналог Capacitor, только без лишних зависимостей: WebView + JS-мост на чистом Kotlin):

- **Одна иконка в лаунчере.** `MainActivity.kt` — WebView с интерфейсом ЗакрепФото (Gradle сам копирует `index.html`, `app.js`, стили и иконки из папки `pinphotos/` в assets APK, см. `copyWebAssets` в `app/build.gradle`). Из приложения работает выбор фото из системной галереи.
- **Мост `PinPhotosNative`** (в `MainActivity.kt`): кнопка «📱 На виджет» в интерфейсе передаёт фото в Kotlin, тот ужимает его и обновляет настоящий виджет. Кнопки «Обычная / 🔥 / 😴» переключают иконку.
- `PinnedPhotoWidget.kt` — виджет рабочего стола (`RemoteViews`), тап открывает приложение.
- `IconSwitcher.kt` + `activity-alias` в `AndroidManifest.xml` — смена иконки как у Duolingo: варианты **заранее зашиты** в APK (обычная / 🔥 / 😴), код лишь переключает активный алиас через `setComponentEnabledSetting`. Иконок по-прежнему одна видимая — просто её картинка и подпись меняются. Иконку «нарисовать на лету» Android не позволит никому, даже Duolingo.

### Размер виджета: 3 × 2

По умолчанию виджет занимает **3 ячейки в ширину и 2 в высоту** (`targetCellWidth=3`, `targetCellHeight=2`, `minWidth=180dp`, `minHeight=110dp` по формуле Android `70dp × n − 30dp` — файл `res/xml/widget_info.xml`). Виджет оставлен **растягиваемым** (`resizeMode="horizontal|vertical"`): на рабочем столе его можно будет потянуть, например, в 2×2 или 4×2, — 3×2 это именно стартовый размер.

Добавить виджет можно прямо из приложения кнопкой **«📲 Добавить виджет на рабочий стол»** (`AppWidgetManager.requestPinAppWidget`). Если конкретный лаунчер это не поддерживает (такое бывает), остаётся ручной путь: долгое нажатие по рабочему столу → «Виджеты» → «Закреплённое фото».

> С версии 0.3 фотографии в Android-приложении хранятся **не в IndexedDB WebView** (она на `file://`-страницах работает нестабильно), а в нативных файлах приложения (`files/photos` + `meta.json`) — мост `PinPhotosNative.listPhotos/savePhoto/updatePhoto/deletePhoto`. В браузерной PWA по-прежнему используется IndexedDB.

### Отладка добавления фото (v0.4)

С версии 0.5 главная кнопка добавления в APK сразу использует нативный импорт (на HONOR/Android 13 WebView не вернул файл в JS — в журнале есть `fileInput click`, но нет `fileInput change`), а кнопка «Поделиться» в APK вызывает системный Android-шаринг через `FileProvider` + `ACTION_SEND`, а не Web Share API.

В приложении есть раскрытая панель **«🧪 Отладка добавления фото»**: каждый этап пишется в журнал (открытие галереи → полученный файл/MIME/размер → декодирование → base64 → ответ нативного хранилища → проверка состояния). Кнопки: «Состояние хранилища», «Скопировать журнал», «Очистить журнал». Плюс есть второй путь импорта — **«🛠 Добавить фото (нативный способ)»**: файл читает сам Android через `ContentResolver` (`pickPhotosNative`/`NATIVE_PICK`), минуя Blob/FileReader в WebView. Нативные ошибки дублируются в logcat с тегом `PinPhotos`.

### Как собрать APK

В этой песочнице нет Android SDK, поэтому APK здесь не собран. На своём компьютере: открой папку `android-widget/` в **Android Studio** → она подтянет Gradle и SDK → ▶ Run на телефоне. Получится одно приложение «ЗакрепФото». Виджет: долгое нажатие по рабочему столу → «Виджеты» → «Закреплённое фото» (появится прямоугольником 3×2).

Подписанный релиз (keystore, APK, GitHub Release, Google Play) — по инструкции из чата: ключ храним вне репозитория, `versionCode` увеличиваем с каждым релизом.
