# Мастерская приключений · Остров искр

Браузерная 2D RPG-песочница с визуальным редактором. Игрок исследует мир, а в мастерской добавляет собственные объекты, предметы, характеристики, правила, кнопки, окна и изображения. Произвольный пользовательский код не выполняется.

## Что уже работает

- Карта 18 × 12, поиск пути по клику, движение WASD/стрелками, взаимодействие E, рюкзак I и экранные кнопки для телефона.
- Несколько локаций на одной карте: Тихая роща, Замок фонарей и Розовый сад Розвааля. Переключение — над картой или переходом в игре, у каждого объекта можно указать свою локацию.
- Садовник, задание на сбор яблок, награда, ключ, ворота, сундук, противник, простой бой, опыт и уровни.
- Замок фонарей: каменный двор с зубчатыми стенами, фонарщик Тео, рыцари Ивар, Вела и Тёмный Мор, фонтан, знамёна, три тёплых огонька, задания «Три огонька» и «Потерянное знамя», фонарный талисман и ключ фонарщика.
- Розовый сад Розвааля: стриженые изгороди, розы, фонтан и особняк. Персонажи: Рем и Рам (задания «Чай для госпожи» и «Чай по-рамски»), Эмилия («Дух и лёд») и Пак — дух, который настаивает, что он не кот. Награды: ледяной кристалл и контракт духа.
- Создание, копирование, удаление и размещение персонажей и объектов на карте.
- Предметы: обычные, ключевые, расходуемые и снаряжение с повторяемым эффектом. Эффекты собираются из действий; новые предметы можно разместить на карте или выдать правилом.
- Новые числовые характеристики героя и объектов, настройки диапазона, начального значения, цвета и значка.
- Задания на сбор с предметной наградой, монетами и опытом.
- Визуальные правила: **событие → условия → действия**. События: взаимодействие, использование, подбор, победа, нажатие кнопки. Действия: изменить характеристику, выдать/забрать предмет, сообщение, окно, состояние задания, флаг, перемещение (в том числе в другую локацию) и смена локации.
- Кнопки под картой и внутри собственных окон. Окна содержат заголовок, текст, иллюстрацию, актуальные характеристики и кнопки.
- 29 встроенных пиксельных спрайтов, включая рыцарей, фонарь, замок, фонтан, огонёк, Рем, Рам, Эмилию, Пака, Розвааля, розу и ледяной кристалл. Загрузка PNG/JPEG/WebP для героя, объектов, предметов, окон и фона. Шесть атмосфер: лес, закат, берег, каменный двор, ночь и розовый сад.
- «Клетка с картинкой»: любая загруженная картинка ставится на выбранную клетку карты как пол, ковёр или кусок сцены. Поэтому собственный замок, подземелье или город можно собрать из своих изображений.
- Черновик отдельно от опубликованного мира; тестирование на копии прогресса; отмена/повтор изменений черновика; публикация с проверкой связей.
- IndexedDB, до восьми локальных версий, восстановление мира и прогресса, экспорт/импорт JSON.
- Русский интерфейс, адаптация под телефон, клавиатурная навигация, отключаемые звуки.

## Границы

Это одна расширяемая игра, не конструктор произвольных жанров. Новую механику можно собрать из имеющихся действий; принципиально новый тип поведения требует расширения движка. Ландшафт задаётся локацией: доступны пять готовых наборов поверхности, а отдельные клетки оформляются картинками. Нарисовать с нуля произвольную проходимость по клеткам из интерфейса пока нельзя. Снаряжение применяет настроенный эффект, отдельных слотов экипировки нет.

Мир хранится **в браузере на конкретном устройстве и адресе сайта**, не в аккаунте и не на сервере. Публикация ссылки на приложение не публикует личное сохранение. Очистка данных браузера может удалить мир. Нужно регулярно скачивать резервную копию. Автоматической облачной синхронизации нет.

## Первый игровой маршрут

1. Поговорить с садовником Миром и принять задание.
2. Собрать три яблока на карте.
3. Вернуться к садовнику, получить ключ и награду.
4. Подойти к воротам через мост и открыть их.
5. Найти сундук в роще.
6. Перейти в Замок фонарей, собрать три огонька у фонарей, помочь Ивару со знаменем и прогнать Тёмного Мора.
7. Заглянуть в Розовый сад: собрать розы для Рем и Рам, принести Эмилии ледяные кристаллы и заключить контракт с Паком.
8. Открыть мастерскую и создать собственное продолжение.

## Пример расширения без кода

1. **Характеристики:** создать «Удачу», задать начальное значение.
2. **Предметы:** создать талисман типа «Снаряжение / постоянный эффект», добавить действие увеличения удачи.
3. Разместить талисман на карте.
4. **Кнопки и окна:** создать окно с текущей удачей и кнопку, которая его открывает.
5. **Правила:** по нажатию кнопки, если флаг `reward_claimed` не установлен, выдать предмет, установить флаг и показать сообщение.
6. Нажать «Проверить», испытать на копии, вернуться и опубликовать.

Флаги позволяют делать одноразовые события. Без условия одноразовая награда может выдаваться при каждом нажатии — это настраиваемое поведение, а не автоматическая защита от любых игровых дисбалансов.

## Локальный запуск

Нужен Node.js 22 или совместимый.

```bash
cd game
npm ci
npm run dev
```

Адрес: `http://localhost:5173`. Сервер слушает `0.0.0.0`, поэтому подходит для предпросмотра Arena.

```bash
npm test                 # тесты движка и схемы мира
npm run build            # TypeScript + production-сборка
npm run preview          # просмотр production-сборки
npx playwright install chromium
npm run test:e2e          # настоящие браузерные сценарии
```

Если Chromium уже установлен вне Playwright, можно передать `CHROMIUM_PATH=/путь/к/chromium`.

## Устройство

- `src/model.ts` — типы, стартовый мир, состояние, палитра объектов.
- `src/engine.ts` — чистые функции механик, ограниченный интерпретатор действий, проверка мира.
- `src/storage.ts` — IndexedDB, проверка сохранений, импорт/экспорт, сжатие изображений.
- `src/components/Studio.tsx` — визуальная мастерская.
- `src/components/GameMap.tsx` — интерактивная карта.
- `src/components/Sprite.tsx` — оригинальные встроенные SVG-спрайты (64×64, без внешних ассетов и лицензионных ограничений). Персонажи из «Re:Zero» нарисованы вручную в общем стиле и не используют чужие файлы изображений.
- `src/components/UI.tsx` — поля и редакторы условий/действий.
- `src/App.tsx` — навигация, игровой цикл, диалоги, черновик, тест и публикации.
- `tests/` — модульные и браузерные проверки.

JSON — внутренний формат данных, а не язык, который должен писать пользователь. Загружаемые изображения ограничены растровыми форматами, уменьшаются и пересохраняются браузером. SVG, исполняемые файлы, `eval` и пользовательский JavaScript не принимаются. Проверка мира блокирует публикацию неизвестных действий и отсутствующих связей. Это не изолированная ОС для запуска недоверенных программ: такая возможность сознательно не предоставляется.

## Публикация на Fly.io

`Dockerfile` собирает приложение и раздаёт статику через непривилегированный Nginx на порту 8080. `fly.toml` рассчитан на одну машину shared-cpu-1x / 256 МБ, автоматическую остановку без посетителей и пробуждение при запросе. Первый запрос после простоя может быть медленнее. Наличие Fly.io-секрета не означает отсутствие расходов: они зависят от актуальных условий аккаунта Fly.io.

Workflow `.github/workflows/deploy-game.yml` запускается при изменении `game/**` в ветке этой сессии или вручную. Он проверяет и собирает приложение, выполняет тесты, создаёт приложение при необходимости и публикует его.

Токен должен находиться в **GitHub Actions secret `FLY_API_TOKEN`** репозитория (либо в доступном ему organization secret). Токен не должен попадать в код, README, переменные сборки клиентского приложения или чат. Workflow передаёт его только CLI Fly.io. Если токен ограничен организацией, нужна организация с правом создания этого приложения; текущий сценарий создаёт его в `personal`.

Плановый адрес: **https://hello-iskra-ratandru.fly.dev**. Он становится рабочей ссылкой только после успешного workflow и проверки HTTP-ответа. До этого приложение можно открыть в предпросмотре Arena.
