# Тесты «Объёма» (на синтетических сценах)

Рабочая папка — `/tmp/t` (туда пишутся сцены и результаты). Нужны Node 20+, Python 3 с numpy и pillow.

| Скрипт | Что делает |
|---|---|
| `node genmat.mjs light` | растр коврика 6 пикс/мм → `/tmp/t/mat_light.pgm` |
| `python3 scene.py /tmp/t/s2 walk 30 light` | рейтрейсер: предмет (цилиндр + шар + кубик) на коврике, кадры 1280×720 с тенью, шумом и точными масками |
| `python3 toraw.py /tmp/t/s2 640` | кадры → сырые RGBA 640 px и маски-эталоны |
| `node tpose.mjs` | точность фокуса и поз камеры по меткам |
| `node trecon.mjs /tmp/t/s2 light 128` | маски → оболочка → сетка → цвет; сравнение с «идеальной» оболочкой по эталонным маскам |
| `WALK=1 node tsplat2.mjs /tmp/t/s2` | обучение сплэтов, PSNR / облачка / дыры на отложенных кадрах (см. v1.9) |
| `node tpool.mjs` | v2.1: шаг сплэтов по частям кадра (потоки) = обычный шаг |
| `node tresume.cjs` | v2.1: прерванная обработка → лист «Обработка прервалась», «Продолжить» перезапускает |
| `node gradcheck.mjs` | проверка градиентов растеризатора сплэтов конечными разностями |
| `node texp.mjs` | экспорт GLB/OBJ/PLY/STL + проверка GLB официальным gltf-validator |
| `python3 mkcam.py && node e2e.cjs` | сквозной тест приложения в headless Chromium с «поддельной камерой» |

Результаты на сцене s2 (30 кадров, один обход 24–61°): фокус ±0.1 %, ошибка центра камеры 0.45 мм;
объём оболочки 126 см³ (v1.0) → ~118–122 см³ (v1.1) при идеальной (по точным силуэтам) 110 см³; сплэты 20 → 27 дБ PSNR на новых ракурсах.

`trecon.mjs` понимает переменные окружения: `FRAC`, `CLOSE` (голосование и закрытие оболочки), `PEEL`, `PALL`, `MAJ`, `NOER`
(чистка масок), `CUT=1` (режим вертушки: всё за кругом — не коврик), `CORRUPT=n` (n ложных «дыр» на кадр), `POSEERR=a`
(шум поз), `SM`, `TB` (сглаживание сетки), `REV=1` (тело вращения), `USEIDEAL=1` (сетка по эталонной оболочке), `MSTAT=1`
(ошибки масок против эталона). `e2e.cjs`: `SH=папка/` для скриншотов, `SHAPE=revolve|smooth`.

Трудные сцены (v1.2): `OBJWHITE=1 TABLE=0.8,0.8,0.83 python3 scene.py /tmp/t/s4 walk 30` — белый матовый предмет на светлом столе
(в 1.1 верх срезался: 10.7 см³ ошибочно вырезано, в 1.2 — 1.3 см³; `trecon.mjs` печатает `CUT`/`EXTRA` против эталона).
`python3 scene.py /tmp/t/spin spin 100 && FPS=10 python3 mkcam.py /tmp/t/spin && node e2e_spin.cjs` — вертушка, раскрученная
рукой (120°/с с затуханием и смазом): проверка автосъёмки по углу.

v1.4: `OBJPOSE="rx,ry,rz,tx,ty,tz"` в `scene.py` — положение предмета (для «доснять низ»), `OBJ=box|hex` — коробка
60×40×45 / шестигранник. `node tbottom.mjs /tmp/t/s2 /tmp/t/b2 "90,0,25,-16,34,24"` — две съёмки → совмещение →
пересечение, сравнение с точной формой (`DBG=1`, `GTM=1` — эталонные маски, `CUTA/CUTB=1` — вертушка).
`node tshape.mjs /tmp/t/box box|prism|planes|normal [объём]` — режимы формы. `e2e_bottom.cjs` (PHASE=A, затем B) —
сквозной тест досъёмки низа в браузере.

v1.5: `STATIC=1 python3 scene.py /tmp/t/spinS spin 100` — вертушка у неподвижной камеры: стол и стена неподвижны относительно
камеры (как в жизни), плюс `plate.jpg` — кадр фона (пустая вертушка); `toraw.py` переводит и его. `DIST=210` — крупные планы
(камера ближе). `/tmp/t/cmp10.mjs`-подобное сравнение «шапки» (лишний объём по слоям 10 мм) показало: съёмка с одной высоты 35°
без фона — 23 см³ лишнего выше 60 мм, с кадром фона — 2.0 см³, настоящий предмет не срезан (0.08 см³).
`node ttex.mjs /tmp/t/st120` — текстура-атлас против цвета вершин: рендер в отложенных ракурсах и сравнение с кадрами
(PSNR, резкость; `CLOSE=/tmp/t/cl` — с крупными планами, `GLB=1` — GLB с текстурой через gltf-validator, `SHOT=0` — картинка).
`e2e_plate.cjs` — сквозной тест вертушки: «Готово» → «Кадр фона» → обработка → текстура (`Q=best MODE=both`).
`e2e_bottom.cjs PHASE=C` — «Крупные планы» к уже снятому скану.

## v1.6 — зависание камеры, раскладка на узком экране

- `stale.cjs` — сторож свежих кадров. Камера, отдающая один и тот же кадр:
  `python3` — повторить первый кадр `camS.y4m` 30 раз в `/tmp/t/camFreeze.y4m`, затем
  `CAM=/tmp/t/camFreeze.y4m node stale.cjs` → ожидается `stale` > 0 и `opens` ≥ 2 (камера перезапущена);
  `CAM=/tmp/t/camS.y4m node stale.cjs` → `stale` = 0, `opens` = 1 (нет ложных срабатываний).
- `ui.cjs` — скриншоты экранов при `VW`×`VH` (по умолчанию 360×720) и координаты кнопок панели съёмки
  и экрана модели: все должны лежать в пределах ширины экрана.

## v1.7 — своя камера (Camera2) в APK

В Android WebView камера getUserMedia на части телефонов «замирает», пока не коснёшься экрана
(ошибка Chromium issues.chromium.org/40884226, «Won't fix»). В APK кадры теперь идут из `NativeCam.kt`
через мост `ObyomNative.camStart / camFrame / camStop` (JPEG base64 + угол поворота сенсора), веб-часть —
`js/nativecam.js`. В браузере остаётся обычная камера.

- `rot.cjs` — подставной `ObyomNative`, все повороты 0/90/180/270: после `drawTo` красный угол слева сверху,
  зелёный справа снизу, размер 1280×720.
- `NATIVE=1 CAM=/tmp/t/camS.y4m PLATE=/tmp/t/spinS/plate.jpg node e2e_plate.cjs` — вся съёмка и обработка через
  подставную нативную камеру (кадры повёрнуты на 90°, как с сенсора). `NATIVE=270` и т. п. — другой угол.
  Ожидается: автокадры ≥ 36, размер как без NATIVE, `своя камера: {starts:1, stops:1}`.

## v1.8 — портретный кадр, «шапка» по кадрам «целиком на листе»

- `capfound.cjs` — находится ли поза в каждом кадре при съёмке: `[PORTRAIT=1] [METHOD=walk] CAM=/tmp/t/camS.y4m node capfound.cjs`.
  Ожидается: поза почти во всех кадрах, фокус ≈ 497 (альбомный) или ≈ 884 (портретный 720×1280).
  До 1.8 в портрете начальная догадка фокуса была 0.75·ширины (540 вместо ~880) → поза находилась в 9 из 61 кадра,
  «поза неточная» почти всегда.
- `NATIVE=1 PORTRAIT=1 CAM=… PLATE=/tmp/t/spinS/plateP.jpg node e2e_plate.cjs` — сквозной тест с вертикальным телефоном
  (`PORTRAIT` работает только вместе с `NATIVE`; `plateP.jpg` — кадр фона, повёрнутый под портрет).
- `scene.py`: `EL=60` — высота камеры для вертушки (по умолчанию 35°), напр. `STATIC=1 EL=60 python3 scene.py /tmp/t/spinH spin 60 light`.
- `tcap.mjs <папки сцен…>` — «шапка» и лишний объём против точной оболочки (по эталонным маскам), по слоям 10 мм.
  `ENC=1` — правило «предмет целиком на листе» (enclose), `PLATE=1` — с кадром фона, `TF=0.1` — доля доверенных кадров,
  `NOTRUST=1` — без доверенного голосования, `FROM=24` — без смазанных первых кадров, `WALK=1` — съёмка с рук,
  `MSTAT=1` — ошибки масок на кадр, `IDEAL2=1` — эталонные маски с обычным голосованием. Результаты 1.8 (FROM=24):
  35°+60° без правила — лишнее 34.0 см³, с правилом — 21.3 см³ (срезано 0.24 см³ из 109.5); с кадром фона 21.9 → 15.7 см³;
  с рук 13.2 → 12.6 см³. Под одной высотой 35° на A4 предмет 76 мм ни в одном кадре не «целиком на листе» — правило не срабатывает.
- `mdump.mjs <папка> k1,k2` — маски кадров рядом с картинками в `/tmp/t/md_<k>.ppm` (`ENC=1` — с правилом).

## v1.9 — верх высокого предмета, сплэты с цветом по углу

- `scene.py`: `OBJ=pbank` — вертикальный пауэрбанк 70×45×143 мм (`LOOKZ=55` — камера смотрит выше), `LIGHTCAM=1` — свет
  движется с камерой (как блик от окна при вертушке), `SPEC=0.5` — блики, `EXPO=0.08` — разброс автоэкспозиции между кадрами.
- `tcap.mjs`: печатает «движение: групп … сдвиг камеры N» и сколько вырезано «движением». `NOMOTION=1` — без улик движения,
  `MF=0.5` — доля «непроверенных» вокселей слоя, `JIT=20` — каждый 3-й кадр сдвинут на 20 пикс. (проверка «камера сдвинулась»).
  Пауэрбанк 35° (`HB=160 FROM=24 ENC=1`): до 1.9 — 85×55×71 мм, срезано 128.6 см³ из 258.6; в 1.9 — 79×53×144 мм, срезано 4.6.
  35°+60°: 73×51×147 мм, лишнее 69 см³, срезано 0.3. Обычная сцена 35°+60°: 65×57×76, лишнее 22.5 (не хуже 1.8).
  `JIT=20`: отброшено 11 кадров из 11 сдвинутых; без сдвига — 0 (контрольные точки — только за кругом, который заметают углы листа).
- `tsplat2.mjs <сцена>` — подбор параметров сплэтов: подготовка как в приложении, каждый 6-й кадр — проверочный.
  Метрики: PSNR внутри точной маски (яркость проверочного кадра подбирается МНК), «облачка» (непрозрачность на фоне), «дыры».
  Переменные: `ITERS N0 NMAX DEG AW DW FLAT EXPO LRDC LRREST MEDW`, `WALK=1`, `PLY=`, `PPM=`, `VERB=1`.
  Сцены: `STATIC=1 LIGHTCAM=1 SPEC=0.5 EXPO=0.08 NOBLUR=1 python3 scene.py /tmp/t/spT spin 72 light` и
  `SPEC=0.5 EXPO=0.08 python3 scene.py /tmp/t/wS walk 36 light`, затем `toraw.py … 640`.

## v2.1: фонарик, уточнение поверхности, сплэты в несколько потоков

* Сцена с фонариком: `STATIC=1 BUMP=2 MATS=1 NOBLUR=1 TORCH=0.25 python3 scene.py /tmp/t/rT spin 72 light` — точечный свет
  у объектива (смещён на 1.4 см), спад 1/d² (`TD0` — расстояние «яркость 1»), `TORCH` — доля комнатного света; пятно
  фонарика ложится и на коврик. Рельеф по фонарику: `NOSH=1 NOAO=1 BUMP=2 OPT='{"torch":true}' node tsurf.mjs /tmp/t/rT`.
  Печатается радиус бока цилиндра (истинный 24 мм) — насколько поверхность уточнена.

| rT (фонарик), бок цилиндра | r − 24, медиана | бороздки: сетка → рельеф | ямки: сетка → рельеф |
|---|---|---|---|
| по оболочке, рельеф по светотени (как 2.0) | 1.34 мм | 17.0° → 22.6° | 18.5° → 21.5° |
| по оболочке, фонарик | 1.34 мм | 17.0° → 19.5° (уклоны не совпадают) | 18.5° → 18.6° |
| уточнение (окно 5×5 в UV), фонарик | 0.39 мм | 17.6° → 16.5° | 18.5° → 17.3° |
| уточнение в касательной плоскости, 2 прохода, фонарик (итог) | 0.06 мм (∣·∣ 0.19) | 18.0° → 14.7° | 18.8° → 16.0° |
| точная оболочка (IDEAL=1), фонарик — предел метода | — | 15.3° → 11.8° | 16.5° → 13.2° |

  Без фонарика (лампа в комнате, rB3) тот же решатель даёт 18.6° → 22.2° — свет почти не меняется по кадрам.
  Цвет без теней: «фото / свет фонарика в кадре» хуже медианы по кадрам (24.8 против 19.1) — оставлена медиана
  (`OPT='{"torch":true,"delight":"torch"}'` — для опытов). Параметры решателя (lam, rounds, minCos) почти не влияют:
  предел — остаточная ошибка совмещения кадров.
* `tpool.mjs` — шаг сплэтов по частям кадра (как в потоках) против обычного: градиенты совпадают до 1e-8.
* `tresume.cjs` — пометка незаконченной обработки и лист продолжения после перезапуска (нужен сервер `obyom/web` на :8765).
* `e2e_plate.cjs` с `POOL=2` — обработка с пулом потоков даже на 2-ядерной машине (по умолчанию потоков = ядер − 1, до 4).
  Найдено и исправлено: `terminate()` вложенных потоков сразу перед `terminate()` родителя иногда роняло страницу
  (≈ половина прогонов) — теперь потоки сплэтов закрываются сами (`close` → `bye`), а поток обработки гасится с паузой 3 с.
  После исправления 7 прогонов из 7 без падений.
* `BATCH=4 node tsplat2.mjs …` — пачка из B кадров на шаг (опыт, в приложении не используется):

| rB3, 60 кадров обучения | PSNR | облачка | капель |
|---|---|---|---|
| 1200 шагов по 1 кадру | 30.09 | 4.9 % | 11 560 |
| 400 шагов по 4 кадра | 28.95 | 5.3 % | 14 896 |
| 600 шагов по 4 кадра | 29.49 | 6.2 % | 19 057 |

  Пачка кадров за шаг выигрывает по времени меньше, чем теряет в качестве, поэтому в приложении потоки делят
  один кадр (ряды тайлов k, k+K, …), а не берут разные кадры.

## v2.2

* **«Maximum call stack size exceeded» в «Рельеф и материал»** — причина в 2.0: `Math.max(0, ...faceChart)` (массив на все грани,
  при крупной сетке переполняет стек фонового потока телефона). Исправлено ещё в 2.1; проверка: `node --stack-size=200 tsurf.mjs /tmp/t/rB3`
  (стек в 5 раз меньше обычного) — 2.1/2.2 считают, код 2.0 падает с той же ошибкой.
* `tsplat2.mjs`: `FAR=0` — выключить новое правило «далеко от оболочки прозрачно» (`splatViews(..., {farHull})`);
  `DBGFAR=1` — сколько пикселей правило меняет и сколько из них на настоящем предмете (должно быть 0).
  Замеры: с рук 10 % пикселей, вертушка 16 %, на предмете 0; PSNR и облачка на синтетике без изменений (там облачка внутри оболочки).
* `gradcheck.mjs`: шаг для `ls` 1e-3 (при 1e-4 численная разность тонула в шуме float32 — «расхождение» `ls[2]` было ложным);
  при расхождении теперь `exit 1`.
* `trecon.mjs`, `mdump.mjs`: относительные импорты; `trecon` по умолчанию — параметры приложения (peel=1, frac=0.08), `PEEL/MAJ/FRAC` — переопределить.
* `e2e_plate.cjs`: `MAPS=/путь/` — пройти кнопкой «Карта» (нормали, высота, шероховатость, металл, затенение) и снять скриншоты.
